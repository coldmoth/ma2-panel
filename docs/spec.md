# Панель управления светом MA2 — спецификация

Это текущее состояние. История запросов владельца по датам: `docs/archive/spec-history.md`. Новый запрос владельца = правка нужного раздела здесь + строка в конец spec-history.md.

Непроверенное на настоящем пульте ведётся в `docs/hall-test-plan.md`. Выполненные планы v1–v4 лежат в `docs/archive/`.

## Цель и пользователи

Веб-панель для света в зале музыкальной школы. Заменяет Web Remote grandMA2, работает только в локальной сети.

- **Учителя и персонал** (не знают MA2): включают записанные сцены, гасят свет, меняют общую яркость.
- **Администратор** (владелец проекта): управляет группами и приборами, яркостью, цветом, записывает сцены.

Устройства: Android-планшет (основное, горизонтальная ориентация), iPad, MacBook, телефон. Браузеры: Safari и Chrome. Управление касанием и мышью. Срока нет. Разработка дома в имитации, выезды в зал для проверки Telnet. (было: 1)

## Архитектура

```
[браузер] --WebSocket--> [мост, Windows с MA2] --Telnet localhost:30000--> [grandMA2 onPC 3.9]
```

- Мост на той же Windows, что и MA2, подключается по `localhost`, смена IP `.215` на связь с пультом не влияет.
- Планшеты открывают `http://<IP Windows>:8080`, к MA2 напрямую не подключаются.
- Сцены и группы хранятся в шоу MA2. Панель только отправляет команды.

Стек: Python 3.12, FastAPI + uvicorn, `asyncio.open_connection` для Telnet. Установка через `uv`. Панель — статика без фреймворков и сборки.

| Файл | Что делает |
|---|---|
| `bridge.py` | `create_app` (одно замыкание), состояние, разбор действий WebSocket (`handle`), `main` и запуск |
| `api.py` | HTTP `/api/*`: настройки, диагностика, `diag.zip`, `probe`, импорт XML файлом, stop/restart; получает локальные переменные через `api.register` |
| `link.py` | `MA2Link` (одно Telnet-соединение, вход, построчное чтение), `Throttle` (последнее значение слайдера), разбор приглашения |
| `commands.py` | Чистые функции: действие → строки MA2, разбор ответов `List ...`. Без сети |
| `fixtures.py` | Разбор XML-экспорта MA2, слияние, угадывание голов по типу, атомарная запись `config.json` |
| `safety.py` | `settings.json` + `secret.env`, режимы защиты, `make_guard` (последний фильтр строк), проверка настроек, маскировка пароля |
| `mock.py` | Поддельный MA2 для `--mock` (`MA2_MOCK_REAL=1` — формат живого пульта) |
| `update.py`, `selfcheck.py` | Обновление с USB и самопроверка на площадке |
| `static/*` | `index.html`, `app.js`, `light.js`, `plan.js` (зал), `move.js` (пад/джойстик), `settings.*`, `diag.*`, `simple.html`, `log.html` |
| `config.json`, `settings.json`, `secret.env` | План шоу; настройки площадки; пароль MA2 |
| `docs/CODEMAP.md` | Карта кода, индекс собирается `scripts/codemap.py` |

(было: 2, 17)

## Режимы панели

**Простой режим** (по умолчанию на основном порту): кнопки сцен (Go и Off), «Погасить всё» с подтверждением, мастер-слайдер яркости.

**Простой порт для учителей.** Тот же процесс слушает `simple_port` из `settings.json` (по умолчанию `8090`, `null` выключает) — там `static/simple.html`: только плитки сцен и большая кнопка «Погасить всё» с подтверждением. Нет разделов, слайдеров, `/api/*`, журнала, диагностики. Защита на стороне моста: с этого порта принимаются только `scene_go`, `scene_off`, `blackout` (и служебный запрос состояния), остальное — отказ «в простом режиме недоступно». Ограничения `safety` действуют как на основном порту; `config` содержит только сцены и страницы. В Firewall открыт порт 8090 (частная сеть).

**Полный режим** — остальные разделы, без PIN (доступ ограничен паролем Wi-Fi зала; пароль знают двое, отдельной защиты на мосту нет). (было: 3, 24)

## Интерфейс: разделы

Тема одна, тёмная (цвета — CSS-переменные в `style.css`). Навигация: боковое меню Сцены / Свет / История / Площадка / Зал / Патч / Шоу (на телефоне — снизу). Верхняя строка: шоу на пульте, связь, «Выбрано: N», «Стоп передачи» (сразу), «Погасить свет» (второе нажатие в течение 3 с вместо диалога). Устройство помнит последний раздел и вкладку выбора (`localStorage`: `ma2.sec`, `ma2.pick`).

- **Сцены**: единый сохранённый список с порядковыми номерами 1, 2, 3 и именами, без страниц и executor в основной выдаче. Вызов/выключение на плитке; удаление и перезапись только в «Изменить», с подтверждением цели. «Переход» и мастер сохраняются. Простой порт показывает тот же порядок/имена без редактора.
- **Свет**: управление разделено на вкладки «Свет» и «Движение» с общим выбором; неизвестные значения не подменяются начальными. Выбор по вкладкам Группы (панели и MA2, с меткой) / Приборы / План; карточки яркости (+ время перехода), цвета (палитра + пресеты MA2), позиции и луча (пад + пресеты позиции MA2), стробоскопа. Значения: «отправлено панелью», «неизвестно», «разные». Неподдерживаемый параметр (по `params` прибора) — карточка неактивна с пояснением.
- **Зал** — редактор (бирюзовый): вход шлёт `edit_begin`, уход — `highlight_off` и `edit_end`; галочка подсветки каждый раз выключена; пошаговая расстановка «прибор → касание схемы → следующий» (`layout_save` на каждое касание), служебный флаг (`fixture_flag`), форма зала (`hall_save`, прямоугольник), группы панели и «В MA2…» (`group_store_ma2`), калибровка луча.
- **Шоу**: список шоу, привязка, загрузка, сохранение.
- **Площадка**: связь, «Получить оборудование из MA2», таблица приборов, чтение групп/пресетов/сцен MA2 (`ma2_read`) и выбор, что добавить (`ma2_import`). (было: 12.3, 16)

Поставляемый `config.json` пустой: без приборов, групп, сцен; при первом запуске v4 старый конфиг копируется в `backups/` и `shows/<шоу>.json`, сам не очищается (`version: 4`). Первое чтение приборов привязывает непривязанный план к шоу на пульте. (было: 16)

## Схема зала

- **Фон:** рисуется по форме зала `config.hall`; `plan.image` и `static/plan.svg` не используются (удалены).
- **Приборы:** иконки в точках `x`, `y` (доли 0-1). Нажатие выбирает, повторное — снимает; выбор множественный и общий для всех вкладок.
- **Показывает** последние значения, отправленные панелью (не обратная связь от пульта). После «Погасить всё» — сброс; после вызова сцены — надпись «значения не отслеживаются» до новых отправок.
- **Выбор группы** подсвечивает её приборы на схеме. Состав групп хранится в `config.json`.
- **Расстановка:** пошаговая «прибор → касание схемы → следующий» (`layout_save` на каждое касание), см. раздел «Интерфейс: разделы» → «Зал».
- **«Обновить из пульта» / «Получить приборы»:** см. раздел «Приборы».
- Значки: по `fixture_flag {id, icon: par|bar|head|fresnel}` — круг, прямоугольник, квадрат, ромб; угадывание по типу заменено флагом. `fixture_flag {id, rot: 0|90}` поворачивает значок планки. Неподвижные — точки без направления.
- **Лучи голов** по Pan: угол = направление от прибора на `plan.stage` + (pan − pan калибровки) / 100 × (`attrs.pan.max − attrs.pan.min`), знак минус при `invert`. Длина постоянная; выбранная голова — яркий луч, остальнные — бледные. Без калибровки луч не рисуется. Калибровка (вкладка «Зал», одна голова): «Сейчас светит прямо на сцену» (запомнить Pan как направление на `plan.stage`), «Луч крутится не туда» (разворот). Зал 20 × 9 м, сцена у левой короткой стены; `plan.stage: {x, y}` — точка «прямо на сцену». Высота зала пока не используется (нужна для луча по Tilt). (было: 3.1, 12.1, 12.3, 16, 17)

## Протокол панель ↔ мост

Панель отправляет только действия. Строки MA2 собирает мост; произвольную строку отправить нельзя. `ClearAll`, патч и `/noconfirm` в протоколе отсутствуют (кроме внутреннего `ClearAll` в `scene_go`).

| Действие | Режим | Строки MA2 / что делает мост |
|---|---|---|
| `scene_go {id, fade?, swap}` | простой | `ClearAll`, затем `Go Executor <exec>` или с `fade` 0–30 с: `Goto Cue 1 Executor <exec> Fade <с>`; сцены из `swap` проверяются по `allowed_scenes`; без `fade` мост гасит их сразу, с `fade` — по истечении `fade` секунд шлёт `Off Executor` каждой (кроме запускаемой), затем рассылает `running: {id: false}` |
| `scene_off {id}` | простой | `Off Executor <exec>` |
| `blackout` / «Погасить всё» | простой | `Off Executor <exec>` каждой сцены конфига, затем `Fixture <все приборы плана, кроме служебных и пропавших>` + `At 0`; `shown` после неё `dim 0` |
| `master {v 0-100}` | простой | команда мастера из конфига (`master.cmd`) |
| `select_group {id}` | полный | `Group <n>`; для группы без `n` — `Fixture a + b + c` |
| `select_fixtures {ids}` | полный | `Fixture a + b + c` |
| `dim {v 0-100}` | полный | `At <v>` |
| `color {r,g,b 0-100}` | полный | `Attribute "ColorRGB1/2/3" At …` — три команды; для `cmy` — строки по типам |
| `strobe {v 0-100}` | полный | см. «Стробоскоп» |
| `clear` | полный | `Clear` |
| `jog {pan, tilt, mirror}` | полный | относительный шаг в градусах (−45…45); мост суммирует шаги вкладки и не чаще `rate_hz` шлёт `Fixture …` + `Attribute "Pan/Tilt" At + <°>` / `At - <°>` (`attrs.<attr>.rel_cmd`) |
| `nudge {attr, dir}` | полный | относительный шаг (`attrs.<attr>.rel_cmd`, `step` в градусах, 0–10) |
| `aim {pan, tilt}` | полный | абсолютные градусы в пределах `min..max` |
| `zoom {v}`, `focus {v}` | полный | одно значение на всех выбранных подвижных |
| `preset_save {label}` / `preset_go {id}` / `preset_delete {id}` | полный | пресеты позиции: сохранение Pan/Tilt из `shown`, вызов, удаление |
| `group_save {label, ids}` / `group_delete {id}` | полный | группы панели без `n`; удалить можно только их |
| `group_store_ma2` | полный | запись группы панели в MA2, см. «Безопасность» |
| `scene_create {label, page, exec?, confirm, replace?}` | полный | см. «Сцены» |
| `scene_rename`, `scene_delete {id, desk?}` | полный | см. «Сцены» |
| `show_bind`, `show_open_plan`, `shows_list`, `show_load`, `show_save` | полный | см. «Шоу» |
| `layout_save {pos}` | полный (в MA2 не уходит) | проверка id и чисел 0-1, запись в `config.json` |
| `fixtures_fetch` | полный | см. «Приборы» |
| `edit_begin` / `edit_end`, `highlight…` | полный | см. «Подсветка» |
| `beam_home {id}` / `beam_invert {id}` | полный | запись `fixtures[].beam.home` / переключение `invert` |
| `fixture_flag {id, …}` | полный | флаги: `moves` (+`same_type`), `icon`, `rot`, `flip_pan`, `flip_tilt` |
| `undo {n}` | полный | откат, см. «История» |
| `hall_save`, `page_save {n, label}`, `scenes_import`, `plan_copy {from, ids}` | полный | см. соответствующие разделы |

Мост → панель: `{"ok": true}` / `{"ok": false, "err": "..."}` на каждое действие и рассылки:
- `status`: `ma2: down | tcp | login_failed | login_unknown | logged_in | manual_off`, `mock`, `show`, `no_attr {attr: [type]}`; команды уходят в `logged_in` и `login_unknown`;
- `config` (без `ma2`) при подключении и после каждого сохранения; на простом порту — только сцены и страницы;
- `shown`: последние отправленные значения `{id: {dim, rgb, pan, tilt, zoom, focus}}` после каждой отправки; `blackout` сбрасывает `shown` целиком; после `scene_go` «что показано» очищается;
- `running {id: bool}` — опрос статуса сцен; `page`, `last` (результат последней строки).

Мост помнит текущий выбор (группа → приборы, или список) и позицию головы — но позиция известна только после абсолютного значения, отправленного самой панелью и принятого без ошибки; забывается при потере связи и после `scene_go`. Значения, выставленные на самом пульте, панель не видит: Telnet их не сообщает. (было: 4, 12.4, 13, 14, 17, 18, 19, 20)

### Движение голов

Подвижные приборы: с `"moves": true` в конфиге или с Pan/Tilt в `params` из экспорта. Выбор нескольких голов — все двигаются вместе.

- **Пад — как стик геймпада:** отклонение задаёт скорость, при отпускании возвращается в центр, голова остаётся на месте. Квадратичная кривая, 90 °/с у края, мёртвая зона 8 % (`JOY_SPEED`, `JOY_DEAD` в `static/move.js`); «Точно (медленно)» — 15 % (`JOY_FINE`). Пад на всю ширину карточки. Панель шлёт `jog` 10 раз/с; относительные команды позволяют крутить голову одновременно с пультом.
- Если в выборе нет подвижных — пад неактивен с подписью «Выберите голову».
- **Инверсия:** `flip_pan` / `flip_tilt` меняют знак шагов (джойстик и ←→↑↓); абсолютные команды флаги не учитывают. Кнопки «Pan наоборот», «Tilt наоборот» ставят флаг всем выбранным.
- **«Зеркально: сводить и разводить»** (`mirror: true` в `jog` и `nudge`): левая половина выбранных голов по `x` на схеме (без места — по номеру) крутит Pan в обратную сторону; при нечётном числе средняя — как обычно.
- **Нет атрибута:** `Error #14: OBJECT DOES NOT EXIST` на Zoom/Focus/Strobe показывается как «у выбранных приборов на пульте нет атрибута «Focus»». Если все выбранные одного типа, мост запоминает `status.no_attr` (до перезапуска), ползунок неактивен.

Синтаксис атрибутов задаётся шаблонами в `config.json`, правится в зале без изменения кода:

```json
"attrs": {
  "pan":   {"cmd": "Attribute \"Pan\" At {v}",   "min": -270, "max": 270},
  "tilt":  {"cmd": "Attribute \"Tilt\" At {v}",  "min": -135, "max": 135},
  "zoom":  {"cmd": "Attribute \"Zoom\" At {v}",  "min": 0, "max": 100},
  "focus": {"cmd": "Attribute \"Focus\" At {v}", "min": 0, "max": 100}
}
```

Панель работает в 0-100; мост пересчитывает линейно в `min..max`, округляет до 0,1. У всех целевых голов одно значение (Zoom, Focus, одна голова) → строки атрибутов идут на текущий выбор. У голов с разными значениями (`move`, `preset_go` на нескольких головах) — для каждой `Fixture <id>` и строки атрибутов, затем возврат выбора (`Fixture a + b` или `Group <n>`); пометка в коде `# ponytail: …` — заменить на одну команду, если найдётся синтаксис. (было: 12.2, 12.5, 14, 16, 18)

## Частота команд

- Панель шлёт слайдеры не чаще 10 раз/с.
- Мост хранит последнее значение на слайдер и шлёт не чаще `rate_hz` (начально 5, подбирается в зале). Для `jog` ожидающие шаги суммируются, ни один не теряется; для абсолютных слайдеров промежуточные значения могут отбрасываться — последнее приводит в нужную точку.
- Кнопки (сцены, выбор, запись) в ограничение не попадают и выполняются строго по порядку. (было: 5, 12.4, 18)

## Связь и ошибки

- Нет WebSocket: красная полоса «Нет связи с мостом», кнопки неактивны, переподключение каждые 2 с; нажатия без связи не копятся.
- Нет связи с MA2: полоса «Нет связи с пультом», кнопки неактивны, переподключение каждые 3 с; команды из очереди при обрыве выбрасываются.
- Ошибка входа: отдельное сообщение, повтор входа каждые 30 с, перезапуск не нужен.
- Ответ с `Error` или `Illegal` — ошибка, показывается на кнопке. Разбор одной функцией.
- Обрыв связи мост↔MA2 проверяется действиями `link_drop` / `link_connect` (открыть/закрыть Telnet-сессию самого моста; после `link_drop` мост сам не переподключается).
- **Результат строки:** `sent` (приглашение получено, слов ошибки нет; не доказательство действия), `error`, `unknown` (нет приглашения за `ma2.timeout`, по умолчанию 2 с; команда могла выполниться), `not_sent`. Ничего не отправляется повторно. После `unknown` мост ждёт поздний ответ; если его нет — следующая строка не уходит, соединение переоткрывается.
- Все команды и ответы пишутся в `bridge.log` с ротацией по размеру; журнал не-слайдерных действий с IP устройства — последние 300 отдаёт `/api/log`, страница `/log.html`. (было: 6, 13, 14)

## Сцены и страницы

- Техническая привязка сцены — `exec` вида `<страница>.<номер>`, команда использует id сцены. Основная выдача плоская: номер — индекс массива `scenes` + 1. Старый план однократно сортируется численно по exec и получает `scene_order_version: 1`; далее порядок сохраняется. Импорт обновляет имена по нормализованному exec, сохраняет id/порядок и добавляет новые сцены в конец. Частичный ответ не удаляет сцены. Непустой label отображается независимо от legacy named. Адрес показывается в редакторе и подтверждении записи, переключение Page для запуска не нужно.
- **Запись — только `scene_create`** с явно подтверждённым номером executor (`exec` + `confirm`), в режимах `store` (номер из `store_execs`) и `full`. В одном `action_lock`: перед записью `List Executor <n>`; пишется только если ответ распознан как пустое место (`ma2.exec_empty_regex`). Занято, ошибка, тишина, непонятный ответ → отказ с причиной. `/Overwrite` и `SaveShow` не шлются никогда; `store_scene` (перезапись) отключена. Первое имя: `StoreLook Executor <exec> Cue 1 /Source=Output` + `Label` + запись в конфиг.
- **Перезапись** («Изменить» → «Перезаписать текущим светом», с подтверждением): `scene_create {label, page, exec, confirm: exec, replace: true}`. В одном `action_lock`: сцена с этим `exec` должна быть в панели, `confirm` совпадает, затем `Delete Executor <exec>`, затем обычная проверенная запись. Старая запись конфига заменяется. Если запись после удаления не прошла — сцена на пульте удалена, плитка остаётся; мост сообщает причину, повторно ничего не шлёт.
- Удаление доступно только в редакторе: «Убрать из панели» сохраняет executor; «Удалить на пульте» показывает имя/адрес и предупреждает о восстановлении из бэкапа. Перезапись сохраняет id/exec/место; при сбое после Delete плитка остаётся с явной ошибкой, старый running инвалидируется, повторной записи нет.
- `scene_rename` — `Label Executor` + имя в конфиге. Кавычки в именах запрещены.
- **`scene_go` заменяет всё:** `ClearAll` перед `Go`/`Goto` — единственное место, где мост шлёт `ClearAll`; защита пропускает ровно эту строку (`ClearAll` чистит только программер). Панель всегда передаёт `swap`; галочка «Выключить предыдущие в конце» убрана. Запись `/Source=Output` — в сцену попадает весь выход пульта.
- **`scenes_import`:** сначала переход на план шоу с пульта; мост шлёт `ma2.list_cmd` (по умолчанию `List Executor {page}.1 Thru {page}.250`) по страницам плана и всем страницам, где `List Page` показывает объекты (`(N)` в конце строки); существующие сцены не меняются; сообщает число нераспознанных строк и `total`. Разбор строки: необязательное слово (`Executor`, `Exec`), необязательный номер, `стр.номер`, возможно повтор, имя.
- **Состояние сцен:** каждые 3 с `List Executor` по страницам, рассылка `running {id: bool}`; нет статуса — панель живёт на том, что помнит.
- `page_save {n, label}`: `Label Page n "…"`. (было: 4, 13, 14, 20, 22)

## Подсветка (highlight)

- `highlight {id}`: при первом выборе гасит остальные приборы зоны, затем зажигает выбранный; при смене гасит предыдущий. `highlight.level` — яркость (по умолчанию 100). Включение требует подтверждения: подсветка гасит остальные приборы зала.
- Зона исключает `missing`, `service`, `highlight.exclude`; вне `full` ограничена `allowed_fixtures`. Подсветкой владеет одна вкладка; `highlight_ping` продлевает аренду `highlight.lease_s` (по умолчанию 10 с).
- Снятие через `Off Fixture <зона>` и восстановление известных отправленных панелью значений — при `highlight_off`, выходе из редактора, разрыве вкладки, истечении аренды. При запуске моста, повторном входе в пульт, «Возобновить» и переключении плана `Off Fixture` не шлётся (см. ниже). `highlight.json` сохраняет зону для восстановления после запуска; при невозможности снять — состояние `stuck`, новый выбор заблокирован.
- **Ничего само не гасит свет:** при запуске моста, повторном входе в пульт, «Возобновить» и переключении плана мост не шлёт `Off Fixture` — подсветка остаётся «не снята», её снимает кнопка в баннере с предупреждением (зал 2026-10-21: команда стирала ручную работу, спасло только Oops). (было: 15, 19)

## Приборы и импорт

- **`fixtures_fetch` («Получить приборы»):** сначала читает имя шоу на пульте; если план привязан к другому шоу — сохраняет его в `shows/`, открывает (или создаёт) план шоу с пульта и импортирует туда (ответ `switched: <имя>`). Экспорт командой `ma2.export_cmd` (по умолчанию `Export Fixture 1 Thru 9999 "panel_fixtures"`, без `/o`): удаляет свой старый XML в `ma2.export_dir`, ждёт до `ma2.export_wait` секунд, ищет свежий файл по glob из `ma2.export_search`. XML сливается с планом: имена, типы, параметры, адреса обновляются; расстановка и подписи сохраняются; новые — в лоток, исчезнувшие — `missing: true`. Ошибка не меняет конфиг; последний XML — в `diag/last_export.xml` и архиве.
- **Перепатч:** пропавший прибор с новым номером при том же имени и типе (ровно один кандидат) наследует место, подпись и отметки. Команды пульту идут по `Fixture N`, смена DMX-адреса не мешает.
- **Приборы без Fixture ID** (только Channel ID) панель не ведёт; импорт возвращает имена в `no_id` — «дайте им Fixture ID в патче MA2».
- **Ручной импорт XML:** `POST /api/fixtures/import_file`, только с самого ПК, в MA2 ничего не отправляет.
- **Головы угадываются по имени типа** (`fixtures.guess_head`, ключи `HEAD_TYPE`: moving, mover, beam, sharpy, pointe, oxygen, robin, viper, mac …, mh, head), т.к. экспорт 3.9 не называет атрибуты, а число каналов не отличает голову от планки. Прибор без `moves` получает `moves: true, moves_auto: true`; явный выбор оператора не перезаписывается; в «Зале» кнопка подписана «Голова (угадано)»; `fixture_flag {id, moves, same_type: true}` ставит флаг всем приборам типа и снимает `moves_auto`.
- `moves` и `beam` импорт не трогает. `plan_copy {from, ids}`: из `shows/<from>.json` копируются `x, y, label, moves, service, rot, beam, flip_pan, flip_tilt, color` и группы панели (без групп пульта, без повторов по имени); в MA2 ничего не уходит. `config.plans` — имена других планов на ПК. (было: 7, 12.6, 15, 17, 19)

## Шоу

- `show_identify` читает `ListVar`; `ma2.showfile_regex` извлекает имя в `status.show`; нераспознанный ответ — имя неизвестно, сырой ответ в диагностике.
- `show_bind {name, confirm}` привязывает план (`config.show`); смена — только с `confirm: true`. `show_open_plan {name}` сохраняет прежний план в `shows/<безопасное имя>.json`, открывает выбранный или создаёт пустой; сбрасывает выбор и известные значения; команд переключения шоу не отправляет. При несовпадении имён — предложение открыть нужный план, импорт приборов блокируется; если оба имени неизвестны — сначала привязка.
- **Раздел «Шоу»: `shows_list`** читает `ListShows` (`ma2.listshows_regex`), показывает и сырой ответ; `ma2.shows_dir` даёт локальный список `*.show.gz`, сам по себе загрузку не разрешающий.
- **`show_load {name, confirm_name, ack_unsaved}`:** точное подтверждение имени, `ack_unsaved: true`, имя в свежем `ListShows`. Шлёт `ma2.loadshow_cmd` (по умолчанию `LoadShow "{name}" /nosave`), ждёт входа и `ListVar` до `ma2.load_timeout` (120 с); при успехе открывает план и, если разрешено, получает приборы. Во время загрузки действия света блокируются, связь и остановка доступны; неподтверждённая загрузка — `unknown` с причиной.
- **Сохранение — одна кнопка с подтверждением, без ввода имени:** мост читает `ListVar` (только чтобы назвать шоу в ответе) и шлёт ровно `SaveShow` — перезаписывается шоу, открытое на пульте.
- Сравнение имён шоу — без учёта регистра и лишних пробелов, без автозаглавных и автозамен; мосту уходит точное имя из `ListShows`.
- При `poll_seconds > 0` мост кроме `List Executor` читает `ListVar`: загруженное с пульта шоу видно в панели (баннер «На пульте шоу …»). (было: 15, 18, 19)

## Цвет, стробоскоп, скрытие слайдеров (dmx_map)

- **Каналы цвета и строба:** для каждого типа приборов мост один раз за запуск и при каждом «Получить приборы» шлёт `Export FixtureType <номер> "<одноразовое имя>"`, ищет файл по имени в папках пульта и на уровень ниже, берёт из первого модуля `ChannelType attribute=DIM/COLORRGB1/COLORRGB2/COLORRGB3` и `coarse`, а также `SHUTTER`/`STROBE` с `ChannelFunction`/`ChannelSet`: имя с `strob` — диапазон строба, с `open` — значение «открыто». Пишет в `dmx_map` типа: цвета и `strobe: {attr, open, from, to}` (проценты канала). Свой файл удаляет. Ручных полей каналов в «Зале» нет. Lua-чтение DMX требует прав Admin у Telnet-пользователя (с Program — Error #44).
- **Стробоскоп:** 0 = «выкл» → `Attribute "<attr>" At <open>`; 1–100 → линейно в `from..to`. Приборы разных типов получают строки по типам (как цвет `rgb`/`cmy`). Тип без диапазона строба стробоскоп не получает; если ни у одного выбранного нет — отказ с причиной. На пульте атрибута `Strobe` нет (`Error #14`).
- **Скрытие Zoom/Focus/строба:** в `dmx_map` пишется `has`. Слайдер не показывается, если у всех выбранных (при пустом выборе — у всех приборов плана) тип прочитан и атрибута нет. Тип не прочитан → слайдер виден и по-прежнему гаснет после `Error #14`. (было: 21, 24)

## Раздел «Патч» и RDM

- **Таблица приборов:** Fixture ID, имя, тип, адрес в патче, footprint профиля MA2 (колонка DMXFootprint из `List FixtureType`; экспорт приборов даёт меньше: у Mini-B 14 вместо 17; без него план правки не строится), занятый диапазон; пересечения отмечаются. Физический footprint — только если прочитан по RDM, иначе «не прочитан», не подменяется догадкой. Явный режим правки; без него раздел только показывает.
- **Смена адреса:** `Assign Fixture <id> At Dmx <u>.<aaa>` (keyword Dmx снимает старый патч). Перед записью мост строит план правки (было → станет, диапазоны, конфликты) с меткой; запись принимается только с той же меткой. После записи — перечитывание экспортом и сверка адреса. Тайм-аут не повторяется. Только при `safety.allow_patch` и только строка, собранная мостом для подтверждённого плана.
- **RDM:** панель RDM не включает и не выключает, а показывает, где это делается (Setup → Console Global Settings → Enable RDM; вселенная: Setup → Patch → DMX List, ячейка RDM), и напоминает выключить после операций. Чтение: `RdmList` (вывод как есть; UID из строк, остальные колонки не проверены). Запись: `RdmSetParameter dmx_start_address <a> / UID = <uid>`, `RdmSetParameter identify_device 1|0 / UID = <uid>`. Только при `safety.allow_rdm`. `RdmAutopatch`/`RdmAutomatch` и прочие RDM-команды не шлются никогда.
- **Сопоставление:** оператор сам связывает UID с прибором; связь хранится в `rdm` прибора (`uid`, `footprint`), не заменяет Fixture ID.
- **Согласованная смена:** сначала физический адрес по RDM, затем патч, затем перечитывание обеих сторон. Атомарности нет — панель показывает, что изменилось, и готовую обратную команду.
- Смена DMX personality/профиля не делается. Все записи патча и RDM попадают в «Историю» (было → стало); откат — только предложенной обратной командой с новым подтверждением. (было: 21)

## Группы и пресеты MA2

Группы MA2 (`ma2groups`) и пресеты (`ma2presets`) — только чтение, отдельно от групп панели. Выбор группы MA2 (`Group n`) — только если её состав прочитан. Запись группы панели в MA2 (`group_store_ma2`) — при `safety.allow_group_store`, с подтверждением номера и проверкой пустоты `List Group n` по `ma2.group_empty_regex` (шаблон, подходящий к занятой строке, отвергается настройками), без `/overwrite`. Форматы `List Group`, `List Preset` и пустого ответа — шаблоны в `settings.json`, проверить на площадке. (было: 16)

## История и откат

Раздел «История»: последние 100 изменений этого моста (время, что сделано), новые сверху; в памяти, перезапуск очищает. `undo {n}` откатывает одно изменение:
- свет (яркость, цвет, позиция, zoom, focus, strobe, пресет позиции): мост шлёт приборам прежние известные панели значения; движение одного слайдера в течение 3 с — одно изменение; неизвестное до изменения не откатывается;
- план (группы, пресеты, расстановка, зал, флаги, удаление сцены из панели и т.п.): изменённые ключи `config.json` возвращаются;
- действия на пульте (сцены, запись и имя сцены, страница, группа в MA2, загрузка шоу) видны, но панелью не откатываются.
Откат сам попадает в историю и тоже откатывается; каждое изменение откатывается один раз. (было: 20, 21)

## Диагностика

## Безопасность (safety)

Разрешения в `settings.json`, только bool, по умолчанию `false`, обязательны даже в `full`, доступны в настройках: `allow_fixture_read`, `allow_highlight`, `allow_show_load`, `allow_show_save`, `allow_group_store`, `allow_patch`, `allow_rdm`. Без `allow_fixture_read`: `ListVar` и `ListShows` — READ; экспорт — только точное совпадение с `ma2.export_cmd`. Каждая строка проходит `make_guard`. Журналируются новые действия; нет повторной отправки, нет `/Overwrite`, прежние ограничения приборов/сцен сохраняются. (было: 14, 15, 16, 21)

## Запуск на Windows и обновления

1. Один раз скопировать папку комплекта (собирается `scripts/build_win.sh`, Python внутри, `uv` не нужен); сборка берёт все `*.py` из корня проекта.
2. `start.bat` запускает `python\python.exe bridge.py` и перезапускает мост после смены настроек (код 3). Ярлык — в автозагрузку.
3. В Windows Firewall открыть порты 8080 и 8090, только частная сеть.
4. Закрепить IP Windows в DHCP роутера.

Дома: `uv run bridge.py --mock`, открыть `http://localhost:8080`.

Обновления: `scripts/serve_update.sh` на Mac раздаёт `ma2-panel-update.zip` + SHA256; `update.bat` на Windows по явному запуску, отказ при занятом мосте (`/api/idle`), заменяет только файлы программы, предыдущая версия в `previous/`, `rollback.bat`. (было: 8, 17, hall-test-plan 11)

## Автозапись ответов пульта

При первом входе в пульт после запуска моста (`start.bat`, без `--mock`) мост сам шлёт только читающие строки с ещё угаданным форматом: команды `--probe` (`ListVar`, `List Fixture`, `List Group`, `List Preset`, `List Sequence`, `List Executor` в нескольких диапазонах, `List Page`, `List User`, `List FixtureType`, `List Attribute`), `ListShows` и `List Executor <exec>` для каждой сцены плана (до 10). Повторный вход после обрыва запись не повторяет. После первого удачного `scene_go` каждой сцены (до 3 за запуск) добавляется `List Executor <exec>`. Строки идут через `action_lock` и `make_guard`, шоу не меняют. Ответы с замаскированным паролем — в `field-data/auto/<дата-время>.txt`, один файл на запуск, хранятся последние 20; три последних попадают в `diag.zip` (папка `auto/`). Владелец присылает `diag.zip`; по файлам правятся `commands.parse_*` и `DEFAULT_MA2`, ответы становятся тестами. (было: 23)

## Планшетный UI (2026-10-30)

Согласованный дизайн: [tablet-ui-design](superpowers/specs/2026-10-30-tablet-ui-design.md).
Графитовые поверхности, радиусы 6–10 px, основные касания ≥48 px, вторичные ≥44 px.
Короткий текст связи виден на всех ширинах; подробности по запросу. Цвет — состояние,
не единственный признак. В редакторе зала настройки прибора свёрнуты отдельно.

Движение: одинаковые переключатели «Точно»/«Зеркально»; инверсии — в свёрнутых
настройках, смешанные значения явно отмечены. Четыре стрелки передают nudge с step=1
(градус); явный step конечный, числовой, 0 < step ≤10, bool запрещён. Без step прежний
протокол сохраняет attrs.step/default 2. Ручного абсолютного Pan/Tilt в UI нет.
Пресеты панели свёрнуты; явное управление удалением с подтверждением, без скрытого
долгого удержания. MA2-пресеты остаются только для вызова. При уходе/потере связи
джойстик останавливается, фоновые jog не продолжаются.

Сообщение значений дополнительно содержит master: number|null — последнее успешно
отправленное значение панели, не измерение MA2. Оно сохраняется при перерисовке и
инвалидируется при смене шоу/поколения связи. Статус read_freshness содержит fixtures/ma2/scenes:
свежесть успешного чтения текущего подключения и шоу, отдельно от сохранённых данных.
Результаты info/success/warning/error различимы; ошибки не исчезают с кнопкой/диалогом,
подпись кнопки не заменяется сообщением.

Новая сцена: scene_slot_find {request} начинает отменяемый поиск; приватное событие
scene_slot {request,state,checked,total,exec?,token?,err?}, state — searching/ready/cancelled/error.
scene_slot_cancel {request} отменяет без прерывания текущего Telnet-ответа. В full
кандидаты 1.1–1.250, в store — только store_execs; занятые в плане исключаются.
Нет перехода на другие страницы при исчерпании. Пустота подтверждается распознанным
ответом конкретного List Executor, не отсутствием строки. Не более 250 проверок/30 с
до начала следующей проверки; token действует 60 с и связан с сокетом/шоу/планом/связью.
scene_create с token всё ещё передаёт exec/confirm/page; перед записью token и пустота
проверяются заново под action_lock. Устаревшая/занятая/неясная цель — отказ без выбора
другого адреса и без повтора. Поиск не удерживает action_lock между проверками.
Простой порт не принимает служебные действия поиска/редактирования.

Снимки значений содержат монотонный `values_revision` в пределах процесса моста.
Панель игнорирует запоздавшие старые снимки; при новом WebSocket начинает отсчёт заново.
Сцена с `write_error` не запускается ни с основного, ни с простого порта до исправления
записи; выключение по-прежнему доступно. Мастер синхронизирует ползунок после завершения
активного жеста, обычный фокус этому не мешает.
