# Панель управления светом MA2 — спецификация

Это текущее состояние. История запросов владельца по датам: `docs/archive/spec-history.md`. Новый запрос владельца = правка нужного раздела здесь + строка в конец spec-history.md.

Непроверенное на настоящем пульте ведётся в `docs/hall-test-plan.md`. Выполненные планы v1–v4 лежат в `docs/archive/`.

## Цель и пользователи

Веб-панель для света в зале музыкальной школы. Заменяет Web Remote grandMA2, работает только в локальной сети.

- **Учителя и персонал** (не знают MA2): включают записанные сцены, гасят свет, меняют общую яркость.
- **Администратор** (владелец проекта): управляет группами и приборами, яркостью, цветом, записывает сцены.

Устройства: Android-планшет (основное, горизонтальная ориентация), iPad, MacBook, телефон. Браузеры: Safari и Chrome. Управление касанием и мышью. Срока нет. Разработка дома в имитации, выезды в зал для проверки Telnet. (было: 1)

## Архитектура

```
[браузер] --WebSocket--> [мост, Windows с MA2] --Telnet localhost:30000--> [grandMA2 onPC 3.9]
```

- Мост на той же Windows, что и MA2, подключается по `localhost`, смена IP `.215` на связь с пультом не влияет.
- Планшеты открывают `http://<IP Windows>:8080`, к MA2 напрямую не подключаются.
- Сцены и группы хранятся в шоу MA2. Панель только отправляет команды.

Стек: Python 3.12, FastAPI + uvicorn, `asyncio.open_connection` для Telnet. Установка через `uv`. Панель — статика без фреймворков и сборки.

| Файл | Что делает |

## Режимы панели

**Простой режим** (по умолчанию на основном порту): кнопки сцен (Go и Off), «Погасить всё» с подтверждением, мастер-слайдер яркости.

**Простой порт для учителей.** Тот же процесс слушает `simple_port` из `settings.json` (по умолчанию `8090`, `null` выключает) — там `static/simple.html`: только плитки сцен и большая кнопка «Погасить всё» с подтверждением. Нет разделов, слайдеров, `/api/*`, журнала, диагностики. Защита на стороне моста: с этого порта принимаются только `scene_go`, `scene_off`, `blackout` (и служебный запрос состояния), остальное — отказ «в простом режиме недоступно». Ограничения `safety` действуют как на основном порту; `config` содержит только сцены и страницы. В Firewall открыт порт 8090 (частная сеть).

**Полный режим** — остальные разделы, без PIN (доступ ограничен паролем Wi-Fi зала; пароль знают двое, отдельной защиты на мосту нет). (было: 3, 24)

## Интерфейс: разделы

Тема одна, тёмная (цвета — CSS-переменные в `style.css`). Навигация: боковое меню Сцены / Свет / История / Площадка / Зал / Патч / Шоу (на телефоне — снизу). Верхняя строка: шоу на пульте, связь, «Выбрано: N», «Стоп передачи» (сразу), «Погасить свет» (второе нажатие в течение 3 с вместо диалога). Устройство помнит последний раздел и вкладку выбора (`localStorage`: `ma2.sec`, `ma2.pick`).

- **Сцены**: единый сохранённый список с порядковыми номерами 1, 2, 3 и именами, без страниц и executor в основной выдаче. Вызов/выключение на плитке; удаление и перезапись только в «Изменить», с подтверждением цели. «Переход» и мастер сохраняются. Простой порт показывает тот же порядок/имена без редактора.
- **Свет**: управление разделено на вкладки «Свет» и «Движение» с общим выбором; неизвестные значения не подменяются начальными. Выбор по вкладкам Группы (панели и MA2, с меткой) / Приборы / План; карточки яркости (+ время перехода), цвета (палитра + пресеты MA2), позиции и луча (пад + пресеты позиции MA2), стробоскопа. Значения: «отправлено панелью», «неизвестно», «разные». Неподдерживаемый параметр (по `params` прибора) — карточка неактивна с пояснением.
- **Зал** — редактор (бирюзовый): вход шлёт `edit_begin`, уход — `highlight_off` и `edit_end`; галочка подсветки каждый раз выключена; пошаговая расстановка «прибор → касание схемы → следующий» (`layout_save` на каждое касание), служебный флаг (`fixture_flag`), форма зала (`hall_save`, прямоугольник), группы панели и «В MA2…» (`group_store_ma2`), калибровка луча.
- **Шоу**: список шоу, привязка, загрузка, сохранение.
- **Площадка**: связь, «Получить оборудование из MA2», таблица приборов, чтение групп/пресетов/сцен MA2 (`ma2_read`) и выбор, что добавить (`ma2_import`). (было: 12.3, 16)

Поставляемый `config.json` пустой: без приборов, групп, сцен; при первом запуске v4 старый конфиг копируется в `backups/` и `shows/<шоу>.json`, сам не очищается (`version: 4`). Первое чтение приборов привязывает непривязанный план к шоу на пульте. (было: 16)

## Схема зала

- **Фон:** рисуется по форме зала `config.hall`; `plan.image` и `static/plan.svg` не используются (удалены).
- **Приборы:** иконки в точках `x`, `y` (доли 0-1). Нажатие выбирает, повторное — снимает; выбор множественный и общий для всех вкладок.
- **Яркость и цвет значков** — только свежий прочитанный выход MA2; при неизвестном/устаревшем выходе значки не изображают свет. История отправленных значений в органах управления не является измерением выхода.
- **Выбор группы** подсвечивает её приборы на схеме. Состав групп хранится в `config.json`.
- **Расстановка:** пошаговая «прибор → касание схемы → следующий» (`layout_save` на каждое касание), см. раздел «Интерфейс: разделы» → «Зал».
- **«Обновить из пульта» / «Получить приборы»:** см. раздел «Приборы».
- Значки: по `fixture_flag {id, icon: par|bar|head|fresnel}` — круг, прямоугольник, квадрат, ромб; угадывание по типу заменено флагом. `fixture_flag {id, rot: 0|90}` поворачивает значок планки. Неподвижные — точки без направления.
- **Лучи голов** — условное расчётное направление по последнему известному Pan панели, не измерение физического луча. Угол = направление от положения `x/y` прибора к центру сценической зоны `config.hall.stage` + (pan − `beam.home`) / 100 × (`attrs.pan.max − attrs.pan.min`), знак минус при `beam.invert`. Стороны сцены: top/bottom/left/right; размеры и глубина — из `config.hall`. Калибровка задаёт направление прибора; поворот значка `rot` относится к планке, не к Pan головы. Длина постоянна относительно схемы и не зависит от Tilt: высота, проекция и физический диапазон конкретного типа не моделируются. Выбранная голова — яркое направление, остальные — бледные. Без калибровки, известного свежего Pan панели или диапазона, при потере связи и для пропавшего прибора направления нет. Неизвестный Tilt не подменяется значением и не определяет геометрию. Изменение калибровки и масштаба обновляет рисунок. В простой панели схемы нет. Калибровка (вкладка «Зал», одна голова): «Сейчас светит прямо на сцену» запоминает Pan, «Луч крутится не туда» меняет знак.

## Протокол панель ↔ мост

**Свидетельства команды (согласовано 2026-11-05):** терминальный ответ запроса
с `request_id` дополнен `command_evidence`: снимок уже собранных для операции
статусов `sent`, `error`, `unknown`, `not_sent` в наблюдённом порядке. `ok`,
`outcome` и обработка операций не меняются. Ответы legacy-запросов без
`request_id` сохраняют прежнюю форму. Старый клиент может игнорировать поле;
новый клиент при отсутствии поля не предполагает ответ MA2. Пустой массив
означает отсутствие записанных свидетельств, а не доказательство сохранения.
`sent` — завершённый ответ без распознанной ошибки, не применение изменения;
`completed` — завершение обработки. Свежий readback показывается отдельно и
не связывается с конкретной командой без отдельного доказательства.

С 2026-11-10 отложенного Off нет. В одном action_lock мост задаёт Off Time прежних запусков панели в текущем плане/шоу через Masterfade, запускает Cue 1 через Goto с общим временем и сразу отправляет адресные Off. Переход выполняет MA2; успешный ответ моста не означает физического завершения fade. Stop, смена шоу и reconnect отменяют неотправленный остаток; уже отправленный fade пульт может завершить сам.

Панель отправляет только действия. Строки MA2 собирает мост; произвольную строку отправить нельзя. `ClearAll`, патч и `/noconfirm` в протоколе отсутствуют. Сцены не очищают Programmer.

| Действие | Режим | Строки MA2 / что делает мост |
|---|---|---|
| `scene_go {id, swap?}` | простой | Свежие ListVar, однозначный List Executor (Normal/LTP, SoftLTP=on, Chaser=off) и nonce-проверка одиночной Cue 1/Go с пустым CMD единственной части; затем `Masterfade T Executor <прежние запуски панели в текущем плане/шоу>`, `Goto Cue 1 Executor <exec> Fade T`, адресные `Off` остальных. `swap` принимается для совместимости, область и время определяет сервер. |
| `scene_off {id}` | простой | `Masterfade T Executor <exec>`, затем `Off Executor <exec>`; T — текущее серверное `scene_fade` (0–30 с), клиентское `fade` игнорируется. |
| `blackout` / «Blackout MA2» | простой, только full | Чтение Grand, журнал исходного уровня, `SpecialMaster 2.1 At 0`, контрольное чтение. Повторное нажатие возвращает прежний уровень при том же контексте и текущем 0. Programmer/Executor/штатная B.O.-маска сохраняются. |
| `master {v 0-100}` | простой | команда мастера из конфига (`master.cmd`) |
| `select_group {id}` | полный | `Group <n>`; для группы без `n` — `Fixture a + b + c` |
| `select_fixtures {ids}` | полный | `Fixture a + b + c` |
| `dim {v 0-100}` | полный | `At <v>` |
| `color {r,g,b 0-100}` | полный | `Attribute "ColorRGB1/2/3" At …` — три команды; для `cmy` — строки по типам |
| `strobe {v 0-100}` | полный | см. «Стробоскоп» |
| `clear` | полный | `Clear` |
| `jog {pan, tilt, mirror}` | полный | относительный шаг в градусах (−45…45); мост суммирует шаги вкладки и не чаще `rate_hz` шлёт `Fixture …` + `Attribute "Pan/Tilt" At + <°>` / `At - <°>` (`attrs.<attr>.rel_cmd`) |
| `nudge {attr, dir}` | полный | относительный шаг (`attrs.<attr>.rel_cmd`, `step` в градусах, 0–10) |
| `aim {pan?, tilt?}` | полный | одна или обе оси в абсолютных градусах в пределах `min..max`; хотя бы одна обязательна, отсутствующая ось не меняется |
| `zoom {v}`, `focus {v}` | полный | одно значение на всех выбранных подвижных |
| `preset_save {label}` / `preset_go {id}` / `preset_delete {id}` | полный | пресеты позиции: сохранение Pan/Tilt из `shown`, вызов, удаление |
| `group_save {label, ids}` / `group_delete {id}` | полный | группы панели без `n`; удалить можно только их |
| `group_store_ma2` | полный | запись группы панели в MA2, см. «Безопасность» |
| `scene_create {label, page, exec?, confirm, replace?}` | полный | см. «Сцены» |
| `scene_rename`, `scene_delete {id, desk?}` | полный | см. «Сцены» |
| `show_bind`, `show_open_plan`, `shows_list`, `show_load`, `show_save` | полный | см. «Шоу» |
| `layout_save {pos}` | полный (в MA2 не уходит) | проверка id и чисел 0-1, запись в `config.json` |
| `fixtures_fetch` | полный | см. «Приборы» |
| `edit_begin` / `edit_end`, `highlight…` | полный | см. «Подсветка» |
| `beam_home {id}` / `beam_invert {id}` | полный | запись `fixtures[].beam.home` / переключение `invert` |
| `fixture_flag {id, …}` | полный | флаги: `moves` (+`same_type`), `icon`, `rot`, `flip_pan`, `flip_tilt` |
| `undo {n}` | полный | откат, см. «История» |
| `hall_save`, `page_save {n, label}`, `scenes_import`, `plan_copy {from, ids}` | полный | см. соответствующие разделы |

Мост → панель: `{"ok": true}` / `{"ok": false, "err": "..."}` на каждое действие и рассылки:
- `status`: `ma2: down | tcp | login_failed | login_unknown | logged_in | manual_off`, `mock`, `show`, `no_attr {attr: [type]}`; команды уходят в `logged_in` и `login_unknown`;
- `config` (без `ma2`) при подключении и после каждого сохранения; на простом порту — только сцены и страницы;
- `shown`: последние отправленные значения `{id: {dim, rgb, pan, tilt, zoom, focus}}` после каждой отправки; scene_go/blackout сохраняют Programmer и последние отправленные значения;
- `running {id: bool}` — опрос статуса сцен; `page`, `last` (результат последней строки).

Мост помнит текущий выбор (группа → приборы, или список) и позицию головы — но позиция известна только после абсолютного значения, отправленного самой панелью и принятого без ошибки; забывается при потере связи и после `scene_go`. Значения, выставленные на самом пульте, панель не видит: Telnet их не сообщает. (было: 4, 12.4, 13, 14, 17, 18, 19, 20)

### Движение голов

Подвижные приборы: не missing, с `"moves": true` в конфиге или с точным именем Pan/Tilt в `params` из экспорта (PANROTATE не считается Pan). Выбор нескольких голов — все двигаются вместе.

- **Пад — как стик геймпада:** отклонение задаёт скорость, при отпускании возвращается в центр, голова остаётся на месте. Квадратичная кривая, 90 °/с у края, мёртвая зона 8 % (`JOY_SPEED`, `JOY_DEAD` в `static/move.js`); «Точно (медленно)» — 15 % (`JOY_FINE`). Пад на всю ширину карточки. Панель шлёт `jog` 10 раз/с; относительные команды позволяют крутить голову одновременно с пультом.
- Если в выборе нет подвижных — пад неактивен с подписью «Выберите голову».
- **Инверсия:** `flip_pan` / `flip_tilt` меняют знак шагов (джойстик и ←→↑↓); абсолютные команды флаги не учитывают. Кнопки «Pan наоборот», «Tilt наоборот» ставят флаг всем выбранным.
- **«Зеркально: сводить и разводить»** (`mirror: true` в `jog` и `nudge`): левая половина выбранных голов по `x` на схеме (без места — по номеру) крутит Pan в обратную сторону; при нечётном числе средняя — как обычно.
- **Нет атрибута:** `Error #14: OBJECT DOES NOT EXIST` на Zoom/Focus/Strobe показывается как «у выбранных приборов на пульте нет атрибута «Focus»». Если все выбранные одного типа, мост запоминает `status.no_attr` (до перезапуска), ползунок неактивен.

Синтаксис атрибутов задаётся шаблонами в `config.json`, правится в зале без изменения кода:

```json
"attrs": {
  "pan":   {"cmd": "Attribute \"Pan\" At {v}",   "min": -270, "max": 270},
  "tilt":  {"cmd": "Attribute \"Tilt\" At {v}",  "min": -135, "max": 135},
  "zoom":  {"cmd": "Attribute \"Zoom\" At {v}",  "min": 0, "max": 100},
  "focus": {"cmd": "Attribute \"Focus\" At {v}", "min": 0, "max": 100}
}
```

Панель работает в 0-100; мост пересчитывает линейно в `min..max`, округляет до 0,1. У всех целевых голов одно значение (Zoom, Focus, одна голова) → строки атрибутов идут на текущий выбор. У голов с разными значениями (`move`, `preset_go` на нескольких головах) — для каждой `Fixture <id>` и строки атрибутов, затем возврат выбора (`Fixture a + b` или `Group <n>`); пометка в коде `# ponytail: …` — заменить на одну команду, если найдётся синтаксис. (было: 12.2, 12.5, 14, 16, 18)

## Частота команд

- Панель шлёт слайдеры не чаще 10 раз/с.
- Мост хранит последнее значение на слайдер и шлёт не чаще `rate_hz` (начально 5, подбирается в зале). Для `jog` ожидающие шаги суммируются, ни один не теряется; для абсолютных слайдеров промежуточные значения могут отбрасываться — последнее приводит в нужную точку.
- Кнопки (сцены, выбор, запись) в ограничение не попадают и выполняются строго по порядку. (было: 5, 12.4, 18)

## Связь и ошибки

- **Восстановление контекста (этап 2, 2026-11-10):** вход Telnet ещё не разрешает
  управление во время восстановления. После повторного соединения подтверждаются
  имя/привязка шоу и, при существующем Patch, перечитываются приборы с типами.
  Без allow_fixture_read восстановление Patch требует включить чтение и явно
  получить приборы; неоднозначный импорт ждёт выбора. Старые действия/позиции/
  очереди не воспроизводятся. status.recovering/recovery_error видны клиентам.
  Состав группы MA2 перечитывается перед её выбором.

- Нет WebSocket: красная полоса «Нет связи с мостом», кнопки неактивны, переподключение каждые 2 с; нажатия без связи не копятся.
- Нет связи с MA2: полоса «Нет связи с пультом», кнопки неактивны, переподключение каждые 3 с; команды из очереди при обрыве выбрасываются.
- Ошибка входа: отдельное сообщение, повтор входа каждые 30 с, перезапуск не нужен.
- Ответ с `Error` или `Illegal` — ошибка, показывается на кнопке. Разбор одной функцией.
- Обрыв связи мост↔MA2 проверяется действиями `link_drop` / `link_connect` (открыть/закрыть Telnet-сессию самого моста; после `link_drop` мост сам не переподключается).
- **Результат строки:** `sent` (приглашение получено, слов ошибки нет; не доказательство действия), `error`, `unknown` (нет приглашения за `ma2.timeout`, по умолчанию 2 с; команда могла выполниться), `not_sent`. Ничего не отправляется повторно. После `unknown` мост ждёт поздний ответ; если его нет — следующая строка не уходит, соединение переоткрывается.
- Все команды и ответы пишутся в `bridge.log` с ротацией по размеру; журнал не-слайдерных действий с IP устройства — последние 300 отдаёт `/api/log`, страница `/log.html`. (было: 6, 13, 14)

## Сцены и страницы

- **Неподтверждённый охват Executor (2026-11-04):** если диапазон List принят только после уменьшения верхней границы, весь импорт сцен (`scenes_import` и сцены в `ma2_import`) отклоняется с причиной, без сохранения прочитанных сцен и без признака свежести. Уменьшенная граница не переносится на другие страницы/повторные запросы. Штатное переключение локального плана вслед за шоу пульта перед `scenes_import` сохраняется; это не импорт каталога. Даже исходный успешный диапазон не доказывает все пулы/адреса MA2: полная адресная модель требует аппаратной проверки.

- **Halt/Resume (2026-11-10):** Stop навсегда отменяет неотправленные стадии старого действия, включая ожидание lock. Resume разрешает только новые действия. Таймеров выключения сцен нет; отправленный MA2 переход не откатывается.

- Техническая привязка сцены — `exec` вида `<страница>.<номер>`, команда использует id сцены. Основная выдача плоская: номер — индекс массива `scenes` + 1. Старый план однократно сортируется численно по exec и получает `scene_order_version: 1`; далее порядок сохраняется. Импорт обновляет имена по нормализованному exec, сохраняет id/порядок и добавляет новые сцены в конец. Частичный ответ не удаляет сцены. Непустой label отображается независимо от legacy named. Адрес показывается в редакторе и подтверждении записи, переключение Page для запуска не нужно.
- **Запись — только `scene_create`**: привязанное и свежеподтверждённое шоу, выбранные существующие приборы, режим full либо store и разрешённый адрес, совпадение exec/confirm, распознанное пустое место. `Fixture <выбранные>` → `Store Executor <exec> Cue 1 /Source=Output /Use=Allforselected` → `Assign Cue 1 Executor <exec> /Trig=Go` → Label и чтение ручной Cue. StoreLook/SaveShow не используются. Активную подсветку нужно сначала снять. `store_scene` остаётся отключённым.
- **Обновление**: `scene_create {replace:true,exec,confirm,label,page}` сохраняет id/exec/место сцены. До изменения target в проверенном пустом spare сохраняется новый Cue 1, затем старый target Cue 1 копируется в spare Cue 2. Только после резервирования выполняется `Copy Cue 1 Executor <spare> At Cue 1 Executor <target> /CueOnly /Overwrite`. Старый Executor не удаляется. Резерв сохраняется как backup_exec; отдельные ошибки имени не означают отказ Cue. Journal scene-write-<exec>.json и write_error до commit блокируют слепую повторную запись/запуск неопределённого target. Ошибка подготовки оставляет старую сцену пригодной; unknown commit требует ручной проверки резерва, без автоматического rollback.
- Удаление доступно только в редакторе: «Убрать из панели» сохраняет Executor. «Удалить на пульте» требует свежеподтверждённого шоу и явного подтверждения; восстановление из бэкапа выполняет оператор.
- `scene_rename` — `Label Executor` + имя в конфиге. Кавычки в именах запрещены.
- **Область сцен:** запуск заменяет только разрешённые Executor из scenes, не другие playback и не Programmer. Allforselected записывает все атрибуты выбранных приборов. Совпадающие приборы требуют normal LTP/Soft LTP; неизвестное чтение или иные параметры блокируют запуск. Programmer имеет собственный приоритет и может перекрывать сцены: выделенный пользователь панели или ручное снятие значений оператором. Snap/чужие внешние триггеры остаются условиями MA2-приёмки.
- **`scenes_import`:** сначала переход на план шоу с пульта; мост шлёт `ma2.list_cmd` (по умолчанию `List Executor {page}.1 Thru {page}.250`) по страницам плана и всем страницам, где `List Page` показывает объекты (`(N)` в конце строки); существующие сцены не меняются; сообщает число нераспознанных строк и `total`. Разбор строки: необязательное слово (`Executor`, `Exec`), необязательный номер, `стр.номер`, возможно повтор, имя.
- **Состояние сцен:** опрос `List Executor` с настроенным периодом и ограниченной нагрузкой; `running` содержит bool/null и метаданные источника/свежести. Отсутствие или устаревание подтверждения означает неизвестность; подробности — раздел «Достоверность статусов». Формат и нагрузка требуют приёмки MA2.
- `page_save {n, label}`: `Label Page n "…"`. (было: 4, 13, 14, 20, 22)

## Обратимое глобальное затемнение (этап 1, 2026-11-10)

Интеграция этапа 4 (2026-11-10): каждое намеренное затемнение/восстановление
увеличивает `blackout_epoch`, отменяет ожидающие значения и fades моста, базы
жестов, прежние light Undo и in-flight действия. Старые сообщения с прежним
поколением отклоняются; после первого переключения light-клиент без поколения
должен обновиться. До первого переключения legacy-запросы совместимы; legacy
blackout без поколения остаётся явным переключением. Простой и основной клиент
передают поколение из status. Unknown Grand запрещает повторное переключение
и показывает инструкцию проверить мастер вручную; очередь не воспроизводится.
Сброс свидетельств панели не означает очистку Programmer на MA2.

Первое нажатие «Blackout MA2» опускает Grand Master после чтения исходного
уровня; повторное «Восстановить свет» возвращает именно этот уровень, включая 0.
Статус общий для всех клиентов. B.O.-маска, сцены и Programmer не переключаются.
При смене шоу/соединения, неизвестном результате, рестарте с журналом либо чужом
ненулевом Grand автоматического восстановления нет. Исходный уровень записан
в blackout.json; дальнейшая проверка/восстановление выполняется на MA2 вручную.
Неизвестное чтение или отсутствие явной процентной единицы в value блокирует действие до команды, без угадывания 100%.

React to Master=Off, Park, DMX tester/merge, внешний DMX и приборы без dimmer
не обещаются погашенными. Это не отключение питания. Повторный чужой 0 отличить
невозможно: требуется согласовать владение Grand. Под затемнением playback
продолжает выполняться; восстанавливается механизм подавления, а не старый кадр.

`scene_fade {fade:0..30}` сохраняет одно время в плане для всех его сцен и
обоих интерфейсов; клиентский fade в scene_go не переопределяет настройку.
Для изменяющих операций по номерам плана check_show требует одновременно
привязку и подтверждённое имя MA2 с совпадением. Запись сцен дополнительно
читает ListVar перед каждой стадией. Транспортный unknown/error не повторяется. После завершённого ListVar со старым
nonce допускаются до трёх read-only чтений с паузой 50 мс; Lua запроса не
переотправляется. После единственной записи Grand до трёх новых nonce-замеров
могут дождаться target; иначе unknown и журнал, без повторной записи/компенсации.

Обоснование команд, границы проверки и приёмка:
[ma2-command-evidence.md](ma2-command-evidence.md). Составные команды и Lua
свойства требуют отдельного onPC-теста; mock не доказывает аппаратную семантику.

Копирование Cue при записи/резервировании использует явный `/CueOnly`; commit
добавляет `/Overwrite` только для Cue 1→Cue 1. Это исключает интерактивный выбор
метода Copy; `/NoConfirm` не используется. На 3.9.63.11 проверены пустые Cue,
сохранность значений выбранных приборов требует отдельной приёмки.

## Подсветка (highlight)

- `highlight {id}`: при первом выборе гасит остальные приборы зоны, затем зажигает выбранный; при смене гасит предыдущий. `highlight.level` — яркость (по умолчанию 100). Включение требует подтверждения: подсветка гасит остальные приборы зала.
- Зона исключает `missing`, `service`, `highlight.exclude`; вне `full` ограничена `allowed_fixtures`. Подсветкой владеет одна вкладка; `highlight_ping` продлевает аренду `highlight.lease_s` (по умолчанию 10 с).
- Снятие через `Off Fixture <зона>` и восстановление известных отправленных панелью значений — при `highlight_off`, выходе из редактора, разрыве вкладки, истечении аренды. При запуске моста, повторном входе в пульт, «Возобновить» и переключении плана `Off Fixture` не шлётся (см. ниже). `highlight.json` сохраняет зону для восстановления после запуска; при невозможности снять — состояние `stuck`, новый выбор заблокирован.
- **Приоритет нового света (2026-11-04):** новое действие панели со светом (любой клиент), halt, потеря соединения или контекста отменяют прежнее автоматическое снятие целиком: ни `Off Fixture`, ни восстановление снимка не отправляются. Состояние — `stuck`. После частичного/неизвестного снятия автоматического повтора и компенсации нет. Отдельная кнопка в баннере требует подтверждения текущего предупреждения (`release_token`); она отправляет только `Off Fixture`, без прежних значений. Новое действие делает это подтверждение устаревшим. Реальные приоритеты и совместимость Programmer проверяются отдельно на MA2.
- **Ничего само не гасит свет:** при запуске моста, повторном входе в пульт, «Возобновить» и переключении плана мост не шлёт `Off Fixture` — подсветка остаётся «не снята», её снимает кнопка в баннере с предупреждением (зал 2026-10-21: команда стирала ручную работу, спасло только Oops). (было: 15, 19)

## Приборы и импорт

- **Полный refresh (этап 2, 2026-11-10):** некорректный/дублирующийся ID,
  битый XML и неоднозначная идентификация не применяются частично. При перестановке
  известных IDs требуется явный выбор идентичности. Перенумерация обновляет ссылки
  groups.fixtures и ma2groups.ids, включая группы с n. Подписи, расстановка,
  значки, инверсии и прочие ручные свойства сохраняются; удалённые остаются missing.
  Изменение адреса/типа/ID отменяет достоверность адреса RDM, сохраняя UID как
  прежнюю привязку со stale. Новое чтение RDM подтверждает адрес отдельно.
  Сохранение плана атомарно; ошибка записи не делает прежние карты stale в памяти.
  Пустой/неопознанный XML не доказывает удаление всех приборов. Семантически
  укороченный, но корректный XML без независимого списка IDs автоматически
  отличить от удаления нельзя; прежние записи физически не удаляются из плана.

- **`fixtures_fetch` («Получить приборы»):** сначала читает имя шоу на пульте; если план привязан к другому шоу — сохраняет его в `shows/`, открывает (или создаёт) план шоу с пульта и импортирует туда (ответ `switched: <имя>`). Экспорт командой `ma2.export_cmd` (по умолчанию `Export Fixture 1 Thru 9999 "panel_fixtures"`, без `/o`): удаляет свой старый XML в `ma2.export_dir`, ждёт до `ma2.export_wait` секунд, ищет свежий файл по glob из `ma2.export_search`. XML сливается с планом: имена, типы, параметры, адреса обновляются; расстановка и подписи сохраняются; новые — в лоток, исчезнувшие — `missing: true`. Ошибка не меняет конфиг; последний XML — в `diag/last_export.xml` и архиве.
- **Подтверждение неоднозначного импорта:** если нескольким исчезнувшим приборам подходит новый или нескольким новым подходит один исчезнувший, план не меняется до явного выбора для каждого нового прибора. Можно перенести место, подпись и отметки только от указанного кандидата либо явно оставить прибор новым. Один старый прибор нельзя назначить двум новым. Подтверждение связано с конкретным запросом и исходным планом; смена шоу, плана или его правка требует нового импорта. Подтверждение не отправляет команд в MA2. Это относится к получению из MA2 и ручному XML; итог показывает добавленные, пропавшие приборы и записи без Fixture ID.
- **Перепатч:** пропавший прибор с новым номером при том же имени и типе (ровно один новый и один исчезнувший кандидат с этим именем и типом) наследует место, подпись и отметки. Команды пульту идут по `Fixture N`, смена DMX-адреса не мешает.
- **Приборы без Fixture ID** (только Channel ID) панель не ведёт; импорт возвращает имена в `no_id` — «дайте им Fixture ID в патче MA2».
- **Ручной импорт XML:** `POST /api/fixtures/import_file`, только с самого ПК, в MA2 ничего не отправляет.
- **Головы угадываются по имени типа** (`fixtures.guess_head`, ключи `HEAD_TYPE`: moving, mover, beam, sharpy, pointe, oxygen, robin, viper, mac …, mh, head), т.к. экспорт 3.9 не называет атрибуты, а число каналов не отличает голову от планки. Прибор без `moves` получает `moves: true, moves_auto: true`; явный выбор оператора не перезаписывается; в «Зале» кнопка подписана «Голова (угадано)»; `fixture_flag {id, moves, same_type: true}` ставит флаг всем приборам типа и снимает `moves_auto`.
- `moves` и `beam` импорт не трогает. `plan_copy {from, ids}`: из сохранённого плана шоу копируются `x, y, label, moves, service, rot, beam, flip_pan, flip_tilt, color` и группы панели (без групп пульта, без повторов по имени); в MA2 ничего не уходит. `config.plans` — имена других планов на ПК. (было: 7, 12.6, 15, 17, 19)

## Шоу

- `show_identify` читает `ListVar`; `ma2.showfile_regex` извлекает имя в `status.show`; нераспознанный ответ — имя неизвестно, сырой ответ в диагностике.
- `show_bind {name, confirm}` привязывает план (`config.show`); смена — только с `confirm: true`. `show_open_plan {name}` сохраняет прежний план в `shows/<безопасное имя>.json`, открывает выбранный или создаёт пустой; сбрасывает выбор и известные значения; команд переключения шоу не отправляет. При несовпадении имён — предложение открыть нужный план, импорт приборов блокируется; если оба имени неизвестны — сначала привязка.
- **Раздел «Шоу»: `shows_list`** читает `ListShows` (`ma2.listshows_regex`), показывает и сырой ответ; `ma2.shows_dir` даёт локальный список `*.show.gz`, сам по себе загрузку не разрешающий.
- **`show_load {name, confirm_name, ack_unsaved}`:** имя из выбранной строки списка и обычный диалог подтверждения с названием шоу и предупреждением о потере несохранённых изменений; без ручного ввода имени и отдельной галочки. После согласия UI отправляет точное `confirm_name` и `ack_unsaved: true`; мост проверяет совпадение имени и наличие в свежем `ListShows`. Шлёт `ma2.loadshow_cmd` (по умолчанию `LoadShow "{name}" /nosave`), ждёт входа и `ListVar` до `ma2.load_timeout` (120 с); при успехе открывает план и, если разрешено, получает приборы. Во время загрузки действия света блокируются, связь и остановка доступны; неподтверждённая загрузка — `unknown` с причиной.
- **Сохранение — одна кнопка с подтверждением, без ввода имени:** мост читает `ListVar` (только чтобы назвать шоу в ответе) и шлёт ровно `SaveShow` — перезаписывается шоу, открытое на пульте.
- Сравнение имён шоу — без учёта регистра и лишних пробелов, без автозаглавных и автозамен; мосту уходит точное имя из `ListShows`.
- При `poll_seconds > 0` мост кроме `List Executor` читает `ListVar`: загруженное с пульта шоу видно в панели (баннер «На пульте шоу …»). (было: 15, 18, 19)

### Обмен настоящими файлами шоу через браузер

1. Обмен целыми `.show.gz` доступен в разделе «Шоу» с устройства браузера через
   основной ПК с локальной MA2 onPC. Требуется однозначно настроенный каталог
   `ma2.shows_dir` текущей установки; его настройка доступна только на основном ПК.
   Не выбирать каталог другой версии автоматически. Для удалённого пульта без
   доступа к его файловой системе операция недоступна с понятной причиной.
2. «Загрузить файл шоу»: выбор файла браузером → ограниченная потоковая передача
   во временное хранилище моста → проверка расширения, размера и целостности gzip
   (до 512 МиБ сжатого и 2 ГиБ распакованного потока). Не распаковывать содержимое
   в каталоги MA2. Повреждённый контейнер не становится доступным для LoadShow.
   Корректный gzip может содержать не шоу: UI сообщает, что проверена целостность
   контейнера, а формат и совместимость версии окончательно проверяет MA2.
3. После проверки показать исходное имя, размер и имя назначения MA2. Сохранить
   отдельной копией без перезаписи существующего файла; при совпадении дать новое
   безопасное имя. Исходные байты сохраняются. Имена/пути от браузера не становятся
   путями на ПК или фрагментами команд MA2.
4. Перед LoadShow — отдельное подтверждение точного назначения и потери
   несохранённых правок текущего шоу. Одноразовое подтверждение связано с файлом,
   его хешем и состоянием подключения/шоу; устаревшее согласие отклоняется.
   Только при allow_show_load, через action_lock и make_guard. Выбрать внутренний
   диск, проверить файл и свежий ListShows; если имя отсутствует — не посылать
   LoadShow. Не добавлять /full и флаги замены настроек. План панели переключается
   лишь после подтверждения имени MA2 по существующему механизму.
5. «Скачать шоу» предлагает сохранённую версию текущего шоу: имя, время файла,
   предупреждение, что несохранённые изменения MA2 в неё не входят. Команд записи
   не отправляет. Выдавать неизменяемый проверенный снимок настоящего `.show.gz`
   средствами браузера, без JSON плана и без HTTP Content-Encoding: gzip.
6. Отдельный вариант «Сохранить текущее и скачать» требует allow_show_save и
   явного подтверждения перезаписи названного текущего файла. До записи проверить
   текущее имя/связь и сохранить отдельную локальную резервную копию прежнего файла.
   Внутренний диск, один SaveShow; не использовать SaveShow под новым именем.
   Ждать наблюдаемого обновления файла, стабильности, полной проверки gzip и
   копирования без изменений источника. Если обновление не доказано, прежний файл
   не выдавать за результат новой записи; показать unknown и возможность отдельно
   скачать сохранённую версию. Автоматического восстановления файла MA2 нет.
7. Этапы различают передачу файла, проверку, ожидание согласия, запись/загрузку
   MA2, подтверждение и готовность скачивания. При тайм-ауте/обрыве после отправки
   команды — unknown; команду не повторять. Повтор запроса с тем же ID не запускает
   запись/загрузку заново. Чтение статуса и повтор скачивания готового снимка
   допустимы. После перезапуска моста незавершённая операция не возобновляется.
8. Смена шоу другим клиентом панели, остановка, потеря связи и два параллельных
   запроса не должны смешивать файл, подтверждение и имя. Загрузка/сохранение
   сериализованы для клиентов этого моста;
   GET ничего в MA2 не записывает. Сохраняются проверки Origin/Host, запрет
   произвольных путей и существующие разрешения. Разрешённая панель в LAN может
   передавать/скачивать шоу; локальные настройки/секреты ей не выдаются.
   Мост не блокирует действия на самом MA2 или из другой Telnet-сессии. Между
   ListVar и SaveShow внешний оператор может переключить шоу: атомарного
   «сохранить только если имя прежнее» в изученной документации нет. В подтверждении
   сохранения требуется предупреждение не переключать шоу и не выполнять запись
   извне до окончания операции. Проверка имени до/после выявляет часть гонок,
   но не предотвращает сохранение другого шоу при внешнем вмешательстве.
9. Передача браузеру подтверждает готовность файла и начало скачивания, но не
   запись на устройство: место сохранения и итог контролирует браузер.
   config/settings/secret и существующие планы не подменяются загруженным архивом.


## Цвет, стробоскоп, скрытие слайдеров (dmx_map)

- **Каналы цвета и строба:** для каждого типа приборов мост один раз за запуск и при каждом «Получить приборы» шлёт `Export FixtureType <номер> "<одноразовое имя>"`, ищет файл по имени в папках пульта и на уровень ниже, берёт из первого модуля `ChannelType attribute=DIM/COLORRGB1/COLORRGB2/COLORRGB3` и `coarse`, а также `SHUTTER`/`STROBE` с `ChannelFunction`/`ChannelSet`: имя с `strob` — диапазон строба, с `open` — значение «открыто». Пишет в `dmx_map` типа: цвета и `strobe: {attr, open, from, to}` (проценты канала). Свой файл удаляет. При ошибке экспорта типа или чтения размеров допускаются до трёх попыток с паузой не менее 30 с; смена соединения/шоу и ручное «Получить приборы» сбрасывают лимит. Старые карты не становятся достоверными из-за повтора. Ручных полей каналов в «Зале» нет. Lua-чтение DMX требует прав Admin у Telnet-пользователя (с Program — Error #44).

- **Выход MA2 (этап 2, 2026-11-10):** live — только свежие байты Lua/getdmx,
  shown/sent — отправленные значения, отсутствие live — unknown. TTL 6 с считается
  от начала чтения каждого блока; nonce/span/байты проверяются, неполный RGB
  не становится белым. RGB с Dimmer/без него и подтверждённый Dimmer-only
  поддержаны; CMY/колёса/смешанные эмиттеры/сложные Instances остаются unknown.
  Один несмещённый instance разрешён; bare LongName разрешается лишь точным
  уникальным совпадением с текущим List FixtureType.
- Отказы Lua/пустые ответы имеют отдельные паузы для каждого DMX-блока: здоровые
  вселенные продолжают опрос. Между блоками пауза не менее 100 мс; после ошибки повтор не ранее 30 с; после трёх
  отказов Lua блок ждёт сброса контекста/явного refresh. Reconnect будит опрос,
  не дожидаясь старого сна. Типы также имеют ограниченные повторные попытки.
- Shutter подтверждается только прочитанным байтом и явным 8-bit Open/Closed
  диапазоном в поддерживаемом XML. Closed даёт яркость 0; strobe, пересечение
  диапазонов и отсутствие классификации/байта дают unknown. DMX не доказывает
  физическую яркость или механическое положение. Actual Pan/Tilt не декодируется
  без подтверждённой физической шкалы профиля; относительный jog остаётся нативным
  MA2 и сохраняет индивидуальные исходные позиции. Расчёт панели — только sent.
- /api/diag → export.dmx_read: адреса/карты, блоки/паузы, последнее успешное
  чтение, TTL/цикл и ошибки. Отрисовка браузера отдельно не подтверждается.

- **Стробоскоп:** 0 = «выкл» → `Attribute "<attr>" At <open>`; 1–100 → линейно в `from..to`. Приборы разных типов получают строки по типам (как цвет `rgb`/`cmy`). Тип без диапазона строба стробоскоп не получает; если ни у одного выбранного нет — отказ с причиной. На пульте атрибута `Strobe` нет (`Error #14`).
- **Скрытие Zoom/Focus/строба:** в `dmx_map` пишется `has`. Слайдер не показывается, если у всех выбранных (при пустом выборе — у всех приборов плана) тип прочитан и атрибута нет. Тип не прочитан → слайдер виден и по-прежнему гаснет после `Error #14`. (было: 21, 24)

## Раздел «Патч» и RDM

- **Таблица приборов:** Fixture ID, имя, тип, адрес в патче, footprint профиля MA2 (колонка DMXFootprint из `List FixtureType`; экспорт приборов даёт меньше: у Mini-B 14 вместо 17; без него план правки не строится), занятый диапазон; пересечения отмечаются. Физический footprint — только если прочитан по RDM, иначе «не прочитан», не подменяется догадкой. Явный режим правки; без него раздел только показывает.
- **Актуальность профиля:** смена соединения/шоу/плана, импорт XML и принудительное чтение отменяют достоверность прежнего footprint и карт. Ошибка обновления не возвращает старые размеры в расчёт. Прежние карты, включая ручные, сохраняются в `dmx_map_saved`; автоматического применения сохранённых карт нет. Для multi-instance, нескольких модулей или неизвестного размера запись и полный DMX-readback не разрешаются без подтверждённых данных; структура offsets не угадывается.
- **Смена адреса:** `Assign Fixture <id> At Dmx <u>.<aaa>` (keyword Dmx снимает старый патч). Перед записью мост строит план правки (было → станет, диапазоны, конфликты) с меткой; запись принимается только с той же меткой. После записи — перечитывание экспортом и сверка адреса. Тайм-аут не повторяется. Только при `safety.allow_patch` и только строка, собранная мостом для подтверждённого плана.
- **Поиск RDM:** при `allow_rdm`, после отдельного подтверждения предупреждения о мигании френеля и работе вне выступления. Поиск идёт 18 секунд по уже разрешённым в MA2 вселенным; настройки вселенных не меняются. До записи мост читает глобальное состояние и настройки вселенных; неизвестный формат, первоначальный On, отсутствие разрешённых вселенных или занятость несовместимой операцией запрещают запуск. Включение глобального RDM — один раз, затем отдельное подтверждение On. `RdmList` читает накопленные данные примерно каждые 6 секунд; это не сигнал завершения discovery, не подтверждение online и не обещание найти все приборы по DMX. Нужна поддержка RDM прибором и всем обратным трактом.
- **Выключение RDM:** после окна, «Остановить поиск» или ошибки — одна попытка глобального Off в исходном действующем контексте, затем отдельное чтение Off. Результат сбора и подтверждение выключения показываются независимо. Обязательство проверить Off атомарно сохраняется до On отдельно от плана/settings; после reload/рестарта неподтверждённое выключение остаётся видимым всем клиентам. Закрытие браузера не прекращает фоновую операцию. Ошибка записи журнала до On запрещает включение.
- **Обрыв и остановка RDM:** нет автоматических повторов On/Off с неизвестным результатом; смена подключения, шоу или stop ticket запрещает поздние записи старой операции. «Остановить передачу» не обходится ради Off. После reconnect — только чтение состояния; «Проверить выключение» ничего не записывает. При неизвестном Off нет зелёного успеха: «Выключение RDM не подтверждено. RDM может оставаться включённым и вызывать мигание. На MA2: Setup → Console → Global Settings → RDM (Enable RDM) → Off. Затем восстановите связь и нажмите “Проверить выключение”». Гарантия выключения при обрыве или аварии моста невозможна. Предупреждение не снимается простым закрытием. Незавершённое обязательство блокирует новый поиск.
- **Изоляция RDM:** один поиск на мост; повторные запросы не запускают второй. Подтверждение привязано к состоянию/соединению/шоу/stop ticket и ограничено по времени. Патч, Identify, импорт, файлы шоу и перенастройка подключения не пересекаются с поиском; действия света не копятся за его lock. Halt доступен всегда. Найденные данные не меняют автоматически приборы, UID-связи, адреса, план, Programmer или содержимое шоу. Неизвестный формат показывается непроверенными строками, не «найдено 0».
- **Остальные операции RDM:** отдельное чтение `RdmList` показывает полученные данные без запуска поиска. Ручная запись: `RdmSetParameter dmx_start_address <a> / UID = <uid>`, `RdmSetParameter identify_device 1|0 / UID = <uid>`, только при `allow_rdm`, вне поиска; включение для них оператор выполняет вручную. `RdmAutopatch`/`RdmAutomatch` запрещены. Фиксированные команды глобального On/Off и чтения его состояния разрешаются последним фильтром только координатору поиска. Подробности согласованного решения: `docs/superpowers/specs/2026-11-03-rdm-discovery-proposal.md`.
- **Сопоставление:** оператор сам связывает UID с прибором; связь хранится в `rdm` прибора (`uid`, `footprint`), не заменяет Fixture ID.
- **Согласованная смена:** сначала физический адрес по RDM, затем патч, затем перечитывание обеих сторон. Атомарности нет — панель показывает, что изменилось, и готовую обратную команду.
- Смена DMX personality/профиля не делается. Все записи патча и RDM попадают в «Историю» (было → стало); откат — только предложенной обратной командой с новым подтверждением. (было: 21)

## Группы и пресеты MA2

Этап 2, 2026-11-10: полное чтение, явный пустой список, partial, error и stale
различаются в status.ma2_read. Ошибка не заменяет сохранённый каталог пустым.
Импорт атомарно требует состав всех выбранных групп; при обновлении сохраняет
пользовательские label. Перед Group n заново читаются список и состав, проверяются
IDs и контекст; требуется allow_fixture_read. Ошибка запрещает управление по
старому составу. Между чтением и Group другой оператор всё ещё может изменить
группу: атомарный снимок между Telnet-сессиями MA2 не предоставляет.

Группы MA2 (`ma2groups`) и пресеты (`ma2presets`) — только чтение, отдельно от групп панели. Выбор группы MA2 (`Group n`) — только если её состав прочитан. Запись группы панели в MA2 (`group_store_ma2`) — при `safety.allow_group_store`, с подтверждением номера и проверкой пустоты `List Group n` по `ma2.group_empty_regex` (шаблон, подходящий к занятой строке, отвергается настройками), без `/overwrite`. Форматы `List Group`, `List Preset` и пустого ответа — шаблоны в `settings.json`, проверить на площадке. (было: 16)

## История и откат

Раздел «История»: последние 100 изменений этого моста (время, что сделано), новые сверху; в памяти, перезапуск очищает. `undo {n}` откатывает одно изменение:
- свет (яркость, цвет, позиция, zoom, focus, strobe, пресет позиции): мост шлёт приборам прежние известные панели значения; движение одного слайдера в течение 3 с — одно изменение; неизвестное до изменения не откатывается;
- план (группы, пресеты, расстановка, зал, флаги, удаление сцены из панели и т.п.): изменённые ключи `config.json` возвращаются;
- действия на пульте (сцены, запись и имя сцены, страница, группа в MA2, загрузка шоу) видны, но панелью не откатываются.
Откат сам попадает в историю и тоже откатывается; каждое изменение откатывается один раз. (было: 20, 21)

                "moves": true, "params": {"pan": {"min": -270, "max": 270}},

- Настройки площадки `port`, `rate_hz`, `ma2`, `master` хранятся в `settings.json`; пароль только в `secret.env`. `attrs` плана сохраняются в config, настройки площадки могут их переопределять. `highlight`, `poll_seconds` — настройки площадки.
- При обычном запуске конфиги версий 1–4 (без версии — v3) проверяются и переходят сразу в v5: перед записью создаются резервные копии config/settings, у старых до v4 сохраняется исходный план (именованный в shows, безымянный — отдельным архивом в backups). Существующие настройки имеют приоритет на уровне вложенных ключей; отсутствующие переносятся из config. Сначала атомарно записывается settings, затем config; повтор после прерывания безопасен. v5 не переписывается; неподдерживаемая версия или неверные данные отклоняются до записи.
- Сохранённые планы в `shows/` имеют ограниченное ASCII-имя на основе полного SHA256 имени шоу. Читается только план с совпадающим полем `show`: актуальный файл имеет приоритет над legacy `shows/<очищенное имя>.json`. Старые файлы остаются нетронутыми; коллизия очищенных имён не смешивает шоу. Повреждённый актуальный файл не перезаписывается автоматически.
- Сцены и группы добавляются правкой файла или из панели; приборы — правкой или «Получить приборы»; позиции пишет сама панель. Файл пишется атомарно (временный + замена). Прибор без позиции — без `x`/`y`; пропавший — `"missing": true`.
- `settings.json` может содержать `attrs` (поверх config), `features` (`true`/`false`/строка-причина блокировки для dim, color, move, zoom, focus, strobe, scenes, store), `simple_port`, разрешения `safety`. Защита разрешает `Attribute "<имя>"` только для имён из сопоставления; `Goto Cue 1 Executor N Fade T` — только для `allowed_scenes` (и в `full`).
- Настройки на месте: `settings.html` и `/api/settings` (только с самого ПК); сохранение ничего не шлёт на пульт, копия в `backups/`, пароль только в `secret.env`. `/api/restart` перезапускает мост (код 3, `start.bat` запускает снова), отказ во время передачи.
- Мост хранит копию `config.json` за каждый день в `backups/`, 7 дней. (было: 7, 14, 15, 16, 24)

## Достоверность статусов (2026-11-02)

- Состояние сцены: «идёт», «остановлена» или «неизвестно». Первые два устанавливаются только по распознанному чтению MA2; успешный ответ на отправку не подтверждает состояние и не доказывает физический свет. Отсутствующая строка, ошибка и нераспознанный ответ не означают «остановлена».
- Один общий опрос сцен для всех клиентов: по умолчанию 2 с, без очереди пропущенных циклов, с приоритетом пользовательских действий. Точную нагрузку и формат Executor проверить в зале; пределы диапазонов шага 3 не угадывать. Явное `poll_seconds: 0` отключает опрос, но не разрешает показывать неподтверждённое состояние как известное.
- Через 6 с без успешного подтверждения статус устаревает: прежнее значение не используется как текущий факт. При потере связи, смене шоу и загрузке шоу статус сразу неизвестен. После восстановления связи выполняется чтение, автоматически команды не повторяются. Новый клиент получает тот же снимок состояния, что остальные.
- Значения параметров различают источник: «последнее отправленное панелью» (`shown`, не измерение выхода) и «прочитано с MA2» (`live`, чтение DMX, не оптическое измерение). Для источников отдельно учитывается свежесть; устаревшие данные не изображаются текущим выходом. При обрыве и смене шоу показанные значения инвалидируются; относительное управление не получает старую базу.
- В обоих интерфейсах успешная отправка обозначается как отправка команды, чтение — как проверка состояния, тайм-аут — как неизвестный результат без автоматического повтора. Потеря WebSocket не оставляет прежние статусы актуальными.

**Обратная связь операций (согласовано 2026-11-05):** компактная строка ожидания
различает передачу запроса браузером, локальную очередь и регистрацию запроса
мостом по `operations/request_id`. `running` в operations не подтверждает
отправку MA2. Терминальный `command_evidence` определяет нейтральный ответ MA2
без ошибки, отказ до отправки, ошибку и неизвестный/частичный итог. Пустое или
отсутствующее поле не даёт права утверждать отправку MA2. Зелёного успеха
операции по sent/completed/running нет; независимый свежий статус сцены остаётся
отдельным показанием. Ошибки красные, unknown/partial янтарные, сохраняются до
закрытия пользователем, включая reconnect и последующие обычные ответы.
Явная замена значения слайдера новым до отправки — нейтральная отмена без потока
ошибок. Отменённая локальная очередь отмечается как неотправленная.
Через 30 с ожидания ответа показывается задержка/неизвестность; для fade порог
не раньше длительности перехода +30 с, для show_load не раньше 150 с. Это только
индикация: запрос не удаляется, поздний ответ того же соединения сопоставляется,
команда не повторяется. При потере связи ожидание очищается с предупреждением;
reconnect не восстанавливает прежний успех и не пересылает команды.

- Исправление по запросу владельца 2026-11-08: карточки яркости и RGB используют свежий `live` с источником MA2 раньше истории отправленных команд и сохраняют прочитанные значения после сцены. Источник явно подписан; значения разных источников внутри выбора не смешиваются. При неизвестном/устаревшем `live` прежняя история остаётся отдельно подписанной. Подсветка значков плана пропорциональна прочитанному диммеру без минимума 25%; ноль не светится, устаревший/неизвестный выход не подсвечивается. Это отображение DMX, не измерение физического света; команды и опрос не меняются.

## Диагностика

- `diag.html`, `/api/diag` (состояние, ответ на вход, сырые ответы, ошибки с подсказками), `/api/probe` (читающие команды через живую связь), `/api/diag.zip` (логи, настройки, конфиг, сырые ответы, журнал; без пароля и `secret.env`).
- `uv run bridge.py --probe` пишет сырые ответы читающих команд в `probe.txt`. (было: 13, 14)
- На «Площадке» есть кнопка-ссылка «Отправить диагностику» к форме `diag.html#report`. С самого ПК моста через localhost кнопка сохраняет один неизменяемый снимок в атомарный локальный журнал (`/api/diag/queue`), даже без интернета или настроенного доступа. Необязательное описание — до 1000 символов, рядом явно указано, что оно отправляется вместе с отчётом; известные приватные значения скрываются. Снимок содержит UTC-время сбора. UUID сохраняется в браузере до запроса и на мосту до отправки. Пока отчёт не завершён, новый снимок не создаётся и описание не меняется.
- Мост без открытого браузера доставляет сохранённый отчёт фиксированному HTTPS-приёмнику `https://diag.shmyrev52.ru`: сразу по кнопке, при запуске и затем каждые 60 секунд. Приёмник сохраняет собственную постоянную очередь и создаёт Issue в закрытом `coldmoth/ma2-panel-diagnostics`. На пользовательском ПК не нужны аккаунт GitHub, токен или настройка доступа. Ограниченный GitHub-токен однократно настраивает владелец на сервере. Отдельного определения «интернет появился» нет: проверяется доступность приёмника. Программа моста должна работать до подтверждения доставки; принятый сервером отчёт обрабатывается независимо от ПК. Сеть выполняется вне event loop и action_lock; сбор не запускает команды MA2/RDM/света. Старые записи журнала автоматически не отправляются без явного включения очереди кнопкой. Старый `/api/diag/send` сохранён для совместимости.
- Автоматические поля отчёта строятся по разрешённому списку: версии, состояния, количества и обезличенная структура уже полученных ответов; исходные настройки, логи, XML, имена шоу/пользователей, пути, адреса и секреты в них не передаются. Произвольный текст описания вводит пользователь. Отсутствующие данные и имитация явно обозначены. Получатель/HTTPS-хост фиксированы, перенаправлений нет; перед отправкой в GitHub сервер проверяет приватность репозитория. Приёмник ограничивает формат, размер, частоту, число сохранённых отчётов и скорость создания Issues; публичный статус не раскрывает тело отчёта. Сохраняются проверки localhost, Origin/Host и специального заголовка.
- По запросу владельца 2026-11-08 отчёт дополнен `readback`: разрешение и интервал DMX-опроса, категория прав Admin/другие/неизвестно, время и результат последнего опроса, число порций/байтов, задержки, коды ошибок, числовые ответы PANELST/PANELV и до 16 строк PANELDMX по 32 значения. До 64 приборов и 32 типов представлены порядковыми номерами только внутри отчёта: валидность патча, footprint, относительные каналы dim/RGB, stale/unsupported, результат экспорта. При ограничении списка есть признак усечения. Имена, реальные Fixture/FixtureType ID, абсолютные DMX-адреса, маркеры запросов, Lua-код, пути и секреты не передаются. Неожиданные строки не копируются; значения из отчёта не объявляются свежим выходом. Приёмник строго проверяет новый необязательный раздел и принимает старые отчёты. Сбор пассивен, команды MA2 не добавляются, старые сохранённые снимки не изменяются. Для версий и числовых свидетельств используются строгие грамматики: короткий пароль не уничтожает совпадающие цифры; произвольные ответы по-прежнему полностью обезличиваются.
- При недоступной сети отчёт остаётся в очереди. Принятие сервером отдельно от подтверждённого создания Issue: UI показывает «принят сервером» до получения номера. Повтор одного UUID с тем же содержимым возвращает квитанцию; другое содержимое отклоняется. Потеря ответа приёмника допускает повтор идемпотентного PUT. После отказа GitHub снимок сохраняется на сервере; исправление доступа выполняет владелец сервера. При неоднозначном POST в GitHub автоматические попытки делают только GET и ищут Issue по UUID, не создают вторую; правило сохраняется после перезапуска. Отсутствие Issue в поиске само по себе не разрешает повторный POST. Старые незавершённые прямые отправки не пересоздаются через приёмник: неоднозначные остаются на прямом поиске с прежним доступом, остальные перед созданием сверяются по UUID. UI каждые 5 секунд обновляет состояние. Закрытие браузера не прерывает доставку.
- Автоматическое удаление отчётов не включено: закрытые Issues и локальный журнал хранятся до ручного удаления. Удаление журнала лишает сохранённых идентификаторов повторов. Результат отправки не является приёмкой MA2 или подтверждением физического света.


## Безопасность (safety)

Разрешения в `settings.json`, только bool, по умолчанию `false`, обязательны даже в `full`, доступны в настройках: `allow_fixture_read`, `allow_highlight`, `allow_show_load`, `allow_show_save`, `allow_group_store`, `allow_patch`, `allow_rdm`. Без `allow_fixture_read`: `ListVar` и `ListShows` — READ; экспорт — только точное совпадение с `ma2.export_cmd`. Каждая строка проходит `make_guard`. Журналируются новые действия; нет повторной отправки, нет `/Overwrite`, прежние ограничения приборов/сцен сохраняются. (было: 14, 15, 16, 21)

## Запуск на Windows и обновления

1. Один раз скопировать папку комплекта (собирается `scripts/build_win.sh`, Python внутри, `uv` не нужен); сборка берёт все `*.py` из корня проекта.
2. `start.bat` запускает `python\python.exe bridge.py` и перезапускает мост после смены настроек (код 3). Ярлык — в автозагрузку.
3. В Windows Firewall открыть порты 8080 и 8090, только частная сеть.
4. Закрепить IP Windows в DHCP роутера.

Дома: `uv run bridge.py --mock`, открыть `http://localhost:8080`.

### Обновления (согласовано 2026-11-02, блок Б)

Полный Windows-комплект и обновление собираются с единой версией, зависимостями
из lockfile и общим набором программных файлов/документации. При каждом новом релизе
Windows x64 workflow проверяет и публикует полный ma2-panel-win.zip, обновление
ma2-panel-update.zip и внешний ma2-panel-update-usb.zip, с SHA256 каждого архива,
из одного коммита. Публикация выполняется только после проверки полного draft;
существующие релизы не заменяются. README ведёт на актуальный полный ZIP.
Для старого встроенного updater v3.2.0–v3.2.4 переход на ma2panel/ выполняется
внешним USB-updater без ослабления проверок, с сохранением данных и откатом.
Версия приложения хранится отдельно от совместимой версии runtime/lockfile. Обновление содержит
манифест файлов и требований Python/lib; несовместимое обновление не устанавливается.
На странице настроек основного ПК доступны текущая/доступная версии, проверка
GitHub-релиза и явная кнопка обновления. USB и локальная сеть сохраняются.
Загрузка и проверка выполняются при работающем мосте. Перед остановкой мост
повторно проверяет занятость и атомарно закрывает приём новых действий.
Внешний updater заменяет программу, запускает мост и проверяет нужную версию
и доступность обоих включённых интерфейсов. Ошибка запуска вызывает точный откат
программы, включая удаление добавленных файлов, и попытку запуска прежней версии.
Пользовательские конфиги, настройки, пароли, шоу и диагностика не заменяются
программным архивом и не восстанавливаются поверх текущих данных при откате.
Последняя исправная программа и копия данных перед обновлением сохраняются;
автоматическая очистка старых копий пока не включена. Ошибка восстановления
показывается явно; успех не объявляется по одному факту запуска процесса.
Браузер показывает стадии и восстанавливает соединение без повтора старых действий.
Управление обновлением разрешено только с основного ПК с защитой межсайтовых запросов.
Firewall формируется по сохранённым портам; его изменение требует штатных прав Windows.

## Планшетный UI (2026-10-30)

Согласованный дизайн: [tablet-ui-design](superpowers/specs/2026-10-30-tablet-ui-design.md).
Графитовые поверхности, радиусы 6–10 px, основные касания ≥48 px, вторичные ≥44 px.
Короткий текст связи виден на всех ширинах; подробности по запросу. Цвет — состояние,
не единственный признак. В редакторе зала настройки прибора свёрнуты отдельно.

Движение: одинаковые переключатели «Точно»/«Зеркально»; инверсии — в свёрнутых
настройках, смешанные значения явно отмечены. Четыре стрелки передают nudge с step=1
(градус); явный step конечный, числовой, 0 < step ≤10, bool запрещён. Без step прежний
протокол сохраняет attrs.step/default 2. Ручного абсолютного Pan/Tilt в UI нет.
Пресеты панели свёрнуты; явное управление удалением с подтверждением, без скрытого
долгого удержания. MA2-пресеты остаются только для вызова. При уходе/потере связи
джойстик останавливается, фоновые jog не продолжаются.

Сообщение значений дополнительно содержит master: number|null — последнее успешно
отправленное значение панели, не измерение MA2. Оно сохраняется при перерисовке и
инвалидируется при смене шоу/поколения связи. Статус read_freshness содержит fixtures/ma2/scenes:
свежесть успешного чтения текущего подключения и шоу, отдельно от сохранённых данных.
Результаты info/success/warning/error различимы; ошибки не исчезают с кнопкой/диалогом,
подпись кнопки не заменяется сообщением.

Новая сцена: scene_slot_find {request} начинает отменяемый поиск; приватное событие
scene_slot {request,state,checked,total,exec?,token?,err?}, state — searching/ready/cancelled/error.
scene_slot_cancel {request} отменяет без прерывания текущего Telnet-ответа. В full
кандидаты 1.1–1.250, в store — только store_execs; занятые в плане исключаются.
Нет перехода на другие страницы при исчерпании. Пустота подтверждается распознанным
ответом конкретного List Executor, не отсутствием строки. Не более 250 проверок/30 с
до начала следующей проверки; token действует 60 с и связан с сокетом/шоу/планом/связью.
scene_create с token всё ещё передаёт exec/confirm/page; перед записью token и пустота
проверяются заново под action_lock. Устаревшая/занятая/неясная цель — отказ без выбора
другого адреса и без повтора. Поиск не удерживает action_lock между проверками.
Простой порт не принимает служебные действия поиска/редактирования.

Снимки значений содержат монотонный `values_revision` в пределах процесса моста.
Панель игнорирует запоздавшие старые снимки; при новом WebSocket начинает отсчёт заново.
Сцена с `write_error` не запускается ни с основного, ни с простого порта до исправления
записи; выключение по-прежнему доступно. Мастер синхронизирует ползунок после завершения
активного жеста, обычный фокус этому не мешает.

## Переносимый запуск и первичная подготовка (согласовано 2026-11-03)

Первый патч: полный Windows-комплект имеет снаружи один `start.bat` и папку
`program` со всей программой, runtime и рабочими данными. Внутренний корень и формат
update-пакета сохраняются. Пользователь сам запускает grandMA2, затем батник панели;
локальный мастер открывается после готовности HTTP. Мастер объясняет создание
отдельного пользователя и профиля MA2 и включение Telnet вручную; существующее шоу
не заменяется. Он сохраняет параметры подключения и явное включение доступа LAN,
не теряя остальные настройки. Пустой пароль сохраняет действующий.
После перезапуска показываются действующее состояние входа, актуальные локальные IPv4
адреса и QR полного интерфейса, созданные без интернета. Сохранённые и действующие
параметры различаются; доступ по localhost не объявляется доступом с планшета.
Настройка выполняется только на основном ПК, просмотр не отправляет команды MA2.
Брандмауэр настраивается внутренним `firewall-open.bat` с правами Windows.

Файлы шоу (загрузка/скачивание и резервное сохранение), подготовка пустого шоу,
поиск с временным RDM и подробные отчёты уже реализованы в локальном объёме.
Действующие правила приведены в разделах «Шоу», «Раздел «Патч» и RDM» и диагностики
этой спецификации. Это не закрывает физическую приёмку SaveShow/LoadShow и RDM Off
на MA2, Windows x64 и реальных планшетов. Неизвестное состояние RDM сохраняется
в журнале и требует операторской проверки; доставка отчётов подтверждается отдельно.

## Локальная подготовка 3.1 (согласовано 2026-11-03)

Запросы панели имеют идентификатор, ответы относятся к конкретному запросу. Обрыв и восстановление связи не повторяют команды автоматически. Итог операции различает `completed`, `partial`, `failed`, `unknown`; принятие команды не подтверждает физический результат света. Если предыдущая стадия неизвестна или завершилась ошибкой, последующие стадии не запускаются автоматически.

Общий план имеет версию; устаревшее сохранение отклоняется с предупреждением без перезаписи более новых изменений другого клиента.

В разделе движения доступен выбор джойстика либо двух горизонтальных абсолютных регуляторов Pan и Tilt. Неизвестные и разные значения обозначаются явно, отображение не отправляет команд. Существующие зеркальность и инверсии сохраняются.

Периодическое чтение DMX обходит только нужные интервалы, ограничивает объём одного цикла и уступает ручным действиям между порциями; ответы предыдущего шоу не обновляют текущий план. Физическая задержка требует приёмки MA2.

### Детали протокола 3.1

Современный клиент передаёт `request_id` — непустую строку до 100 символов; итог возвращает тот же ID и `a`. ID уникален в пределах WebSocket, повтор отклоняется до исполнения. После 20 000 ID сокет закрывается вместо забывания идентификаторов. Клиенты старого протокола без ID сохраняют форму ответов `ok/a/err`; это не отменяет проверки устаревших правок.

`completed` означает завершение известных стадий моста; `failed` — отказ без подтверждённых выполненных стадий; `partial` — известное частичное выполнение с последующей ошибкой; `unknown` — неоднозначный исход хотя бы одной стадии. Принятие значения throttle не является итогом исполнения. Итог современного запроса fade/crossfade ждёт соответствующих стадий; это не подтверждение физического завершения перехода MA2.

Полный `config` содержит непрозрачную `revision`, включающую идентичность процесса. Запрос изменения плана передаёт `config_revision`, сохранённую при начале редактирования; проверка выполняется под общей блокировкой до изменения. Конфликт возвращает `conflict:true` и текущую версию. Старый draft не получает новую версию автоматически по чужой рассылке. Параллельные собственные сохранения интерфейс упорядочивает; при конфликте пользователь обновляет данные и повторно проверяет правку.

`status.operations` сообщает о выполняющихся действиях других клиентов без их секретов. Общий баннер «Выполняются операции» в UI не показывается: цвет, движение и остальные действия не добавляют строку над управлением. Специальные предупреждения связи, загрузки шоу, подсветки и ошибок сохраняются. Обрыв сокета/пульта отменяет ожидающие значения и жесты; восстановление не повторяет операции.

Абсолютные Pan/Tilt задаются в градусах настроенного диапазона независимо друг от друга. Неизвестное/разное значение не заменяется автоматически нулём. «Точно», зеркальность и инверсии сохраняют прежний смысл для относительного джойстика/шагов; абсолютные координаты их не применяют, это подписано в интерфейсе.

DMX опрашивается порциями до 32 адресов, без пустых промежутков между приборами. Согласовано 2026-11-08: пауза `dmx_seconds` распределяется на весь круг (`dmx_seconds / число порций` после успешной порции), а не повторяется после каждой порции; TTL остаётся 6 с. Медленный пульт или большое число порций всё ещё могут дать неизвестные значения вместо устаревших. Диагностика `dmx_read` содержит число порций, паузу, длительность чтения и последнего полного круга, максимальный возраст сохраняемых адресов на момент ответа. Порции обходятся по кругу; ожидание Lua не удерживает блокировку ручных действий. Первичное обнаружение каналов ограничено одним типом за цикл и может дополнительно ждать экспорта; реальная задержка требует измерения. Значения из других сохранённых переменных ListVar не подменяют текущую порцию; адреса теряют свежесть через 6 секунд от начала запроса Lua независимо от остальных порций; задержанный ответ не начинает TTL заново.

После отказа MA2 на Lua следующая попытка допускается не раньше чем через 30 с. Три последовательных отказа приостанавливают отправку DMX-запросов до смены соединения/шоу или ручного «Получить приборы»; задача опроса продолжает работать и проверяет новый контекст. Достоверный ответ сбрасывает счётчик отказов. Команды управления светом автоматически не повторяются.


## Управление сценами: контракт Фазы 3 (согласовано 2026-11-03)

Этот раздел задаёт будущую реализацию. Действующие `scene_go`, `scene_off`, клиентский
Актуальное поведение сцен и Grand описано в этапе 1 от 2026-11-10 выше. При реализации Фазы 3
обновить соответствующие строки протокола, раздел «Сцены и страницы» и оба интерфейса.
Ссылки аудита «§337–340» были номерами строк старого снимка, не номерами разделов.

- Браузер передаёт намерение выбора сцены и её id, а не строки MA2 или доверенный
  перечень выключаемых источников. Мост обеспечивает одну политику на обоих портах.
- Порядок действий задаёт принятие мостом под общей блокировкой, не часы браузеров.
  Мост определяет toggle по свежему чтению MA2 в текущем шоу/соединении. При unknown
  или устаревшем статусе выполняет чтение; если результат опять неизвестен — отказ
  без изменяющих свет команд. Подтверждённо активная сцена при повторном выборе выключается.
- Новый выбор всегда начинает Cue 1, с fade и без него, и выключает остальные сцены
  текущего шоу, включая запущенные оператором Executor вне плана и на других страницах.
  Определения Cue/Sequence не удаляются и не перезаписываются. Клиентский `swap` не
  ограничивает охват и не расширяет права. До первой изменяющей команды должны быть
  подтверждены полный охват и достаточные разрешения safety; иначе отказ, без частичной замены.
- Последнее принятое действие отменяет несовместимые старые завершения переходов.
  Проверка актуальности и отправка защищены `action_lock`, привязаны к шоу и поколению
  соединения; A→B→A, другой клиент и гашение не позволяют старому таймеру погасить новый выбор.
- Ошибка либо неизвестный результат останавливает следующие стадии. Уже отправленное
  не считается отменённым; результат виден как частичный/неизвестный. Команды автоматически
  не повторяются, после reconnect выполняется только чтение. Принятая команда не доказывает свет.
- После общего гашения следующий выбор должен вернуть только выбранную сцену. Точные
  строки MA2, полный способ перечисления/выключения внешних Executor, изоляция Programmer
  и владение Blackout остаются зависимостями зала (§12b–12e hall-test-plan). Чтение не может
  устранить гонку с физическим оператором; абсолютная атомарность MA2 не обещается. Пока
  зависимости не подтверждены, нельзя объявлять такую замену или возврат реализованными.

Критерии будущей проверки: unknown/устаревший статус, Cue 1 с/без fade, внешний Executor,
недостаток прав до отправки, A→B→A и пять клиентов, обрыв на каждой стадии, смена шоу,
возврат после гашения. Реальные List-ответы нужны до изменения парсеров.

### Отказ импорта Executor (2026-11-04)

Ошибка или неизвестный результат `List Page` отменяет весь импорт Executor без частичного сохранения плана. Сохранённые сцены не удаляются; чтение не объявляется полным или свежим. Ответ содержит причину отказа и предложение повторить импорт вручную.

### Возраст отправленных атрибутов (2026-11-04)

По согласованию владельца (REL-003) источник `panel` и возраст отправленных значений
учитываются отдельно для каждой пары прибор/атрибут (`rgb` — единый атрибут).
В `values_meta` ключи `sent:<id>:<attr>` содержат source/freshness/updated_at;
`shown` остаётся сводным признаком наличия свежих отправленных значений.
Через 6 с значение исключается из `shown` и базы вычислений. Посторонняя команда,
другой атрибут и Master не продлевают его свежесть. Это свидетельство отправки,
а не чтение Programmer или физического выхода.

Устаревшее значение не служит началом программного fade, базой move/jog/nudge,
сохраняемого пресета позиции, снимка Highlight или Undo. При неизвестной базе
сохраняются существующие отказы/относительные команды и штатный Fade пульта;
промежуточные абсолютные значения не выдумываются. Undo проверяет возраст прежних
значений, а не только нового задания; устаревшая запись видна с причиной отказа.
Master имеет отдельные метаданные `master`: процент подписан «отправлено панелью»
и после TTL помечается устаревшим; чтение Master этим не реализуется.

## Концертный интерфейс, этап 3/4 (согласовано 2026-11-10)

Сохраняются входы «Сцены / Свет / Подготовка / Помощь». На экране сцен рядом с
кнопками постоянно доступен рабочий план и параметры выбранных приборов; в «Свете»
план также открыт. На портретном планшете список сцен ограничен по высоте и

в редакторе подготовки. Выбор через группы, список и план использует одну цель.

Одна локальная настройка «Переход» (0–30 с) применяется к ручному запуску сцен,
быстрым кнопкам яркости и образцам цвета в обоих разделах. Перетаскивание остаётся
немедленным. Это параметр очередного действия, не изменение сохранённого Cue,
собственного Off Time, настроек MA2 или состояния другой вкладки. Автозапуска нет.

«Сохранить сцену» доступно непосредственно во время работы: имя, существующий
поиск свободного места, подтверждение записи. Slot/token и защита от занятого места
сохраняются. Адрес Executor вынесен в раскрываемые технические данные; перезапись
требует отдельного подтверждения. Ошибка/partial/unknown не закрывают диалог и не
теряют имя; результат виден внутри диалога и в общих сообщениях.

Доступность параметров определяется явными атрибутами/настройками прибора или
подтверждённой картой типа. Неизвестные возможности не изображаются доступными.
RGB/Dimmer карты учитываются отдельно от `has` вспомогательных параметров.
HSV Value называется «Яркость цвета». Источник текущего цвета виден без раскрытия
точного смешения; показания MA2 отделены от истории отправки панели.

Чтение сцен и DMX обновляет отдельные элементы. Структурное обновление во время
ввода/жеста откладывается до завершения взаимодействия; показания и доступность
управления продолжают обновляться. Blur применяет отложенное обновление без нового
WS-пакета. Черновик формы зала сохраняется при конфликте, с явной возможностью
отбросить его и принять новые данные; старая revision не заменяется незаметно.
Поздний отказ старого выбора не очищает новую цель. Смена цели, Blackout, обрыв,
уход со страницы и скрытие вкладки отменяют старые жесты/очереди; продолжение
прерванного жеста не становится новой командой после восстановления.

Семантика `scene_go`, `scene_off`, StoreLook, Programmer/Highlight и Blackout
остаётся прежней. Будущий контракт Фазы 3 управления сценами этим этапом не
реализуется. Проверки mock/браузера не заменяют приёмку MA2 (§12–13 плана зала).


## Исправления независимого review этапа 4 (запрос владельца 2026-11-10)

- Актуальная основа — публичные main/v3.2.5 d95220f, пакет `ma2panel/`.
  Корневой recovery launcher, resources, миграции v5, упаковка и updater сохраняются.
  Компоновка этапа 3 (сцены/постоянный план/окно выбора, четыре главных входа)
  заменяет прежнюю компоновку; инструменты подготовки, персональная видимость,
  выбор Group на MA2, оптика неподвижных приборов и обзор сцен остаются доступны.
- Recovery проверяется сервером после ожидания action_lock и перед каждой строкой.
  Начало восстановления отменяет старые transport waiters/tickets. Существующий
  `blackout_epoch` служит токеном управления также после восстановления связи:
  запоздалое сообщение со старым токеном отклоняется и после завершения recovery.
  Старый клиент без токена после смены контекста не получает обход блокировки;
  нужны обновлённый клиент и новое действие. Чтение Patch/имени шоу и явное
  подтверждение сопоставления доступны при recovery, команды света запрещены.
- Один Fixture ID не доказывает идентичность. Смена имени/типа или неполные
  старые метаданные требуют выбора: сохранить кандидата либо оставить новым.
  Уникальное совпадение непустых имени и типа допускает перенумерацию. Полностью
  одинаковые имя/тип/ID не доказывают серийную идентичность оборудования: это
  граница данных XML, а не обнаружение физической замены.
  Новый прибор не наследует координаты/label/калибровку/RDM. Ссылки групп,
  позиционных пресетов и выделения удаляются; при перенумерации переносятся.
  Native-сцены сохраняют Executor, содержимое Cue мост автоматически не меняет.
  Успешный импорт меняет plan_epoch: старые intents, offers и Undo недействительны.
- Перед ручным Off мост каждый раз устанавливает Masterfade из общего Fade;
  Goto использует то же время. Изменение регулятора само не отправляет команд MA2.
  Cue times не переписываются; уже принятый MA2 fade может завершаться самостоятельно.
  Непроверенные `Off ... Fade`/Assign OffTime не добавляются.
- Свежие measured RGB=(0,0,0) не подсвечивают план при Dimmer>0. Само прочитанное
  значение Dimmer не подменяется расчётом. Подтверждённый dimmer-only остаётся
  белым; неполные RGB, stale/unknown и last-sent не доказывают свечение.
  Это отображение DMX, физическая яркость/приоритеты требуют проверки в зале.

## Финальные исправления v3.3.0 (запрос владельца 2026-11-11)

- При переносе 23→31 с повторным использованием 23 прежний прибор остаётся
  кандидатом для 31. Сначала резервируются неизменные ID/имя/тип, затем решается
  всё сопоставление, включая конкурирующие источники и перестановки. При конфликте
  выбор явный для всех затронутых записей; один старый прибор нельзя использовать
  дважды. Координаты/метки/настройки и ссылки переносятся одновременно. Другие
  сохранённые планы имеют собственный Patch и не переписываются импортом текущего.
- MA2-группа сохраняет action ticket клиента через ожидание lock, чтение состава,
  сохранение результата и последнюю команду. Blackout, reconnect, смена шоу/плана
  или отключение клиента отменяют старую операцию, включая извлечённую из очереди.
- Переход снимает только адреса, для которых панель пыталась отправить Goto в
  текущем плане/шоу. Неизвестный результат Goto сохраняет возможное владение;
  успешный Off снимает его. Свежий Off-readback исключает лишнюю команду,
  устаревшее/неизвестное чтение не отбрасывает возможный запуск. Внешняя активность
  и клиентский swap не расширяют область. Проверяются только затронутые адреса.
  После перезапуска/смены контекста старые playback не угадываются: оператор
  проверяет свет в MA2 перед первым запуском. Нативный fade продолжает MA2.

Сверка 2026-11-11: runtime-ID вычисляется по uv.lock с каноническим CRLF,
сохраняя ID опубликованной Windows v3.2.5 независимо от Git checkout на хосте.
Зависимости и lockfile не меняются. Приёмка обновления проверяет runtime guard
старого updater, установку нового пакета и откат с сохранением данных.
