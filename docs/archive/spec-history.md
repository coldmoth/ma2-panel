## 1. Цель и пользователи

Веб-панель для света в зале музыкальной школы. Заменяет Web Remote grandMA2 и работает только в локальной сети.

- **Учителя и персонал** (не знают MA2): включают записанные сцены, гасят свет, меняют общую яркость.
- **Администратор** (владелец проекта): управляет группами и приборами, меняет яркость и цвет, записывает сцены.

Устройства: Android-планшет, iPad, MacBook, телефон. Браузеры: Safari и Chrome. Управление касанием и мышью.

Срока нет. Разработка идёт дома в режиме имитации, потом один выезд в зал для проверки Telnet.

## 2. Архитектура

```
[браузер] --WebSocket--> [мост, Windows с MA2] --Telnet localhost:30000--> [grandMA2 onPC 3.9]
```

- Мост работает на той же Windows, что и MA2, и подключается по `localhost`. Поэтому смена IP `.215` на связь моста с пультом не влияет.
- Планшеты открывают `http://<IP Windows>:8080`. Напрямую к MA2 они не подключаются.
- Сцены и группы хранятся в шоу MA2. Панель только отправляет команды.

### Файлы

| Файл | Что делает |
|---|---|
| `bridge.py` | `create_app`: состояние панели, разбор действий WebSocket (`handle`), выбор/свет/сцены/шоу/подсветка/экспорт приборов, `main` и запуск |
| `api.py` | HTTP-маршруты `/api/*`: настройки, диагностика, `diag.zip`, `probe`, импорт XML файлом, stop/restart |
| `link.py` | `MA2Link` (одно Telnet-соединение, вход, строка за строкой), `Throttle` (последнее значение слайдера), разбор приглашения |
| `commands.py` | Чистые функции: действие → список строк MA2, разбор ответов `List ...`. Без сети |
| `fixtures.py` | Разбор XML-экспорта MA2, слияние приборов, угадывание голов по типу, атомарная запись `config.json` |
| `safety.py` | `settings.json` + `secret.env`, режимы защиты, `make_guard` (последний фильтр строк), проверка настроек, маскировка пароля |
| `mock.py` | Поддельный MA2 для `--mock` (с `MA2_MOCK_REAL=1` отвечает в формате живого пульта) |
| `update.py`, `selfcheck.py` | Обновление с USB и самопроверка на площадке |
| `static/*` | Панель без фреймворков и без сборки: `index.html`, `app.js` (разделы, связь), `light.js`, `plan.js` (зал), `move.js` (пад), `settings.*`, `diag.*`, `log.html` |
| `config.json`, `settings.json`, `secret.env` | План шоу (приборы, группы, сцены, зал); настройки площадки; пароль MA2 |
| `docs/CODEMAP.md` | Карта кода для разработчика: где что лежит (индекс функций собирается `scripts/codemap.py`) |

Стек: Python 3.12, FastAPI + uvicorn (WebSocket и статика), `asyncio.open_connection` для Telnet. Установка через `uv`.

## 3. Режимы панели

**Простой режим** открывается по умолчанию:
- кнопки сцен из `config.json` (Go и Off);
- кнопка «Погасить всё» с подтверждением;
- мастер-слайдер общей яркости.

**Полный режим** — все остальные вкладки, без PIN (с 2026-10-17: доступ ограничен только паролем Wi-Fi зала):
- плитки групп potolok, front, pushki, fon, back;
- схема зала с приборами (раздел 3.1), на ней выбираются отдельные приборы, включая 1-3 и 17-22;
- слайдер яркости выбранного;
- выбор цвета через HSV-круг на canvas и шаблоны цветов;
- «Записать в сцену» с подтверждением;
- «Снять выбор» (`Clear`).

Панель в локальной сети; пароль Wi-Fi знают двое. Отдельной защиты на мосту нет.

### 3.1 Схема зала

- **Фон:** с v4 схема рисуется по форме зала `config.hall` (раздел 16); `plan.image` и `static/plan.svg` больше не используются.
- **Приборы:** иконки в точках `x`, `y` (доли 0-1 от размеров картинки, поэтому не зависят от экрана). Нажатие выбирает прибор, повторное нажатие снимает выбор. Можно выбрать несколько.
- **Что показывает:** цвет и яркость, которые панель отправила этому прибору последними. Это не обратная связь от пульта. После «Погасить всё» показанные значения сбрасываются. После вызова сцены на схеме написано «значения не отслеживаются», пока панель не отправит новые.
- **Выбор группы** подсвечивает её приборы на схеме. Состав групп хранится в `config.json`.
- **Режим «Редактировать схему»:** иконки перетаскиваются пальцем или мышью. Приборы без позиции лежат в лотке «Не расставлены». Кнопка «Сохранить» записывает позиции в `config.json`.
- **«Обновить из пульта»:** мост экспортирует приборы MA2 в XML и обновляет список. Новые приборы попадают в лоток. Прибор, которого больше нет в шоу, остаётся на схеме серым с пометкой «нет в шоу». Подписи и позиции, заданные вручную, не перезаписываются.
- Лучи голов по Pan — раздел 12. Неподвижные приборы показываются точками без направления.

## 4. Протокол панель ↔ мост

Панель отправляет только действия. Строки MA2 собирает мост. Произвольную строку отправить нельзя.

| Действие | Режим | Строки MA2 |
|---|---|---|
| `scene_go {id, fade?, swap?}` | простой | `ClearAll`, затем `Go Executor <exec>` (раздел 20); с `fade` 0–30 с: `Goto Cue 1 Executor <exec> Fade <с>` (см. раздел 17) |
| `scene_off {id}` | простой | `Off Executor <exec>` |
| `blackout` | простой | `Off Executor <exec>` для каждой сцены из конфига, затем `Fixture <все приборы плана, кроме служебных и пропавших>` + `At 0` (раздел 19) |
| `master {v 0-100}` | простой | команда мастера из конфига (см. открытые вопросы) |
| `select_group {id}` | полный | `Group <n>` |
| `select_fixtures {ids}` | полный | `Fixture a + b + c` |
| `dim {v 0-100}` | полный | `At <v>` |
| `color {r,g,b 0-100}` | полный | `Attribute "ColorRGB1" At r`, `…RGB2…`, `…RGB3…` — три отдельные команды |
| `clear` | полный | `Clear` |
| `store_scene {id}` | полный | `StoreLook Executor <exec> Cue 1 /Source=Output /Overwrite`, `Label Executor <exec> "<имя>"`, `SaveShow` |

Действия схемы (только полный режим, в MA2 не отправляются, кроме экспорта):

| Действие | Что делает мост |
|---|---|
| `layout_save {pos: [{id, x, y}]}` | Проверяет id и числа 0-1 и сохраняет в `config.json` |
| `import_fixtures` | Отправляет `ma2.export_cmd`, читает XML из `ma2.export_dir`, сливает с `config.json`, сохраняет |

Мост → панель: `{"ok": true}` / `{"ok": false, "err": "..."}` на каждое действие и рассылка:
- `status`: `ma2: connected | down | login_failed`, `mock: true|false`;
- `config` (без `ma2`) при подключении и после каждого сохранения конфига;
- `shown`: последние отправленные значения по приборам `{id: {dim, rgb}}` после каждой отправки в MA2.

Мост помнит текущий выбор (группа → её приборы, или список приборов), поэтому знает, к каким приборам относятся `dim` и `color`. `clear` сбрасывает выбор, `blackout` сбрасывает `shown`.

`ClearAll`, патч и `/noconfirm` в протоколе отсутствуют.

## 5. Частота команд

- Панель отправляет значения слайдеров не чаще 10 раз в секунду.
- Мост хранит последнее значение на каждый слайдер и отправляет его не чаще `rate_hz` из конфига. Начальное значение `rate_hz` 5, подбирается в зале.
- Кнопки (сцены, выбор, запись) в ограничение не попадают и выполняются строго по порядку.

## 6. Ошибки

- Нет WebSocket: красная полоса «Нет связи с мостом», кнопки неактивны, переподключение каждые 2 секунды. Нажатия без связи никуда не копятся.
- Нет связи с MA2: полоса «Нет связи с пультом», кнопки неактивны, мост переподключается каждые 3 секунды. Команды из очереди при обрыве выбрасываются.
- Ошибка входа в MA2: отдельное сообщение, мост повторяет вход каждые 30 секунд, перезапуск не нужен.
- Ответ MA2 с `Error` или `Illegal` считается ошибкой и показывается на кнопке. Разбор ответа сделан одной функцией, её поправим после проверки в зале.
- Все команды и ответы пишутся в `bridge.log` с ротацией по размеру.

## 7. config.json (пример формы)

```json
{
  "port": 8080,
  "ma2": {"host": "127.0.0.1", "port": 30000, "user": "panel", "password": "",
          "export_cmd": "Export Fixture 1 Thru 9999 \"panel_fixtures\" /o",
          "export_dir": "C:/ProgramData/MA Lighting Technologies/grandma/gma2_V_3.9.60/importexport"},
  "rate_hz": 5,
  "master": {"cmd": "Master 2.1 At {v}"},
  "plan": {"image": "plan.svg"},
  "groups": [{"id": "potolok", "n": 101, "label": "Потолок", "fixtures": [4, 5, 6, 7, 8, 9, 23, 24]}],
  "fixtures": [{"id": 12, "label": "Фронт левый", "type": "acme", "x": 0.2, "y": 0.8}],
  "scenes": [{"id": "pianist", "exec": "1.101", "label": "Pianist"}]

```

Сцены и группы добавляются правкой этого файла, приборы — правкой или кнопкой «Обновить из пульта». Позиции приборов записывает сама панель. Мост пишет файл атомарно (временный файл + замена), чтобы при сбое конфиг не испортился. У прибора без позиции `x` и `y` отсутствуют, у пропавшего из шоу стоит `"missing": true`.

Значения `export_cmd` и `export_dir` выше — предположение, их нужно проверить в зале.

## 8. Запуск на Windows

1. Один раз скопировать всю папку комплекта (собирается `scripts/build_win.sh`, Python лежит внутри, `uv` не нужен). Дальше обновления по сети (`docs/hall-test-plan.md`, раздел 11).
2. `start.bat` запускает `python\python.exe bridge.py` и перезапускает мост после смены настроек (код 3).
3. Ярлык на `start.bat` положить в автозагрузку.
4. Разрешить порт 8080 в Windows Firewall только для частной сети.
5. Закрепить IP Windows в DHCP роутера, чтобы адрес для планшетов не менялся.

Дома: `uv run bridge.py --mock`, открыть `http://localhost:8080`.

## 12. v2: движение голов и новый дизайн

Дата: 2026-10-16. Обсуждение с владельцем 16.10, макеты вкладок утверждены. Реальный свет ещё не проверен, выезд в зал будет после v2. Разделы 1-11 остаются в силе, если ниже не сказано иначе.

### 12.1 Зал

Зал 20 × 9 м, высота около 9 м. Черновой `plan.svg` перерисовывается в пропорции 20:9 (viewBox 2000×900). Сцена у левой короткой стены, длинная сторона идёт по горизонтали, поэтому план целиком помещается на горизонтальном планшете. Точка «прямо на сцену» для калибровки лучей задаётся в `plan.stage: {x, y}` (доли 0-1, по умолчанию центр сцены на черновом плане). Высота зала в v2 не используется, она понадобится для луча по Tilt.

### 12.2 Что входит в v2

1. Подвижные приборы: ACME 12, 13, 14. У прибора в `config.json` стоит `"moves": true`. Остальные приборы неподвижные.
2. Pan и Tilt через пад. Выбрано несколько голов → все сдвигаются вместе, каждая от своего положения на тот же шаг.
3. Zoom и Фокус: два слайдера, одно значение для всех выбранных.
4. Пресеты положения («Рояль», «Центр»): запомнить Pan и Tilt выбранных голов и вернуть одним нажатием. Только админ.
5. Создание групп в панели: «выбор → новая группа». Удалить можно только группы, созданные в панели.
6. Иконки по типам на схеме: BAR — прямоугольник, голова — круг с лучом, френель — ромб, PAR и Mini-B — круг. Неизвестный тип — круг.
7. Лучи голов на схеме по Pan с калибровкой.
8. Новый интерфейс: четыре вкладки и тёмная тема.

### 12.3 Интерфейс

Основное устройство — планшет в горизонтальной ориентации. Тема одна, тёмная: тёмный фон, янтарный акцент, как на пульте. Яркий экран в тёмном зале слепит и виден зрителям. Цвета задаются CSS-переменными в `style.css`.

Сверху ряд вкладок и индикатор связи с пультом. На вкладках «Свет», «Движение» и «Настройка» схема зала слева, панель управления справа. В портретной ориентации и на телефоне схема сверху, панель под ней, вкладки прокручиваются по горизонтали.

| Вкладка | Что на ней |
|---|---|
| Сцены | Кнопки сцен с состоянием «идёт / выкл», вертикальный мастер, «Погасить всё». Схемы нет |
| Свет | Схема, плитки групп, HSV-круг и 8 шаблонов цвета, слайдер яркости, «Снять выбор» |
| Движение | Схема с лучами, чипы выбранных голов, пад Pan/Tilt, слайдеры Zoom и Фокус, кнопки пресетов, «Запомнить пресет» |
| Настройка | Схема, «Расставить» (режим редактирования v1), «Обновить из пульта», калибровка луча, создание и удаление групп, «Записать в сцену» |


На вкладке «Движение»:
- Выбор на схеме общий для всех вкладок. Если в выборе нет подвижных приборов, пад и слайдеры неактивны с подписью «Выберите голову».
- Пад работает как тачпад: палец ведёт по паду, головы сдвигаются на величину жеста. Точка на паде показывает Pan и Tilt первой выбранной головы, подпись — числа 0-100.
- Значения упираются в 0 и 100 у каждой головы отдельно.
- После вызова сцены положение голов неизвестно. Пад стартует от последних отправленных значений, у головы без них — от 50/50. Над схемой надпись «Положение не отслеживается после вызова сцены», как для цвета в v1.

Калибровка луча (вкладка «Настройка», выбрана одна голова):
- «Сейчас светит прямо на сцену»: запомнить текущий Pan как направление на `plan.stage`.
- «Луч крутится не туда»: развернуть направление вращения луча на схеме.
- Без калибровки луч не рисуется, у головы показан только круг.

Луч на схеме: угол = направление от прибора на `plan.stage` + (pan − pan калибровки) / 100 × размах Pan в градусах (`attrs.pan.max − attrs.pan.min`), со знаком минус при `invert`. Длина луча постоянная. Луч выбранной головы яркий, невыбранной — бледный.

### 12.4 Протокол: новые действия

Все новые действия только в полном режиме.

| Действие | Что делает мост |
|---|---|
| `move_start` | Запоминает Pan и Tilt выбранных подвижных приборов как начало жеста. В MA2 ничего не отправляет |
| `move {dx, dy}` | Слайдер. `dx`, `dy` — общий сдвиг от начала жеста, числа −100…100. Новое значение = начало + сдвиг, обрезка 0-100 |
| `zoom {v 0-100}`, `focus {v 0-100}` | Слайдеры. Одно значение на всех выбранных подвижных |
| `preset_save {label}` | Сохраняет Pan и Tilt выбранных подвижных из `shown` в `config.presets`. Метка уже есть → перезапись |
| `preset_go {id}` | Отправляет Pan и Tilt каждой голове пресета, затем возвращает выбор |
| `preset_delete {id}` | Удаляет пресет из конфига |
| `group_save {label, ids}` | Добавляет группу в `config.groups` без `n` |
| `group_delete {id}` | Удаляет группу, только если у неё нет `n` |
| `beam_home {id}` | Записывает текущий Pan прибора в `fixtures[].beam.home` |
| `beam_invert {id}` | Переключает `fixtures[].beam.invert` |

`move` отправляет общий сдвиг, а не приращение. Поэтому ограничение частоты из раздела 5 может отбрасывать промежуточные значения: последнее значение всё равно приводит головы в нужную точку.

`select_group` для группы без `n` отправляет `Fixture a + b + c`, как `select_fixtures`.

В `shown` у прибора добавляются `pan`, `tilt`, `zoom`, `focus` (0-100), если панель их отправляла. После `blackout` `shown` сбрасывается целиком, как в v1. После любого изменения пресетов, групп или калибровки мост сохраняет конфиг атомарно и рассылает `config`.

### 12.5 Команды MA2 для атрибутов движения

Синтаксис для Pan, Tilt, Zoom и Focus у ACME не проверен. Он задаётся шаблонами в `config.json` и правится в зале без изменения кода:

```json
"attrs": {
  "pan":   {"cmd": "Attribute \"Pan\" At {v}",   "min": -270, "max": 270},
  "tilt":  {"cmd": "Attribute \"Tilt\" At {v}",  "min": -135, "max": 135},
  "zoom":  {"cmd": "Attribute \"Zoom\" At {v}",  "min": 0, "max": 100},
  "focus": {"cmd": "Attribute \"Focus\" At {v}", "min": 0, "max": 100}
}
```

Панель работает в 0-100. Мост пересчитывает значение линейно в `min..max`, округляет до 0,1 и подставляет в `{v}`. Значения выше — предположение.

Отправка:
- У всех целевых голов одно значение (Zoom, Focus, одна голова) → строки атрибутов идут на текущий выбор.
- У голов разные значения (`move` и `preset_go` на нескольких головах) → для каждой головы `Fixture <id>` и строки Pan, Tilt, затем возврат выбора `Fixture a + b` или `Group <n>`. Пометить в коде `# ponytail: по строке выбора на голову; заменить на одну команду, если в зале найдётся синтаксис`.
- `ClearAll`, патч и `/noconfirm` по-прежнему не генерируются.

## 17. Плавные переходы, угадывание голов, модули (2026-10-19, по запросу владельца)

- **Переход между сценами.** `scene_go` принимает `fade` (0–30 с, как у яркости). Без `fade` или при 0 уходит `Go Executor <exec>`. С `fade` уходит `Goto Cue 1 Executor <exec> Fade <с>`: синтаксис взят из справки MA2 (`Goto Cue 3 Fade 4`), на живом пульте не проверен. Если пульт ответит ошибкой, она видна оператору, повторов нет. Время, записанное в самой сцене на пульте, при этом заменяется.
- `swap` — список id сцен, которые панель считает идущими. Мост проверяет их по `allowed_scenes` и по истечении `fade` секунд шлёт `Off Executor` каждой (кроме запускаемой), затем рассылает `running: {id: false}`. Выключение — резкое: плавного погашения старой сцены в мосту нет. Строка `Goto Cue 1 Executor N Fade T` разрешена защитой только для `allowed_scenes` (и в `full`).
- Панель: раздел «Сцены», строка «Переход» (сразу, 2, 5, 10 с) и галочка «Выключить предыдущие в конце». Выбор хранится в памяти вкладки.

Поэтому при получении приборов `fixtures.guess_head` смотрит только на имя типа (`HEAD_TYPE`: moving, mover, beam, sharpy, pointe, oxygen, robin, viper, mac …, mh, head). ## 18. Джойстик, инверсия голов, опрос шоу (2026-10-21, по запросу владельца)

- **Джойстик.** Пад Pan/Tilt работает как стик геймпада: отклонение задаёт скорость, при отпускании стик возвращается в центр, голова остаётся на месте. Положение головы знать не нужно. Панель 10 раз/с шлёт `jog {pan, tilt, mirror}` — шаг в градусах с прошлой отправки (−45…45). Мост суммирует ожидающие шаги одной вкладки (ни один не теряется) и не чаще `rate_hz` шлёт `Fixture …` + `Attribute "Pan" At + <°>` / `At - <°>` (шаблон `attrs.pan.rel_cmd`, тот же, что у шагов ←→↑↓). Команды относительные, поэтому голову можно одновременно крутить с пульта.
- Скорость: квадратичная кривая, 90 °/с у края, мёртвая зона 8 % (`JOY_SPEED`, `JOY_DEAD` в `static/move.js`). Кнопка «Точно (медленно)» — 15 % скорости (`JOY_FINE`). Пад занимает всю ширину карточки, остальное под ним.
- **Инверсия.** `fixture_flag {id, flip_pan: bool}` и `{id, flip_tilt: bool}`: голова висит иначе, знак её шагов (джойстик и ←→↑↓) меняется. Кнопки «Pan наоборот», «Tilt наоборот» под джойстиком ставят флаг всем выбранным головам. Абсолютные команды («Задать позицию», пресеты) флаги не учитывают.
- **Зеркально.** Галочка «Зеркально: сводить и разводить» (`mirror: true` в `jog` и `nudge`): левая половина выбранных голов по `x` на схеме (без места — по номеру) крутит Pan в обратную сторону, лучи сходятся и расходятся. При нечётном числе средняя голова идёт как обычно.
- **Нет атрибута.** Ответ `Error #14: OBJECT DOES NOT EXIST` на Zoom/Focus/Strobe показывается как «у выбранных приборов на пульте нет атрибута «Focus»». Если все выбранные одного типа, мост запоминает тип (`status.no_attr {attr: [type]}`, до перезапуска), и ползунок для таких голов неактивен.
- **Опрос.** При `poll_seconds > 0` мост кроме `List Executor` читает `ListVar`: шоу, загруженное с пульта, видно в панели (баннер «На пульте шоу …»).
- **Подтверждение имени шоу** (загрузка, сохранение): без автозаглавной буквы и автозамены; сравнение без учёта регистра и лишних пробелов. Мосту уходит точное имя из `ListShows`.
- Значения яркости, цвета и положения, выставленные на самом пульте, панель не видит: Telnet их не сообщает.

## 19. После зала 2026-10-21: ничего само не гасит свет, сохранение одной кнопкой, новые приборы (по запросу владельца)

- **Подсветка не снимается сама.** При запуске моста, повторном входе в пульт, «Возобновить» и переключении плана мост больше не шлёт `Off Fixture <зона>`: эта команда стирала и то, что оператор выставил на пульте вручную (зал, 2026-10-21, спасло только Oops). Подсветка остаётся «не снята», её снимает кнопка в баннере с предупреждением. Снятие при выходе из редактора, по таймауту и при отключении планшета работает как раньше. Включение подсветки требует подтверждения: она гасит остальные приборы зала.
- **Сохранение шоу** — одна кнопка с подтверждением, без ввода имени. Мост читает `ListVar` (только чтобы назвать шоу в ответе) и шлёт `SaveShow`: перезаписывается шоу, открытое на пульте.
- **«Получить приборы»** сначала читает имя шоу на пульте. Если план панели привязан к другому шоу, мост сохраняет его в `shows/`, открывает (или создаёт) план шоу с пульта и импортирует приборы туда. Ответ: `switched: <имя>`.
- **Перепатч.** Если прибор пропал из экспорта, а новый номер появился с тем же именем и типом (ровно один кандидат), место на схеме, подпись и отметки переходят к новому номеру. Команды пульту идут по номеру прибора (`Fixture N`), смена DMX-адреса на них не влияет.
- **Перенос из другого шоу** `plan_copy {from, ids}`: из `shows/<from>.json` на приборы с теми же номерами копируются `x, y, label, moves, service, rot, beam, flip_pan, flip_tilt, color` и группы панели (без групп пульта, без повторов по имени). `ids` пусто — все. В MA2 ничего не уходит, патч панель не меняет. `config.plans` — имена других планов на этом ПК.
- **Сцены** (`scenes_import`) тоже сначала переходят на план шоу с пульта. Читаются страницы плана и все страницы, где `List Page` показывает объекты (`(N)` в конце строки). Строка executor разбирается шире: необязательное слово в начале (`Executor`, `Exec`), необязательный номер, `стр.номер`, возможно повтор, имя. Настоящие строки `List Executor` в зале ещё не записаны. Ответ: `total` — сцен в плане.
- **Приборы без Fixture ID** (патч только с Channel ID) панель не может вести (`Fixture N`). Импорт возвращает их имена в `no_id`, панель показывает: «дайте им Fixture ID в патче MA2».
- **Значок на схеме** `fixture_flag {id, icon: par|bar|head|fresnel}`: круг, прямоугольник, квадрат, ромб; заменяет угадывание по типу.
- **«Погасить свет»** кроме `Off Executor` сцен панели ставит яркость 0 всем приборам плана (кроме служебных и пропавших): в плане нового шоу без сцен кнопка ничего не делала, а свет из панели и программера оставался. `shown` после неё: `dim 0` у этих приборов. Отмена — Oops на пульте.

## 20. Сцена заменяет всё, удаление сцены на пульте, «История» (2026-10-21, по запросу владельца, v21)

- **Сцена заменяет всё.** `scene_go` шлёт `ClearAll` перед `Go`/`Goto`: значения панели в программере больше не остаются поверх сцены. Это единственное место, где мост шлёт `ClearAll`; защита пропускает ровно эту строку (`ClearAll` чистит только программер, шоу не меняет). Панель всегда передаёт `swap` (все сцены, которые она видит идущими): без `fade` мост гасит их сразу, с `fade` — в конце перехода. Галочка «Выключить предыдущие в конце» убрана. После `scene_go` «что показано» панели очищается.
- **Что попадает в сцену.** Запись по-прежнему `StoreLook ... /Source=Output`: весь выход пульта. Прибор, который при записи не светил, в сцену не попадает, но раз сцена гасит прочие и чистит программер, при её вызове он вернётся к значениям по умолчанию (тёмный). Так на сцене ровно то, что было при записи.
- **Удаление на пульте.** `scene_delete {id, desk: true}`: `Delete Executor <exec>`, затем сцена уходит из панели. Только режимы `full` и `store` (в `store` — номер из `store_execs`, проверяет защита). Кнопка «Удалить на пульте» с подтверждением; `SaveShow` не шлётся. Подтверждение пульта для `Delete` в Telnet не проверено.
- **«История»** — раздел панели: последние 100 изменений этого моста (время, что сделано), новые сверху; в памяти, перезапуск моста очищает. Действие `undo {n}` откатывает одно изменение:
  - свет (яркость, цвет, позиция, zoom, focus, strobe, пресет позиции): мост шлёт приборам прежние значения, которые панель знала; движение одного слайдера в течение 3 с — одно изменение; значение, неизвестное панели до изменения, не откатывается;
  - план (группы, пресеты, расстановка, зал, флаги приборов, удаление сцены из панели и т. п.): изменённые ключи `config.json` возвращаются к прежним;
  - действия на пульте (сцены, запись и имя сцены, страница, группа в MA2, загрузка шоу) видны в списке, но панелью не откатываются.
  - Откат сам попадает в историю и тоже откатывается. Каждое изменение откатывается один раз.


## 21. Цвета на плане без ручной разметки; раздел «Патч» и RDM (2026-10-21, по запросу владельца, v23–v24)

- **Каналы цвета (v23).** Для каждого типа приборов плана мост один раз за запуск (и при каждом «Получить приборы») шлёт `Export FixtureType <номер> "<одноразовое имя>"`, ищет файл по имени в папках пульта и на уровень ниже, берёт из первого модуля `ChannelType attribute=DIM/COLORRGB1/COLORRGB2/COLORRGB3` и `coarse` (номер канала) и сохраняет в `dmx_map` типа. Свой файл удаляет. Ручных полей каналов в «Зале» нет. Чтение DMX через Lua требует у пользователя Telnet прав Admin (с Program пульт отвечает Error #44).
- **Раздел «Патч» (v24, Подготовка).** Таблица приборов плана: Fixture ID, имя, тип, адрес в патче, footprint профиля MA2 (колонка DMXFootprint из `List FixtureType`; экспорт приборов даёт меньше: у Mini-B 14 вместо 17; без него план правки не строится), занятый диапазон. Пересечения диапазонов отмечаются. Физический footprint известен только если его прочитали по RDM; иначе он «не прочитан» и не подменяется догадкой. Явный режим правки: без него раздел только показывает.
- **Смена адреса в патче.** `Assign Fixture <id> At Dmx <u>.<aaa>` (документация MA2 3.9, keyword Dmx: старый патч прибора снимается). Перед записью мост строит план (прибор, было → станет, диапазоны, конфликты) и выдаёт метку; запись принимается только с той же меткой (данные не устарели). После записи мост перечитывает приборы экспортом и сверяет адрес. Тайм-аут не повторяется. Только при `safety.allow_patch` и только строка, собранная мостом для подтверждённого плана.
- **RDM.** Включение RDM на пульте командой не документировано: панель его не включает и не выключает, а показывает, где это делается (Setup → Console Global Settings → Enable RDM; вселенная: Setup → Patch → DMX List, ячейка RDM), и после каждой операции напоминает выключить. Чтение: `RdmList` (вывод показывается как есть; UID берётся из строк, остальные колонки формата не проверены). Запись по UID: `RdmSetParameter dmx_start_address <a> / UID = <uid>` и `RdmSetParameter identify_device 1|0 / UID = <uid>`. Только при `safety.allow_rdm`. `RdmAutopatch`/`RdmAutomatch` и прочие RDM-команды мост не шлёт никогда.
- **Сопоставление.** Оператор сам связывает UID с прибором плана; совпадение имени или адреса связь не подтверждает. Связь хранится в `rdm` прибора (`uid`, `footprint` если прочитан), не заменяет Fixture ID.
- **Согласованная смена.** Сначала физический адрес по RDM, затем патч, затем перечитывание обеих сторон. Атомарности нет: при частичном успехе панель показывает, что изменилось, и готовую обратную команду.
- **Режим/профиль.** Смена DMX personality и профиля MA2 не делается: число каналов каждого режима через Telnet не проверить.
- Все записи патча и RDM попадают в «Историю» (было → стало), откат — только предложенной обратной командой с новым подтверждением.

## 22. Удаление сцены крестиком и перезапись сцены (2026-10-21, по запросу владельца, v24.1)

- **Крестик.** В правом верхнем углу каждой плитки сцены есть кнопка «×». Нажатие спрашивает подтверждение («Удалить сцену <exec> на пульте? Вернуть её можно только из бэкапа шоу.»), затем шлёт `scene_delete {id, desk: true}` по правилам раздела 20. Без подтверждения ничего не отправляется. Кнопка неактивна без связи и при отключённой функции `store`. Если сцена идёт, «Выкл» стоит левее крестика.
- **Перезапись.** «Изменить» на плитке открывает окно: имя сцены, «Сохранить имя» (`scene_rename`) и «Перезаписать текущим светом». Перезапись спрашивает подтверждение и шлёт `scene_create {label, page, exec, confirm: exec, replace: true}`.
- **Как мост перезаписывает.** В одном `action_lock`: сцена с этим `exec` должна быть в панели (иначе отказ), `confirm` совпадает с `exec`, затем `Delete Executor <exec>`, затем обычная проверенная запись из раздела 14 (`List Executor <exec>` → пустое место → `StoreLook` + `Label`). Старая запись сцены в `config.json` заменяется новой. Режимы как у `scene_create` (`full`, в `store` — номер из `store_execs`).
- Запрет раздела 14 остаётся: `/Overwrite` и `SaveShow` не шлются, `store_scene` отключена. Перезапись — это удаление плюс запись в пустое место, а не запись поверх.
- Если запись после удаления не прошла, сцена на пульте уже удалена, а в панели плитка остаётся (конфиг не меняется). Мост сообщает причину, повторно ничего не отправляет; оператор перезаписывает ещё раз или убирает плитку.

## 23. Запись ответов пульта при каждом запуске (2026-10-22, по запросу владельца)

- При первом входе в пульт после запуска моста (`start.bat`, без `--mock`) мост сам шлёт только читающие строки, формат ответа на которые в коде ещё угадан: команды `--probe` (`ListVar`, `List Fixture`, `List Group`, `List Preset`, `List Sequence`, `List Executor` в нескольких диапазонах, `List Page`, `List User`, `List FixtureType`, `List Attribute`), `ListShows` и `List Executor <exec>` для каждой сцены плана (до 10). Повторный вход после обрыва связи запись не повторяет.
- После первого удачного `scene_go` каждой сцены (до 3 сцен за запуск) мост добавляет `List Executor <exec>`: строка идущей сцены показывает настоящее слово статуса.
- Строки идут через тот же `action_lock` и ту же защиту (`make_guard`), ничего не меняют в шоу. Ответы с замаскированным паролем пишутся в `field-data/auto/<дата-время>.txt`, один файл на запуск, хранятся последние 20. Три последних файла попадают в `diag.zip` (папка `auto/`).
- Владелец присылает `diag.zip`; по файлам правятся разборы `commands.parse_*` и регулярки `DEFAULT_MA2`, а сами ответы становятся тестами.

## 24. Простой режим для учителей, стробоскоп по типу прибора, скрытие Zoom/Focus (2026-10-25, по запросу владельца)

- **Простой режим на втором порту.** Тот же процесс моста слушает второй порт `simple_port` из `settings.json` (по умолчанию `8090`, `null` выключает). Там открывается `static/simple.html`: только плитки сцен (включить, выключить идущую) и большая кнопка «Погасить всё» с подтверждением. Нет разделов, слайдеров, настроек, `/api/*`, журнала и диагностики.
- Защита на стороне моста, а не только в интерфейсе: соединение с порта `simple_port` принимает только `scene_go`, `scene_off`, `blackout` (и служебный запрос состояния); любое другое действие получает отказ «в простом режиме недоступно». Ограничения `safety` (разрешённые сцены и приборы, режим) действуют как на основном порту. Сообщения `config` на этот порт содержат только сцены и страницы.
- В Windows Firewall разрешается и порт 8090 (частная сеть), раздел 8.
- **Стробоскоп.** Атрибута `Strobe` на пульте нет (зал 2026-10-18: `Error #14` на каждое значение). Мост берёт его из того же `Export FixtureType`, что и каналы цвета (раздел 21): атрибут `SHUTTER` или `STROBE` в `ChannelType`, а внутри него функции/наборы каналов (`ChannelFunction`, `ChannelSet`) с именем, содержащим `strob`, — диапазон строба, и с именем `open` — значение «открыто». Это пишется в `dmx_map` типа как `strobe: {attr, open, from, to}` (значения в процентах канала, как их понимает `Attribute "..." At`).
- Слайдер: 0 = «выкл» → `Attribute "<attr>" At <open>`; 1–100 → линейно внутри `from..to`. Приборы разных типов в выборе получают строки по типам, как цвет (`rgb`/`cmy`). Тип без найденного диапазона строба стробоскоп не получает; если таких нет ни у одного выбранного — отказ с причиной. Защита разрешает `Attribute` только для имён, прочитанных из типов. Структура `ChannelFunction`/`ChannelSet` в экспорте 3.9.60 и единицы `At` для многофункционального канала не проверены: первая проверка в зале — `docs/hall-test-plan.md`, раздел 12.
- **Скрытие Zoom и Focus.** По тому же экспорту типа в `dmx_map` типа пишется `has`: какие из `ZOOM`, `FOCUS`, строба есть. Панель не показывает слайдер, если у всех выбранных приборов тип прочитан и атрибута нет; если выбор пуст — по всем приборам плана. Тип ещё не прочитан → слайдер виден, как раньше (и по-прежнему гаснет после `Error #14`, раздел 19).
