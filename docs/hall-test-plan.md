# Панель MA2: установка и проверка на площадке

Комплект переносится на Windows один раз. Дальше настройки правятся на месте в браузере (страница «Настройки»), а исправления кода приходят по локальной сети с Mac (раздел 11). Флешка нужна только для первого переноса.

Главное о безопасности:
- Панель шлёт пульту только строки из разрешённого списка. Проверка стоит в самом мосту, перед отправкой (`safety.py`).
- В режиме `test` (по умолчанию) разрешён только живой свет на приборах и сценах, вписанных в настройки. Запись в пульт заблокирована.
- Patch, Fixture Types, RDM, сеть, загрузка и сохранение шоу, ClearAll, Delete, Macro не генерируются вообще и заблокированы защитой в любом режиме, кроме `full`. В `full` их тоже не шлёт ни одна кнопка.
- Ничего не отправляется повторно само. Нет автоматической перезаписи.
- Изменение настроек ничего не отправляет на пульт.

## 0. Что проверено, а что нет

**Проверено на Mac на имитации пульта (mock):** автотесты (`uv run pytest`), сквозной сценарий «запуск → подключение → данные → выбор прибора → параметры → сцены → остановка → повторный запуск» (`tests/test_scenario.py`), точные строки для каждой кнопки (`docs/outgoing-commands.md`).

**Не проверено, проверяется только на настоящем grandMA2 (помечено ⚠):** все форматы ответов пульта (раздел 12), имена атрибутов у ваших приборов, синтаксис относительного шага Pan/Tilt, реальные диапазоны Pan/Tilt, изоляция Programmer (раздел 9), запуск на этом конкретном Windows. Работу с первого переноса это не гарантирует; программа рассчитана на то, чтобы непонятный ответ пульта блокировал только конкретную функцию и был виден в Диагностике.

## 1. До начала (ответственный оператор, ~10 мин)

1. Оператор сохраняет актуальное шоу и делает отдельную копию под новым именем (`..._before_panel_test`). Копия шоу не хранит временные значения Programmer и состояние исполнителей.
2. Записать или сфотографировать: какое шоу загружено, какие исполнители запущены, положение фейдеров и Master, что лежит в Programmer, какой пользователь и профиль вошли на пульте.
3. Выбрать приборы для теста (Fixture ID) и момент, когда на них можно менять свет. Голову для Pan/Tilt направить в безопасную сторону, Dim ≤ 30 %.
4. Решить, как вернуть исходное состояние (раздел 10).

## 2. Установка (~5 мин)

1. `Win+R` → `winver`: нужна Windows 10 или 11, 64 бита.
2. Распаковать `ma2-panel-win.zip` в любую папку, например `C:\ma2-panel` (пробелы и кириллица в пути допустимы). Ничего не устанавливается, MA2 не затрагивается.
3. `check.bat`: покажет адреса ПК и настройки, проверит, открыт ли порт Telnet 30000. Ничего не отправляет и не входит в пульт.
4. Включённый Telnet Remote проверяет оператор. Сеть и Telnet на пульте не менять без ответственного.

## 3. Запуск, остановка, перезапуск

- `start-mock.bat`: без пульта, внутри программы имитация. Для знакомства и проверки настроек.
- `start.bat`: подключение к настоящему пульту. Окно не закрывать. Если «Перезапустить мост» нажат на странице настроек, окно само запустит мост заново.
- Остановка: `stop.bat`, Ctrl+C или закрыть окно. Пульту при этом ничего не отправляется, закрывается только Telnet-соединение панели.
- Панель на этом ПК: `http://localhost:8080`. Журнал: `bridge.log` в папке программы.

## 4. Настройки на месте (страница «Настройки»)

Открыть `http://localhost:8080/settings.html` **на самом ПК с мостом** (с планшета страница закрыта). Сохранение пишет `settings.json` (старый файл копируется в `backups/`) и ничего не отправляет на пульт. Новые настройки начинают действовать после кнопки «Перезапустить мост» (она откажет, пока идёт передача команд).

| Раздел | Что вписать |
|---|---|
| Подключение | адрес пульта (`127.0.0.1`, если MA2 на этом ПК), порт 30000, пользователь (`panel`), пароль (хранится только в `secret.env`, обратно не показывается), тайм-аут ответа, шаблоны ответов (раздел 12) |
| Панель | `bind`: `127.0.0.1` пока проверяем на этом ПК, `0.0.0.0` для планшета; порт 8080 |
| Безопасность | режим `test`; разрешённые приборы (номера через запятую); разрешённые сцены (`1.101`); для записи сцен режим `store` и список `store_execs` |
| Функции | галочка на каждую функцию; текст причины блокирует функцию с этой причиной (например, найден дефект) |
| Сопоставление атрибутов | JSON поверх `attrs` из config.json: имена атрибутов, шаблоны команд, шаг и диапазоны Pan/Tilt, режим цвета |

Типичные исправления:
- «Ошибка входа»: пользователь/пароль в разделе «Подключение».
- «Вход не подтверждён»: в Диагностике посмотреть ответ на вход, вписать слово из него в `login_ok_regex`.
- «Результат неизвестен» на каждой команде: в Диагностике сравнить сырые ответы; поправить `prompt_regex` или увеличить тайм-аут.
- «Заблокировано защитой: прибор N»: добавить N в разрешённые приборы.
- «Команда не в списке разрешённых» для атрибута: имя атрибута отличается, поправить сопоставление.

## 5. Диагностика

`http://<ПК>:8080/diag.html` (ссылка «Диагностика» в панели):
- состояние связи словами, ответ пульта на вход (пароль скрыт), результат последней команды;
- **1. Отчёт без отправки команд:** «Скачать диагностический пакет» собирает уже имеющиеся журналы и состояние. На пульт ничего не уходит. Пакет скачивается, даже если часть данных недоступна (тогда в нём есть `collect_errors.txt`);
- **2. Активные проверки** (шлют команды на пульт; свет, патч, сцены и шоу не меняются):
  - «Прочитать списки пульта»: `ListVar`, `List Fixture`, `List Group`, `List Preset`, `List Sequence`, `List Executor`, `List Page`, `List User` и сырые ответы;
  - «Проверить экспорт приборов»: создаёт на ПК с MA2 несколько файлов `panel_diag_*` (`Export /?`, `Export Fixture`, `Export Fixture … /nc`, `Export Channel`, `Export Root LiveSetup.Layers`) и ищет, в какой папке они появились. Нужна галочка «Разрешить получение приборов из MA2»;
  - «Всё сразу и скачать пакет»: обе проверки, затем скачивание;
- блок «Чтение приборов: что известно»: команда, папки и их содержимое, последняя попытка (ответ MA2, найденный файл, ошибка разбора);
- список ошибок с подсказкой, что поправить.

В пакете скрыт только пароль (по форме строки входа и `MA2_PASSWORD=`; пароль из шести и более символов ещё и по значению). Адреса, даты, номера приборов и имена не затираются. Пакет содержит версию сборки, `diag.json` (связь, версия MA2, шоу, настройки чтения приборов), `diag/export_trace.json` (последняя попытка получения), `diag/export_probe.json` и найденные XML. Присылайте этот файл при любой проблеме.

## 6. Статусы

Строка состояния и последняя команда показываются отдельно:

| Статус | Значит | Не значит |
|---|---|---|
| Соединение установлено | TCP-порт пульта ответил | что вход выполнен |
| Вход выполнен | ответ на `login` без ошибки и совпал с `login_ok_regex` | что у пользователя нужные права |
| Вход не подтверждён | ошибки нет, но ответ не распознан | что вход не удался: команды идут, статус жёлтый |
| Команда отправлена, ошибок нет | пульт вернул приглашение `]>`, слов ошибки нет | что свет изменился. Смотреть на прибор |
| Ошибка пульта | в ответе слово ошибки | |
| Результат неизвестен | приглашения не было за тайм-аут | что команда не выполнилась. Повторно не отправлена; если поздний ответ так и не пришёл, следующая команда не уходит, соединение переоткрывается |

## 7. Порядок проверки функций на пульте

Функции проверяем по очереди; это порядок проверки, сборка одна. После каждого шага смотреть на прибор и на пульт. При сомнении: красная «Остановить передачу» (ничего не гасит, только перестаёт слать; «Возобновить» включает обратно).

| № | Что делаем | Ожидаем | Если не так |
|---|---|---|---|
| 1 | `start-mock.bat`, `http://localhost:8080`, пройти все вкладки, открыть Настройки и Диагностику | плашка «Имитация», всё нажимается | окно моста и `bridge.log` |
| 2 | Настройки: адрес, пользователь, пароль, приборы; `stop.bat`, `start.bat` | «Вход выполнен» или «Вход не подтверждён». На пульте ничего не изменилось | Диагностика → ответ на вход, раздел 4 |
| 3 | Диагностика → «Проверить пульт» → «Скачать диагностический пакет» | сырые ответы видны, zip скачан | прислать zip |
| 4 | Свет → прибор N → Dim 10–20 % | `Fixture N`, `At 20`; меняется только N | Стоп, пакет диагностики |
| 5 | Группа (её приборы разрешены) → Dim | `Fixture a + b …` только с ними | Стоп |
| 6 | Цвет «Красный» | `Fixture N` + три `Attribute "ColorRGB…"`; цвет сменился | имя атрибута → Сопоставление атрибутов; у прибора нет RGB → `color: "none"` или `"cmy"` |
| 7 | Zoom, Focus, Strobe по одному | строки в логе, прибор реагирует | как п. 6 |
| 8 | Pan/Tilt, раздел 8 | | |
| 9 | Обрыв: кнопка «Разорвать связь с пультом» (сверху) | «Связь с пультом разорвана вручную», кнопки неактивны, на пульте закрылась только сессия `panel`, остальное работает | |
| 10 | «Подключить к пульту» | вход заново; старые значения ползунков **не** приходят, позиция голов снова «неизвестна» | Свет дёрнулся: стоп, пакет диагностики |
| 11 | Сцены → обновить сцены из пульта (Настройка); `allowed_scenes`: `["1.101"]`; кнопка сцены, затем «Выкл» | `Go Executor 1.101`, `Off Executor 1.101` | пакет диагностики (ответ `List Executor`) |
| 12 | Запись сцены, раздел 8.2 (только по согласованию) | | |
| 13 | `stop.bat`, `start.bat` | после запуска свет не меняется, выбор пуст | |
| 14 | Оператор на пульте | пользователь/профиль не изменились, свет других приборов не изменился | стоп, разобраться |

Отключение сетевого кабеля и любые изменения сетевых адаптеров в проверке не используются: обрыв проверяется только для соединения моста с MA2 (п. 9–10).

## 8. Pan/Tilt и сцены

### 8.1 Pan/Tilt без скачка

Пульт по Telnet не сообщает, куда сейчас смотрит голова. Поэтому:
- пока панель сама не задала голове абсолютную позицию, позиция **неизвестна**: пад выключен и это написано на вкладке «Движение»;
- шаги «Pan −/+», «Tilt −/+» шлют относительное изменение (`Attribute "Pan" At + 2`), голова сдвигается на шаг от текущего положения, без скачка ⚠ синтаксис проверить первым шагом;
- «Задать позицию» шлёт абсолютные градусы: голова поворачивается сразу, панель просит подтверждение. После этого позиция известна и пад двигает голову плавно от неё;
- позиция снова становится неизвестной после обрыва связи и после запуска сцены;
- диапазоны (±270° / ±135°) взяты из настроек и помечены «не проверен на пульте», пока в сопоставлении не стоит `range_checked: true`.

Проверка: Dim ≤ 30 %, одна голова. Нажать «Pan +» один раз → голова сдвинулась немного в одну сторону. «Pan −» → вернулась. То же для Tilt. Только после этого «Задать позицию» на значение рядом с текущим, затем пад.

### 8.2 Запись сцены с защитой существующей работы

Только с согласия ответственного, после остальных шагов.
1. Настройки: режим `store`, `store_execs`: номер(а) executor, которые оператор считает пустыми. Перезапуск.
2. Настройка → «Новая сцена из текущего света»: имя, затем вручную напечатать номер executor.
3. Мост сразу перед записью спрашивает `List Executor <номер>` и пишет только если ответ **распознан как пустое место** (`exec_empty_regex`). Занято, ошибка, тишина или непонятный ответ: запись отменяется с объяснением. Неизвестный ответ никогда не считается свободным местом.
4. Отправляется `StoreLook Executor <n> Cue 1 /Source=Output` и `Label …`. `/Overwrite` и `SaveShow` не отправляются никогда; запись в существующую сцену отключена. Шоу сохраняет оператор.
5. Если результат `StoreLook` неизвестен: панель так и пишет, повторно не шлёт, сцену в панель не добавляет; оператор смотрит executor на пульте.
6. ⚠ `/Source=Output` записывает выход: при общем Programmer или работающих сценах в сцену попадёт больше, чем выставила панель.
7. Вернуть режим `test`.

## 9. Изоляция Programmer ⚠ (проверить вместе с оператором)

Что **не** доказывает общий Programmer: значение прибора видно в общей таблице приборов (Fixture Sheet) или на выходе. Таблица и выход показывают итоговый свет от всех источников: Programmer любого пользователя, исполнители, Master.

Проверяем три вещи по отдельности.

**А. Пользователь.** Диагностика → «Проверить пульт» → ответ на `List User`: строка пользователя `panel` и его профиль. Формат ответа не проверен; если непонятно, сфотографировать список пользователей на пульте. Оператор называет пользователя, под которым работает он сам. Если это тоже `panel`, изоляции нет: остановиться.

**Б. Профиль.** У `panel` должен быть свой профиль, не тот, что у пользователя пульта. Один профиль на двоих: считаем выборку и Programmer общими, дальше не проверяем, исправляет ответственный.

**В. Источник значения.** Только когда Programmer оператора **пуст** (Clear на пульте не подсвечена).
1. Панель: прибор N, Dim 20 %.
2. Оператор смотрит **свой** Programmer: подсветилась ли у него Clear, появился ли N среди значений его Programmer (цвет Programmer, а не исполнителя). Да: Programmer общий.
3. Нет: оператор очищает свой Programmer до конца (в MA2 Clear действует ступенчато: выбор → активные значения → всё). Его Programmer был пуст, у него ничего не пропадает. N остался на 20 %: Programmers раздельные, значение держит `panel`. N погас: общий.
4. По желанию: оператор берёт другой прибор M в свой Programmer. Панель всегда шлёт явный `Fixture N` перед значением, поэтому чужой выбор её команды не меняет; шаг подтверждает, что панель не снимает чужие значения.
5. Записать: пользователь, профиль, общий/раздельный, фото.

Общий Programmer: любой Clear/Store на пульте задевает значения панели и наоборот. Работать только по договорённости, запись сцен не делать.

## 10. Что программа может изменить и как вернуть

В MA2: значения в Programmer пользователя панели (Dim, цвет, Pan/Tilt, Zoom, Focus, Strobe разрешённых приборов); Go/Off сцен из разрешённого списка; Telnet-сессия панели; в режиме `store` новая сцена в проверенном пустом executor. Только с отдельными флагами (по умолчанию выключены, `full` их не включает): `allow_fixture_read` — файл экспорта `panel_fixtures.xml` в папке importexport; `allow_highlight` — Dim 0/уровень подсветки и `Off Fixture` приборов зоны в Programmer панели; `allow_show_load` — `LoadShow` выбранного и подтверждённого шоу (меняет весь свет); `allow_show_save` — `SaveShow` по кнопке. Без этих флагов не меняется: шоу, существующие сцены, группы, пресеты, патч, типы приборов, RDM, пользователи, профили, сеть, страницы, Master.

На Windows (только папка программы): `bridge.log*`, `bridge.pid`, `backups/`, `probe.txt`, `settings.json`, `secret.env`, `config.json` (план, группы, пресеты, сцены панели), `shows/` (планы других шоу), `highlight.json` (только пока подсветка не снята), `diag/` (`last_export.xml`, `export_trace.json`, `export_probe.json`, `export_probe/`), `update.log`, `update_url.txt`, `previous/`, правило брандмауэра «MA2 panel» (если запускали `firewall-open.bat`).

Возврат:
1. «Остановить передачу», `stop.bat`.
2. Значения Programmer убирает оператор привычным способом, после проверки, чьё это содержимое. Мост не шлёт Clear, ClearAll, Off All, Oops; `LoadShow`/`SaveShow` — только по кнопке при включённом флаге.
3. Сцены вернуть по записи из п. 1.2.
4. `firewall-close.bat` (администратор). `bind` обратно `127.0.0.1`.
5. Папку можно удалить целиком.

## 11. Обновления по сети с Mac (без флешки)

На Mac, в папке проекта:
```
scripts/serve_update.sh
```
Скрипт соберёт `ma2-panel-update.zip` (только файлы программы), посчитает SHA256, покажет адрес Mac и запустит раздачу на порту 8765. Ctrl+C останавливает. macOS может спросить разрешение на входящие соединения для python3: разрешить.

На Windows: `update.bat`. Первый раз спросит адрес Mac (например `192.168.0.20:8765`), дальше помнит (`update_url.txt`).
- Обновление идёт только по этому явному запуску.
- Перед установкой проверяет мост: если идёт передача команд (или была в последние 10 с), отказывает. Если мост простаивает, спрашивает «Остановить мост и обновить?».
- Проверяет SHA256 и состав архива: заменяет только `*.py`, `*.bat`, `static/`, `docs/`, `VERSION`, `README-RU.md`. Никогда не трогает `settings.json`, `secret.env`, `config.json`, `backups/`, логи, `python/`, `lib/` и файлы MA2.
- Прежняя версия кладётся в `previous/`; `rollback.bat` возвращает её.
- После обновления: `start.bat`. Версия видна в Диагностике.

## 11a. Приборы из MA2

Перед чтением приборов в «Настройки» включите флаг `allow_fixture_read`. Нужен доступ к экспорту приборов; само чтение не меняет свет.

1. Подключитесь к пульту и дождитесь статуса входа.
2. На вкладке «Настройка» проверьте строку **«Шоу на пульте»**. Если имя не определилось, нажмите **«Привязать план к этому шоу»** и подтвердите привязку.
3. Если на пульте показано другое шоу, сначала нажмите **«Открыть план шоу X»**. Не загружайте файл шоу только ради смены плана панели.
4. Нажмите **«Получить приборы из MA2»**.
5. Дождитесь результата:
   - **«добавлено N»** — приборы появились в плане, но ещё не имеют координат;
   - **«пропало M»** — приборы больше не найдены в экспорте. Они не удаляются, а остаются в плане серыми с пометкой «нет в шоу»;
   - **«всего K»** — общее количество приборов в плане.
6. Расставьте новые приборы на плане. Их координаты, подписи и цвет сохраняются при следующих чтениях.
7. После изменений патча снова нажмите **«Получить приборы из MA2»**. Существующая расстановка сохранится, новые приборы добавятся в лоток, исчезнувшие будут отмечены как пропавшие.

Кнопка использует `ma2.export_cmd`, по умолчанию:
```
Export Fixture 1 Thru 9999 "panel_fixtures"
```
Перед командой панель удаляет собственный старый `panel_fixtures.xml` в `ma2.export_dir` и в папках `ma2.export_search` (иначе MA2 спросит про перезапись, а старый файл можно принять за новый), затем ждёт файл `ma2.export_wait` секунд. Файл, найденный вне `export_dir`, принимается только если он создан после отправки команды. Недописанный файл перечитывается, пока растёт его размер. Команда экспорта и ответ MA2 записываются в `diag/export_trace.json`.

Это не то же самое, что **«Импорт подготовленного XML-файла (не из пульта)»** в «Настройках». Импорт файла ничего не отправляет в MA2 и предназначен для XML, выбранного вручную на этом ПК.

Если файл экспорта не найден или формат не распознан:

1. Откройте «Диагностику», нажмите «Всё сразу и скачать пакет».
2. В пакете смотрите `diag/export_trace.json` (что отправлено, что ответил MA2, какие папки проверены) и `diag/export_probe.json` (в какой папке появились файлы).
3. На компьютере MA2 проверьте папку `importexport`, обычно:
   `C:/ProgramData/MA Lighting Technologies/grandma/*/importexport`.
4. Сверьте настройки `ma2.export_dir` и `export_search`. При необходимости проверьте `ma2.export_dir`/`export_search` и имя файла в `ma2.export_cmd`.
5. Не нажимайте кнопку повторно без проверки: при ошибке список приборов не меняется. Передайте ответственному `diag.zip` и исходный XML, если он найден.

## 11b. Подсветка при расстановке

В «Настройках» включите `allow_highlight`. Подсветка работает только в редакторе плана и только для выбранного прибора.

В редакторе включите галочку **«Подсвечивать выбранный прибор в зале»**. Панель затемняет только приборы текущего плана, которые:

- не имеют `missing: true`;
- не имеют `service: true`;
- не указаны в `settings.highlight.exclude`;
- разрешены списком приборов в настройках, если режим не `full`.

Служебные приборы (`service`), приборы из `exclude` и приборы, которых нет в плане, не гаснут и не трогаются. У выбранного прибора устанавливается уровень `highlight.level` (по умолчанию 100), у остальных приборов зоны — 0. Меняются только диммеры.

Подсветка снимается при снятии галочки, нажатии «Сохранить» или «Отмена», уходе с вкладки, закрытии вкладки/соединения, а также после 10 секунд без связи. При снятии панель отправляет `Off Fixture <ids>` и восстанавливает значения, которые сама установила до подсветки.

Если появилась красная плашка **«Подсветка не снята»**:

1. Не продолжайте расстановку.
2. Проверьте связь и нажмите **«Снять подсветку»**.
3. Если мост не запускается, запустите `start.bat`. При необходимости войдите на пульте под пользователем `panel` и нажмите **Clear** в его Programmer.
4. До запуска моста значения могут оставаться в Programmer пользователя `panel`.

Исполнитель с приоритетом выше Programmer, например `Super`, может оставаться видимым и перекрывать результат подсветки. Подсветка не управляет сценами, executor’ами и Programmer других пользователей; фактическую изоляцию Programmer проверьте по разделу 12a.

## 11c. Шоу

Откройте вкладку **«Шоу»**. На ней три блока:

1. **Файл шоу** — текущее шоу, список файлов, загрузка и сохранение.
2. **Cue и Sequence** — сцены и последовательности внутри шоу; ссылка ведёт на вкладку «Сцены».
3. **Page и Executor** — страницы и исполнители; ссылка ведёт на вкладку «Сцены», где кнопки сгруппированы по страницам.

Для загрузки включите `allow_show_load`. Для кнопки **«Сохранить текущее шоу»** отдельно включите `allow_show_save`.

Порядок загрузки:

1. Выберите файл шоу и нажмите «Загрузить».
2. Подтвердите имя шоу.
3. При наличии несохранённых изменений выберите один из трёх вариантов:
   - **«Сохранить на пульте самостоятельно, потом загрузить»** — загрузка отменяется;
   - **«Сохранить текущее шоу»** — отправляется `SaveShow` при включённом `allow_show_save`;
   - **«Загрузить без сохранения»** — подтвердите предупреждение о потере изменений и ещё раз введите имя.
4. Дождитесь статуса **«Шоу загружено»** или сообщения об ошибке.

Загрузка влияет на весь свет: шоу, страницы, executor’ы, сцены и пользователей пульта. Панель сама шоу не загружает при подключении, открытии вкладки или переподключении. После успеха открывается план нового шоу; старые значения Programmer и выбор приборов повторно не отправляются.

Успех подтверждается совпадением имени шоу после загрузки. Если имя не совпало, истёк тайм-аут или вход не выполнен, загрузка считается неуспешной, а план панели не переключается. Если после загрузки нет входа, проверьте пользователей нового шоу: в нём может отсутствовать пользователь `panel`. Создайте/настройте его на пульте и перезапустите мост.

   - **Сделать:** включить `allow_fixture_read`, нажать «Получить приборы из MA2», проверить появление файла и приборов.
   - **Записать:** фактическую команду, имя XML, папку, время создания и количество приборов; сохранить `diag.zip` и XML.

   - **Сделать:** загрузить копию шоу, в которой заранее проверено наличие пользователя `panel`.
   - **Записать:** вошёл ли мост автоматически/после переподключения, точный ответ пульта.
   - **Если не совпало:** проверить пользователя и профиль в шоу; отсутствие пользователя исправляется в шоу, а не настройкой панели.

   - **Записать:** пользователи, профили, общий/раздельный Programmer, фото экрана.
   - **Если не совпало:** остановить испытание и назначить пользователю `panel` отдельный профиль/пользователя. Регуляркой это не исправляется.

7. **`Off Fixture`**
   - **Сделать:** включить `allow_highlight`, выбрать прибор при подсветке, снять галочку и проверить, что значения подсветки исчезли только из Programmer пользователя `panel`.
   - **Записать:** строку `Off Fixture <ids>`, состояние Programmer оператора и результат на приборе.
   - **Если не совпало:** остановить передачу, проверить `allow_highlight`, пользователя `panel` и наличие перекрывающего `Super`; не заменять команду на `Clear` или `ClearAll`.

## 12. Что зависит от ещё неизвестного ответа пульта

Сырые ответы на эти строки мост записывает сам при каждом запуске (`field-data/auto/`, спека 23). Ничего вводить на пульте не нужно: после работы скачайте `diag.zip` (Диагностика) и пришлите, файлы лежат в папке `auto/`.

| Что | Предположение | Если ответ другой | Где править на месте |
|---|---|---|---|
| Конец ответа | приглашение `]>` | «результат неизвестен», значения после `Fixture` не уходят | `prompt_regex`; крайний случай `require_prompt: false` (конец = 200 мс тишины) |
| Вход | ответ содержит `Logged in` | «вход не подтверждён» (жёлтый), команды идут | `login_ok_regex` |
| Слова ошибки | `error`, `illegal`, `unknown command` | ошибка может показаться как «отправлена без ошибки» | по сырым ответам, правка кода → обновление по сети |
| Время ответа | до 2 с | «результат неизвестен», поздний ответ в логе | `timeout` |
| Пустой executor | `No objects found` | запись сцены блокируется: «ответ не распознан» | `exec_empty_regex` |
| Список сцен | строка `1.101 Имя …` | сцены не добавляются, «N строк не распознано» | по сырым ответам → обновление по сети |
| Статус сцены | слова `Running`/`Off` | состояние с пульта не видно, панель помнит свои нажатия | `poll_seconds: 0` (выключено по умолчанию) |
| Имена атрибутов | `ColorRGB1..3`, `Pan`, `Tilt`, `Zoom`, `Focus`, `Strobe` | ошибка пульта, значение не меняется | Сопоставление атрибутов |
| Относительный шаг | `Attribute "Pan" At + 2` | ошибка или голова стоит | `attrs.pan.rel_cmd`, `attrs.pan.step` |
| Диапазоны Pan/Tilt | ±270° / ±135° | «Задать позицию» уведёт голову не туда | `attrs.pan.min/max`, после проверки `range_checked: true` |
| Переход | ` Fade 3` после значения | ошибка пульта (по умолчанию переход «Сразу», Fade не шлётся) | `fade_fmt` в config.json |
| Цвет CMY | те же атрибуты, значения 100−RGB | неверный цвет | `attrs.color`, `color` у прибора |
| Стробоскоп (спека 24) | в экспорте типа `ChannelType attribute=SHUTTER` с `ChannelSet` «Open»/«Strobe…», `Attribute "Shutter" At <%>` ставит процент канала | строб не тот или прибор гаснет; в журнале сырой файл типа | разбор `parse_fixture_type` по `diag/` → обновление по сети |
| Пользователи | `List User` показывает пользователя и профиль | проверка А по фото пульта | — |
