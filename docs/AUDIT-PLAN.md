## Решения владельца

1. Основная цель — надёжная установка в своём зале; публичный релиз тоже нужен. Срока мероприятия нет.
2. Обычно панель работает самостоятельно; одновременная работа оператора MA2 должна поддерживаться. Ориентир — 5 клиентов панели без назначения главного.
3. Полный интерфейс на 8080 — владелец и концертный оператор; простой на 8090 — преподаватели для репетиций. Запись/перезапись доступны полному интерфейсу с сохранением существующих серверных проверок режима и разрешений.
4. Устройства: Android (Opera/Chrome), iPad/Safari. Проверка реальных устройств обязательна перед заявлением о совместимости.
5. Пользователь панели — `Remote`, права полные. Профиль Remote и профиль оператора ещё не установлены; разные пользователи сами по себе не доказывают изоляцию Programmer.
6. Сцены — один упорядоченный список; вкладки страниц не нужны. Адрес Executor остаётся технической привязкой в редакторе. Пункт 13 аудита не реализовывать буквально.
   `static/simple.js` уже берёт сцены из общего `config.scenes`; плоская выдача закреплена в спецификации. В шаге 7 проверить оба интерфейса и порядок списка; в шаге 24 убрать вводящие в заблуждение объяснения страниц. Отдельная новая навигация не нужна.
7. При выборе сцены выключаются все остальные сцены текущего шоу, включая запущенные оператором вне панели; выбранная запускается с Cue 1. Повторное нажатие активной выключает её; последнее нажатие отменяет несовместимые старые переходы. Список панели не является границей гашения других сцен. Точный охват MA2 и корректность перехода проверить на тестовом шоу; не считать перечисление config.scenes полным списком источников.
8. Цель обновления статуса сцен — примерно 1–2 секунды; период уточнить по нагрузке. После восстановления связи только читать состояние, автоматически команды не повторять.
9. Гашение должно выключать весь свет. Следующий выбор сцены сразу возвращает свет, отдельный выход из Blackout не нужен. Механизм общего гашения требует испытания; текущую ограниченную команду нельзя объявить глобальным Blackout.
10. Запись сцены — весь текущий выход света. Сцена панели представляет одно состояние (Cue 1), а не перебор Cue через обычный Go. Существующие последовательности вне панели не переписывать; при их выключении учитывать решение п. 7.
11. Highlight нужен только при подготовке. Изоляция Programmer и политика ClearAll требуют проверки с оператором.
12. Джойстик сейчас устраивает; сохранить существующее зеркальное/инвертированное управление. Добавить переключение на два горизонтальных регулятора Pan и Tilt; точный вид выбрать перед UI-патчем.
13. Неоднозначные совпадения приборов при импорте подтверждает пользователь. Не требовать заново ручной список приборов, пока не изучены существующие данные.
14. Нужны обновления с USB, по локальной сети с Mac и через GitHub. На компьютере зала есть интернет/GitHub. В браузере основного компьютера нужна кнопка обновления: загрузка релиза с GitHub, установка и перезапуск без ручного запуска BAT/копирования файлов. Ручная пересылка диагностических ZIP владельца не устраивает; нужна отправка из панели с минимальным числом действий.
15. 3D-модель зала не нужна; пункт 16 отложен без срока. Большой рефакторинг и необязательные новые функции не предшествуют исправлению ошибок.

## Подход и расход

Рассмотрены: только критические исправления; все подтверждённые замечания по очереди; только текущие жалобы. Владелец выбрал второй вариант. Это означает проверку всех 43 пунктов с отдельным решением, а не обязательное внедрение каждой рекомендации аудита.

- Уточнение владельца 2026-11-02: экономить лимит Codex, передавать Clodex также планирование, код и тесты. Для содержательной реализации первый кандидат — Sonnet; для сложного плана и сложного кода — Opus. Основной агент согласует решения, даёт ограниченный контекст, проверяет/применяет результат, запускает тесты и коммитит. Мелкие очевидные правки делает сам; удачный код помощника заново не переписывает.
- Medium — обычная работа; High — конкретная сложная асинхронная ошибка/восстановление. Astra и повышенный reasoning для review — только с отдельного согласия. XHigh/Max не использовать по умолчанию.
- Владелец просит чаще использовать Clodex, в том числе подходящие Opus/Sonnet. Перед выбором сверять реальный ID, фиксированный тариф, совместимость обёртки; названия не доказывают качество. Бюджет $5 не повышать.
- Платные вызовы только последовательно через `scripts/clodex.py`. Передавать ограниченные обезличенные материалы, проверить непустой ответ и завершение. Локальный учёт не равен балансу провайдера.
- На старте планирования локальный учёт Clodex: $0.2604 из $5. Это не расход текущего чата.
- Уточнение каталога 2026-11-02: прежний вывод об отсутствии Claude был неполным. Bearer-запрос возвращал иной каталог; `GET /v1/models` с `x-api-key` и `anthropic-version: 2023-06-01` вернул 11 Claude ID, включая `claude-opus-5-5` и `claude-sonnet-5-5`. Документированный Claude-маршрут — `/v1/messages`. Детали и снимок тарифов в `DELEGATION.md`; обёртка адаптирована шагом 0a и проверена заглушками. Платную Claude-генерацию пока не запускали.
- Проверять доступный счётчик Codex перед крупной реализацией и review, после них; не обещать процент стоимости всего проекта.
- Адресные тесты при разработке; один полный набор перед завершением. Не повторять полное исследование или проверки без причины.
- GitHub Actions: использовать стандартные runners, таймауты, отмену устаревших запусков и короткое хранение артефактов. До настройки проверить видимость целевого репозитория и условия хранения; платные runners не подключать.

молча лимит Codex вместо согласованного делегирования. Продуктовый контракт и обязательные тесты
от этого распределения не меняются.

Реализация: ticket хранит `plan_epoch`, ревизию конкретной сцены и поколение соединения `link._gen`. Создание таймера и проверка перед отправкой — внутри `execute` под `action_lock`; блокировка удерживается до завершения `link.send`. Новая операция инвалидирует прежнюю до первой отправки, включая частичный сбой. После reconnect старый таймер не действует даже до завершения идентификации шоу. Отмена фоновых задач при shutdown использует существующий lifecycle. Несовместимые таймеры до пробуждения могут оставаться задачами, но больше не отправляют команды.

Приёмка шага 1: после локальных регрессионных тестов, полного pytest и review статус **«локально проверено»**; переход A→B→A на тестовом MA2 назначить шагу 27. Только после этого можно повысить статус до «готово». Следующие независимые локальные патчи не блокируются ожиданием зала.
