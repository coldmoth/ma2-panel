## Архитектура и интерфейс

Стек сохраняется: Python/FastAPI, обычный JS, без зависимостей. Мост — единственный источник снимка для обоих портов. `running` содержит bool или null; null означает неизвестность. `running_meta` содержит по id `{source: "ma2"|"unknown", freshness: "fresh"|"stale"|"unknown", updated_at: unix_seconds|null}`. `values_meta` содержит такие же метаданные для `shown` (source panel) и `live` (source ma2). Метаданные не доказывают физический выход. Устаревшее running становится null; старый live очищается; shown остаётся лишь историей отправки и не подсвечивает план как текущий выход.

Альтернативы: оптимистические bool после отправки дешевле, но оставляют исходный дефект; выбран явный неизвестный статус до чтения. Существующий парсер Executor сохраняется с ограничением зала, отсутствие строки не трактуется как Off. Опрос не расширяет диапазоны шага 3.

## Проверки риска

Старый ответ после reconnect/смены шоу не публикуется; пропуск цикла не продлевает свежесть; одинаковое повторное чтение продлевает её; новый клиент получает полный снимок; частичная ошибка не создаёт ложных Off. При неизвестном статусе остаётся доступно явное выключение сцены, повтор команды автоматически не выполняется.

## Результат и решения при реализации

Локально проверено, MA2/Windows/реальные планшеты не проверены. Модуль status_evidence.py хранит отдельные источники и монотонные сроки. В UI независимый срок от локального получения; updated_at только маркер обновления, часы устройств не сравниваются. Оба порта получают полный снимок сцен. Явный poll_seconds=0 сохраняется.

Решения: чтение конкретных настроенных Executor вместо спорного диапазона, без изменения импорта шага 3. Unknown/stale других разрешённых сцен включаются в swap; это кандидаты на выключение, а не подтверждение запуска. Предел swap ограничен числом сцен конфига, дубликаты отклоняются: прежние 16 ломали замену списка с неизвестными статусами. Полный охват источников вне конфига остаётся шагам 6–7. Рассылка сериализована, задержка клиента ограничена 0.5 с на отправку и 0.5 с на закрытие; публикация поллера не держит action_lock при ожидании клиентов.

Независимый review review_statuses нашёл гонку старой рассылки после инвалидации и ожидание WS под action_lock. Обе воспроизведены тестами RED→GREEN. Дополнительно RED→GREEN: DMX через поколение соединения, закрытие зависшего клиента, swap из 17 сцен, быстрые Go с unknown/stale и фильтрация прав в обоих UI. Всего 10 новых backend-тестов, Node-регрессии в panel-v4.cjs.

Sonnet smoke завершён READY, тариф проверен каталогом 0.6 USD/1M. Два содержательных Sonnet-запроса завершились HTTPError без текста, автоматических повторов нет; резервы unknown $0.1084218 и $0.0377844 сохранены. Реализация: основной Codex — backend/интеграция; внутренний frontend_statuses — UI/DOM; review_statuses — независимый review на той же модели. Общий локальный учёт $0.2620→$0.4083; счётчик лимита Codex недоступен.

Финальная проверка: полный pytest по команде проекта с JUnit — 628, 0 failures/errors, прежнее предупреждение Starlette/httpx; Node — exit 0.
