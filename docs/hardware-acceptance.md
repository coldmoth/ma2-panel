# Приёмка на grandMA2: отдельный стенд и затем зал

Дата подготовки: 2026-11-10. Это инструкция, а не отметка о прохождении.
Целевая система проекта — grandMA2/onPC 3.9.60; обязательно записать полный build.
Результат другой сборки 3.9 не переносится автоматически на 3.9.60.
Итоговые свидетельства и дефекты хранятся в репозитории: docs/stage4-audit.md.
Синтаксис и runtime-предпосылки — [ma2-command-evidence.md](ma2-command-evidence.md).
Сопоставить с [hall-test-plan.md, §12–13](hall-test-plan.md).

## 1. Подготовка и резервные копии

1. Назначить оператора пульта и наблюдателя с правом немедленно остановить испытание.
   Не выполнять на концерте, при людях под движущимися головами или при доступном стробе.
2. Сначала отдельная Windows-машина/VM, новое тестовое шоу без рабочего оборудования.
   Отключить Art-Net/sACN/DMX In, физические DMX/USB-интерфейсы и участие в MA-Net Session.
   Не подключать копию рабочего шоу к сети зала. В зал переходить только после стенда.
3. В Backup пульта сохранить исходное шоу новым именем с датой и скопировать на отдельный
   носитель; проверить наличие и размер копии. Сохранить отдельно пользовательский профиль,
   настройки сети, текущий Grand Master и состояние штатной B.O. Не перезаписывать исходник.
4. Полностью остановить панель. Скопировать её каталог данных: config.json, settings.json,
   secret.env (приватно), shows/, backups/, layouts и журналы blackout.json,
   scene-write-*.json, highlight.json, rdm-search.json, .updates/ и previous/ при наличии.
   Не удалять pending-журналы ради зелёного статуса.
5. Распаковать проверяемую сборку в отдельный каталог. Для стенда — только копии настроек
   с отдельными портами, show/export/diag путями. Не запускать два моста с одним каталогом.
   Секреты не помещать в отчёт/скриншоты. Сверить SHA256 полученного ZIP.
6. Подготовить виртуальные RGB, Dimmer и две головы с разными диапазонами/инверсией,
   прибор без Shutter и прибор с явными Open/Closed/Strobe каналами. Использовать минимум
   две вселенные. Для DMX-интервалов отдельно проверить четыре вселенные на стенде.
7. Создать A={1,2}, B={2,3}, C={1,3} и отдельный внешний playback X={99}; у панели —
   выделенные Executor и резервные места. Исключить параллельную запись этих объектов.
   Сцены панели: только одна ручная Cue 1/Go, LTP/Soft LTP, пустой Cmd; не применять к чейзеру.

## 2. Соединение и достоверность

1. Разрешить Telnet и выделить отдельного пользователя MA2 с достаточными правами.
   Пароль хранить в secret.env. Не менять рабочие права ради обхода отказа Lua.
2. Запустить отдельную панель; проверить адрес/порт и страницу «Площадка»/«Диагностика».
   Убедиться, что имя шоу из свежего ListVar совпадает с привязкой плана, указан полный build.
3. Привязать только тестовый план. При другом/неизвестном шоу запись и свет должны быть
   запрещены, старые команды не должны ждать восстановления для автоматической отправки.
4. Проверить nonce-чтение свойств Cue и Grand и фактическую Lua API этой версии.
   Если свойства/единицы/формат не распознаны, ожидается объяснимый отказ до команды.
   Не подменять неизвестный результат данными mock и не отключать guard.
5. Проверить мастер первичной настройки, HTTP основной/простой панели и две вкладки WS.
   Успех команды означает подтверждение транспорта/пульта, а не физический результат.

## 3. Patch, группы и сохранность плана

1. Получить приборы из MA2; сверить IDs, типы, адреса, вселенные, параметры и количество
   с Patch на пульте. У неизвестных профилей недоступные атрибуты не должны изображаться рабочими.
2. Поставить ручные координаты/метки, создать группу; повторить импорт. Они сохраняются.
3. По одному: добавить/удалить прибор, поменять адрес/вселенную, имя и Fixture ID.
   После импорта проверить план и все ссылки локальных и импортированных групп.
   Удалённый прибор отмечается отсутствующим; неоднозначное соответствие требует выбора.
4. Повторить импорт групп с сохранённой пользовательской меткой; проверить состав.
   Намеренно неполный/ошибочный экспорт не должен заменить исправный план частичными данными.
5. Открыть другое тестовое шоу: старые цели/карты/черновики не применяются к нему без
   подтверждённого контекста. Вернуться и убедиться в сохранности обоих планов.

## 4. Реальный выход, цвет и движение

1. На пульте открыть DMX Sheet и Fixture Sheet. Установить одному прибору Dimmer и RGB
   извне панели. Сравнить байты нужной вселенной, физический свет и значок плана.
2. Изменить цвет/яркость с панели и одновременно другим оператором. Последнее отправленное
   значение не должно обозначаться измеренным. Итоговый DMX может зависеть от Programmer,
   приоритетов, HTP/LTP, Park, DMX tester/merge и React to Master.
3. Отключить/запретить Lua, задержать одну порцию, прочитать неполный ответ. Проверить
   отдельные отказы блоков, ограниченные retry и отсутствие опроса в плотном цикле.
   Через TTL (6 с) старое значение становится stale/unknown, свечение не выдаётся за actual.
4. Проверить RGB/Dimmer/Shutter Open/Closed; Strobe, неизвестный/многофункциональный диапазон,
   неподдерживаемые CMY/instances не объявляются достоверным цветом/яркостью.
5. Две головы из разных исходных положений: относительный Pan/Tilt сохраняет разницу,
   не прыгает к вычисленному центру; инверсия и пределы проверяются по каждому профилю.
   При неизвестной базе абсолютного жеста — отказ или явное новое абсолютное задание.
   Схематический луч плана не считается измерением механического положения.

## 5. Ручные сцены, crossfade и Store

1. Запустить A вручную при Fade=0; убедиться, что через ожидание следующая Cue сама не стартует.
2. Fade=5: A→B. Прибор 1 плавно освобождается; 2 переходит к B; 3 появляется; X не гаснет.
   Проверить Dimmer вниз/вверх и non-dimmer: их реальные приоритеты/Snap/release записать отдельно.
3. В середине перехода B→C→A; затем быстрые повторные нажатия. Нет запоздалого таймера Off,
   который гасит новую сцену. Пульт может сам закончить уже принятую команду при обрыве.
4. Добавить ручное значение Programmer и более высокий playback. Не обещать, что запуск
   сцены перекроет их; снять значения вручную только по решению оператора.
5. Изменить общее время в одной вкладке; проверить другую вкладку, простой порт и перезапуск.
   Сцены используют серверное время; быстрые значения — то же время, перетаскивание — сразу.
6. Выбрать приборы на плане, записать их текущий Output в свободное место. Проверить
   содержимое Cue, триггер/приоритет и имя на MA2, затем ручной запуск.
7. Перезаписать тестовую сцену: новый кадр сначала в spare Cue 1, прежний — в spare Cue 2,
   backup и commit копируют с явным CueOnly, commit — также Overwrite. При отказе Store/подготовки target не меняется.
   При неизвестном commit ничего не повторять: отдельно проверить target, spare и журнал.
   «Executor занят» после записи не доказывает побайтовое совпадение содержимого Cue.

## 6. Безопасная проверка Blackout

1. Сначала только виртуальный стенд; затем пустой зал с оператором у пульта и согласованным
   владением Grand. Записать точный исходный уровень, включая 0 и дробный 37.5; состояние B.O.
2. Первое нажатие: чтение → журнал → SpecialMaster 2.1 At 0 → чтение. Убедиться, что
   Executor, Programmer и штатная B.O. не удалены. Тестировать также свет X вне панели.
3. Повторное намеренное нажатие возвращает исходный уровень только в прежнем контексте
   и при текущем Grand=0. Дублированное действие со старым blackout_epoch не включает свет.
4. Во время затемнения изменить playback, затем восстановить: выходит текущий playback,
   а не сохранённый кадр. Чужой ненулевой Grand должен запретить автоматическое восстановление.
5. Удержать слайдер/джойстик, нажать Blackout из второй вкладки/простого порта. Старые очереди,
   жесты, fades моста и Undo отменяются; новый жест требует нового намерения оператора.
6. Разорвать связь/перезапустить панель в затемнении. Состояние unknown и инструкция проверить
   Grand видимы в обоих интерфейсах; автоматического возврата нет. Не повторять вслепую.
7. Отдельно проверить React to Master=Off, Park, DMX tester/merge, внешний DMX и приборы
   без dimmer. Они могут остаться включены. Blackout не является отключением питания.
   Повторный чужой Grand=0 программно неотличим от сохранённого нуля.

## 7. Обрыв, ошибки и восстановление

1. Отдельно разорвать Telnet и WS. Старый measured свет исчезает/устаревает, интерфейс
   объясняет причину, управление блокируется. Повторить с двумя клиентами и удержанным жестом.
2. Восстановить связь. Дождаться свежего имени шоу, Patch/профилей и recovery gate.
   Убедиться по журналу, что ничего старого не воспроизвелось. Только затем новый жест.
3. Диагностика: «Связь и помощь» → «Диагностика», «Журнал действий»; локальные logs/,
   diag/, field-data/auto/ и журналы рядом с config.json. Для спорной команды сохранить
   время, request_id, точную строку/ответ и снимок MA2 без паролей/ключей.
4. При проблеме остановить передачу в панели; это прекращает команды, но не откатывает свет.
   Не перезапускать неизвестную запись и не удалять journals. Проверить Grand и штатную B.O.
   вручную на пульте, затем playback/Programmer/DMX overrides с владельцем шоу.
5. Для неудачного Store сохранить spare и scene-write журнал. Восстанавливать Cue через
   GUI MA2 из проверенного резерва только на остановленном стенде и после сверки адресов.
6. Для отката программы полностью остановить её, использовать штатный rollback/previous
   и сохранённые пользовательские данные. Не заменять config/settings шаблонами.
   Откат кода не откатывает Grand Master, Cue или фактический свет.
7. Исходное шоу загружает оператор из проверенной копии. Восстановить согласованные
   сеть/профиль/Grand/B.O.; сверить приборы и DMX перед возвращением к работе.

## 8. Успех и оставшиеся аппаратные утверждения

Для каждого шага записать: build MA2/Windows/панели, исходные условия, ожидаемое,
фактическое, время, PASS/FAIL/UNKNOWN и ссылку на локальное свидетельство.
Любой необъяснённый свет, потеря данных, replay, резкий release при Fade>0,
неизвестный результат, показанный успешным, или повреждение резервов — FAIL и запрет выпуска.

Mock/pytest/DOM и даже onPC не подтверждают физическую линию DMX, механические пределы,
инверсии/калибровку конкретных голов, безопасность строба, взаимодействие с оборудованием
зала, его приоритетами и внешними источниками. Windows ARM64 с x64-эмуляцией не заменяет
проверку нативного Windows x64. До этих проверок и независимого review выпуск не принят.
