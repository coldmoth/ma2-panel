# Фаза 1: локальная проверка комплекта Windows

Дата: 2026-11-03. Платформа проверки: macOS. **Windows запуск не выполнен.**
Windows/VM, Wine, Parallels, VMware, VirtualBox и UTM в доступной среде не обнаружены.
Нельзя подтвердить исполнение .bat, загрузку .pyd/DLL, NTFS ACL, Firewall,
кириллицу на Windows, перезапуск и блокировки файлов. Это открытый блокер до зала.

## Что проверено локально

- `bash scripts/build_win.sh` успешно собирает комплект с Python 3.12.10 amd64
  embeddable и Windows wheels из `uv.lock`; пакет не опубликован.
- ZIP: CRC OK, 781 файл, нет дубликатов путей без учёта регистра и переходов `..`.
  Распакован во временный путь с пробелами и кириллицей на macOS.
- Все 80 файлов из manifest совпали по размеру/SHA256; VERSION совпадает с manifest:
  `3.1.0rc1+b77e1fb-dirty` (локальный снимок незакоммиченного патча).
- Наличие PE `python.exe`, `python312.dll`; `python312._pth`:
  `python312.zip`, `.`, `..`, `..\lib`, `import site`. Это проверка структуры,
  не доказательство загрузки расширений Windows.
- Внешний start.bat вызывает program/start.bat, внутренний использует полные
  пути в кавычках, переходит в свою папку и запускает bridge.py. VERSION батники
  не читают. Код 3 запускает мост повторно; исполнение ветки требует Windows.
- Два изолированных subprocess `bridge.py --mock` на Python macOS: с VERSION
  `3.1.0rc1` и без него оба дали HTTP 200 `/api/diag`, версии `3.1.0rc1` и `dev`.
  Рабочие config/settings, Telnet MA2 и рабочее шоу не использовались.
- Найдено и исправлено скрытие версии 3.1 в обезличенном отчёте; ограниченный
  allowlist одинаков на мосту и сервере. Релизная identity не заменена исходной версией.

Архив будет меняться при следующей сборке: manifest фиксирует байты конкретного
снимка. SHA256 окончательного локального архива записать при передаче на Windows;
не объявлять этот dirty-снимок опубликованным релизом.

## Реальный smoke на Windows: выполнить до подключения к MA2

1. Скопировать ZIP и его SHA256, проверить `Get-FileHash .\ma2-panel-win.zip -Algorithm SHA256`.
   Распаковать ПОЛНОСТЬЮ в `C:\Тест панели с пробелами\`; не запускать из окна ZIP.
2. Не запускать grandMA2. В cmd перейти в `ma2-panel` и выполнить:
   `start.bat --mock`. Открыть localhost:8080, убедиться, что явно показан mock,
   а `/api/diag` содержит версию из `program\VERSION`. При занятых портах использовать
   копию settings с другими портами; не завершать чужие процессы.
3. Отдельно из program проверить импорты:
   `python\python.exe -c "import fastapi, uvicorn, segno, pydantic_core; print('imports OK')"`.
   Сохранить bridge.log, runtime.json и вывод ошибки, если запуск не удался.
4. На копии комплекта остановить мост, переименовать VERSION в VERSION.saved,
   снова `start.bat --mock`: мост должен стартовать, diagnostics version будет dev.
   Вернуть VERSION до проверки обновлений; manifest повреждённой копии невалиден.
5. Проверить штатную остановку и перезапуск после сохранения настройки через localhost.
   Записать pid до/после, не считать смену подписи кнопки доказательством рестарта.
6. Записать Windows build/архитектуру, путь, SHA256 ZIP, время, HTTP/версию,
   ошибки загрузки DLL и результат запуска .bat. Статусы: работает / сломано / не проверено.
   Firewall, ACL/locked files, update/rollback и power-loss — отдельная полная матрица
   `docs/audit-block-b-updates.md` в исходном репозитории, а не выполненная часть этого smoke.

Не запускать рабочий MA2 без отдельного согласования оператором. Mock не подтверждает свет.
