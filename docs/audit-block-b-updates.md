## Что реализовано

- `release.py` и `scripts/package_release.py`: общий payload Windows/USB/LAN,
  одна версия на сборку, настоящий README и одинаковые документы. Зависимости Windows
  берутся через `uv export --locked --no-dev`, ручной список pins удалён.
- `program-manifest.json`: версия, формат, требования runtime, размеры и SHA256 файлов.
  Проверяются состав ZIP, безопасные Windows-пути, регистр, коллизии, ссылки и лимиты размера.
  `runtime.json` связывает установленный комплект с lockfile; `runtime-files.json`
  обнаруживает изменение фактических Python/lib. Несовместимость отклоняется до остановки.
- `update.py`: staging и снимок на том же диске, постоянный журнал `.updates/active.json`,
  точный откат новых/удалённых файлов, recovery до обычного запуска. Прежние снимки
  сохраняются; автоматической очистки копий обновления нет. Неизвестные пользовательские
  root-файлы при первом переходе с legacy-установки не удаляются по расширению.
- Recovery-код публикуется атомарно, файлы снимка фиксируются до удаления оригиналов.
  На POSIX синхронизируются каталоги; на Windows переименования используют write-through.
  Это локально проверенные меры, а не доказательство переживания физического power loss на NTFS.
- `browser_update.py`: фиксированный стабильный релиз `coldmoth/ma2-panel`, ограниченная
  загрузка и SHA256, внешний stdlib-процесс, ожидание завершения прежнего PID,
  запуск/проверка версии, operation ID и PID на обоих включённых портах; при сбое — откат.
  Гибель worker после запуска нового моста обнаруживает watchdog: управление закрывается,
  стабильный worker восстанавливает исходную транзакцию и запускает прежнюю программу.
- Управление только с loopback, локальным Host, проверкой Origin и `X-Update: 1`.
  Общая блокировка исключает одновременные browser/USB/LAN/CLI-откат операции.
  Вход закрывается без await между проверкой занятости и переключением;
  транспорт повторно проверяет gate после своей блокировки и late-reply drain.
- USB/LAN после подтверждения используют тот же атомарный `/api/update/quiesce`,
  не безусловный `/api/stop`. Старый запущенный мост без этого API надо сначала остановить
  вручную штатным `stop.bat`. При ожидании учитывается жизнь процесса, не только ответ HTTP.
- Страница настроек: версии, проверка/явная установка, стадии, отказ «занято», ошибки,
  откат и переподключение через GET. Неоднозначный POST не отправляется повторно.
  Пока HTTP-мост отсутствует, read-only loopback relay показывает статус на прежнем порту;
  если обе версии не запустились, сообщение доступно до 180 с или первого чтения результата.
- `firewall.py`/BAT: сохранённые порты, выключенный simple_port не открывается;
  ограничения по программе, локальной подсети и профилям сохранены.
  Менять правила надо от имени администратора после смены портов/папки установки.
- Конфиги, настройки, пароль, подсветка, URL, шоу, диагностика/её credentials и field-data
  не входят в payload и не заменяются откатом. Копия перед обновлением — в `backups/`;
  каталог ограничен текущим пользователем (POSIX 0700, Windows ACL требует smoke).

## Известные границы

- Старые установки без runtime identity требуют первого полного комплекта.
  SHA256 — проверка целостности, не независимая цифровая подпись; доверяем фиксированному
  HTTPS-источнику релиза и правам публикации в репозитории.
- Строгое совпадение lockfile намеренно консервативно: новый lockfile может потребовать
  полного комплекта даже при изменении только dev-зависимостей. Это безопасный отказ.
- Загрузка до остановки не означает фоновую автоматическую установку. При занятости
  установка отменяется; после окончания действий пользователь нажимает снова.
- `previous/` и `.updates/` — части восстановления, не мусор для автоматической очистки.
  Старые неизменяемые снимки остаются внутри `.updates/`; пользовательские backups отдельно.
- Если worker принудительно убит после остановки старого моста, но до запуска нового,
  независимого системного supervisor нет: требуется ручной `start.bat`, который сначала
  выполняет recovery. Если сам BAT отсутствует после прерванной замены, из папки установки
  выполнить `python\python.exe .updates\recovery.py --recover .`, затем `start.bat`. Штатные исключения установки/старта обрабатываются автоматически;
  после запуска replacement-моста гибель worker отслеживает watchdog.
- Уже известный дефект чистых шаблонов `ma2.export_dir` (шаг 15) не исправлялся этим блоком.
  Приёмку чистого комплекта он пока блокирует. Тесты явно задают временный export_dir;
  не выдавать такие тесты за успешный первый запуск на одних публичных шаблонах.
- Чтение настоящего GitHub `/releases/latest` выполнено: в текущем релизе нет
  ожидаемых update ZIP + SHA256, получен понятный отказ до остановки. Скачивание
  нового формата из опубликованного релиза ещё не проверено. Windows embeddable/NTFS/ACL, Android/iPad и MA2
  ещё не проверены. Публичный release и лицензия остаются в блоке Е.

## Первый переход со старой установки

1. На ПК зала остановить старый мост штатным `stop.bat`. Старую папку сохранить целиком.
2. Распаковать полный комплект в отдельную новую папку. Не распаковывать шаблоны поверх
   действующих config/settings. Перенести свои config/settings/secret.env, highlight.json,
   shows, diag, diagnostic-upload.json, field-data и update_url.txt при наличии.
3. Проверить фактический `ma2.export_dir` в своих настройках/конфиге (см. ограничение шага 15).
   Сначала выполнять smoke на копии с `--mock`; не подключаться к рабочему MA2 ради проверки.
4. Обновить firewall для нового пути и портов с правами администратора.
   Затем проверить обычный запуск и оба интерфейса. Старую папку не удалять.
5. Следующие совместимые релизы доступны из настроек через localhost. USB/LAN сохранены;
   USB-комплект содержит `update.py` и необходимый ему `release.py`.

## Обязательный Windows smoke

1. Чистый полный ZIP: embeddable Python, оба порта, HTTP/WS, путь с пробелами/кириллицей.
   Зафиксировать ограничение export_dir, а не маскировать его зелёным smoke.
2. Реальный опубликованный test release: check/download/SHA256; network timeout/rate limit,
   отсутствие assets, повреждённый ZIP и несовместимые Python/lib оставляют старую версию работающей.
3. idle→новое действие во время загрузки/подтверждения: установка отказывает;
   два запроса/два клиента/USB одновременно не создают две транзакции. Старые WS не переотправляют действия.
4. install→health→оба порта→возврат UI; simple_port=null, нестандартные порты и firewall.
5. Locked/read-only файл, отказ ACL, мало диска, ошибка каждого шага копирования/rename,
   неудачный старт/health, неудачный старт отката: корректный статус, данные побайтно сохранены.
6. Убить worker до остановки, в замене, после запуска новой версии и во время rollback;
   затем отдельное отключение питания на тестовой установке. Запуск не смешивает версии,
   recovery повторяем; прежний исправный снимок и копия пользовательских данных остаются.
7. Проверить ACL каталога backups с credentials; штатные права обновления и повышенные
   права только для firewall. Убедиться, что start.bat и updater не запускают два моста.
