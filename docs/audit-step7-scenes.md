Это отчёт и критерии следующего патча, не согласованное изменение контракта.
Продуктовый код и `spec.md` не менялись; команды настоящему MA2 не отправлялись.

## Уже решено владельцем

По [плану, решения 6–10](AUDIT-PLAN.md#решения-владельца): оба интерфейса показывают
один упорядоченный список. Новый выбор запускает Cue 1 и выключает остальные сцены
текущего шоу, включая запущенные оператором вне конфига. Повторное нажатие активной
сцены выключает её; последнее нажатие отменяет несовместимые старые переходы.
После общего гашения выбор сцены возвращает свет без отдельного выхода из Blackout.
Существующие последовательности вне панели не переписываются.

Текущий [контракт сцен](spec.md#сцены-и-страницы) описывает старые Go/Goto, ClearAll

и раздела сцен, получить согласие владельца; затем изменить spec и датированную историю.
Сохранённое решение владельца задаёт цель, но не подтверждает MA2-механизм её выполнения.

## Почему сейчас нельзя закончить реализацию

- [Шаг 3](audit-step3-executors.md): полный охват и реальные ответы Executor ещё не
  установлены. Нельзя заменить все сцены простым обходом `config.scenes`, угадать предел
  адресов или считать частичный ответ полным перечнем источников.
- [Шаг 5](audit-step5-programmer.md): неизвестны профили и изоляция Programmer.
  Сохранение `ClearAll` без этой проверки не доказывает сохранность работы оператора;
  его простое удаление тоже не обеспечивает нужный выход света.
- [Шаг 6](audit-step6-blackout.md): не выбран механизм гашения и безопасного возврата.
  Простое снятие маски может вернуть старый свет; локальный флаг не доказывает владение
  Blackout, включённым оператором.
- [Шаг 4](audit-step4-statuses.md): локальная модель статусов проверена, но слова статуса,
  задержка и нагрузка MA2 ещё не приняты в зале. Устаревшее состояние клиента нельзя
  считать достаточным доказательством активности для общего toggle.

Новый запрос «выполни шаг 7» не содержит результатов этих испытаний и не разрешает
эксперименты с рабочим шоу. Повторно исследовать шаги 3/5/6 без новых данных не требуется.

## Критерии будущего патча

Это требования к проверке, а не выбранный алгоритм или готовые MA2-команды.

1. Сервер обеспечивает политику для обоих портов и пяти клиентов. Пропущенный/неполный
   `swap` не ограничивает охват; клиентские id не дают дополнительных прав.
2. Новая сцена всегда начинает Cue 1, с fade и без него. Выключение других сцен не
   удаляет и не перезаписывает их Cue; охват включает внешний Executor другой страницы.
3. Повторное нажатие активной сцены выключает её в обоих UI. До реализации согласовать
   действие при unknown/устаревшем чтении и конкурирующем запуске оператора: по такому
   статусу сейчас нельзя достоверно выбрать между запуском и выключением.
4. Для A→B→A, пяти клиентов и общего гашения никакое старое завершение не гасит
   последнюю выбранную сцену и не возвращает старый свет. Уточнить порядок принятия
   запросов сервером: часы разных браузеров не задают общий порядок нажатий.
5. Все требуемые полномочия проверены до первой изменяющей команды. Если режим не
   разрешает полный охват, нельзя молча выполнить частичную замену или обойти safety;
   доступ простого порта согласовать вместе с шагом 6.
6. Ошибка/unknown на любой стадии останавливает следующие стадии; уже отправленное
   не считается отменённым. После reconnect — чтение без автоматического Go/Off/Store,
   старые таймеры не пересекают смену шоу/соединения. Оператору виден неизвестный результат.
7. После общего гашения следующий выбор возвращает только требуемую сцену; чужой
   Programmer и чужой Blackout обрабатываются по согласованным правилам шагов 5/6.

Будущие регрессии: toggle при подтверждённой активности и неизвестности; Cue 1 без fade;
пропущенный swap и внешний Executor; ограничения safety до отправки; A→B→A и пять
клиентов; сбой/обрыв на каждой стадии; смена шоу; возврат после общего гашения.
Для поведения сначала получить нужный RED, затем реализацию. Зелёные старые тесты
проверяют сохранение старой модели, а не выполнение всей новой политики.
