# Файлы шоу MA2 через браузер — предложение контракта

2026-11-03. Согласовано владельцем: «да давай». Продолжение portable-start,
коммит 72f2f50. Ниже согласованный контракт и границы доказуемости.

## Подтверждённые факты

- Настоящий файл шоу — `.show.gz`; MA указывает каталог `gma2/shows` соответствующей
  версии. Точный локальный каталог зависит от установки, выбирать его по принципу
  «первая найденная версия» нельзя.
- `Import/Export` переносит объекты через XML, а не целое шоу.
- `LoadShow` работает на выбранном диске; отсутствующее имя открывает пустое шоу.
  `/nosave` запрещает сохранение прежнего шоу; `/full` также затрагивает настройки.
- `SaveShow` без имени сохраняет текущее шоу; прежняя запись становится backup
  (MA хранит до десяти). `SelectDrive 1` выбирает внутренний диск.
- Изученные страницы не описывают Telnet-сигнал завершения записи или внутреннюю
  схему show-файла. Проверка gzip не доказывает, что содержимое — совместимое шоу.

Источники MA Lighting (grandMA2, не grandMA3):

- https://help.malighting.com/grandMA2/en/help/key_keyword_loadshow.html

Сегодня `bridge.list_shows/load_show` проверяют свежий ListShows и подтверждают
имя после загрузки через ListVar; неподтверждённый результат бывает unknown.
`show_save` подтверждает только отправку. `ma2.shows_dir` сейчас даёт лишь список.
`shows/*.json` — планы панели, их нельзя использовать вместо файлов MA2.

## Предлагаемая правка раздела «Шоу» docs/spec.md

1. Обмен целыми `.show.gz` доступен в разделе «Шоу» с устройства браузера через
   основной ПК с локальной MA2 onPC. Требуется однозначно настроенный каталог
   `ma2.shows_dir` текущей установки; его настройка доступна только на основном ПК.
   Не выбирать каталог другой версии автоматически. Для удалённого пульта без
   доступа к его файловой системе операция недоступна с понятной причиной.
2. «Загрузить файл шоу»: выбор файла браузером → ограниченная потоковая передача
   во временное хранилище моста → проверка расширения, размера и целостности gzip
   (до 512 МиБ сжатого и 2 ГиБ распакованного потока). Не распаковывать содержимое
   в каталоги MA2. Повреждённый контейнер не становится доступным для LoadShow.
   Корректный gzip может содержать не шоу: UI сообщает, что проверена целостность
   контейнера, а формат и совместимость версии окончательно проверяет MA2.
3. После проверки показать исходное имя, размер и имя назначения MA2. Сохранить
   отдельной копией без перезаписи существующего файла; при совпадении дать новое
   безопасное имя. Исходные байты сохраняются. Имена/пути от браузера не становятся
   путями на ПК или фрагментами команд MA2.
4. Перед LoadShow — отдельное подтверждение точного назначения и потери
   несохранённых правок текущего шоу. Одноразовое подтверждение связано с файлом,
   его хешем и состоянием подключения/шоу; устаревшее согласие отклоняется.
   Только при allow_show_load, через action_lock и make_guard. Выбрать внутренний
   диск, проверить файл и свежий ListShows; если имя отсутствует — не посылать
   LoadShow. Не добавлять /full и флаги замены настроек. План панели переключается
   лишь после подтверждения имени MA2 по существующему механизму.
5. «Скачать шоу» предлагает сохранённую версию текущего шоу: имя, время файла,
   предупреждение, что несохранённые изменения MA2 в неё не входят. Команд записи
   не отправляет. Выдавать неизменяемый проверенный снимок настоящего `.show.gz`
   средствами браузера, без JSON плана и без HTTP Content-Encoding: gzip.
6. Отдельный вариант «Сохранить текущее и скачать» требует allow_show_save и
   явного подтверждения перезаписи названного текущего файла. До записи проверить
   текущее имя/связь и сохранить отдельную локальную резервную копию прежнего файла.
   Внутренний диск, один SaveShow; не использовать SaveShow под новым именем.
   Ждать наблюдаемого обновления файла, стабильности, полной проверки gzip и
   копирования без изменений источника. Если обновление не доказано, прежний файл
   не выдавать за результат новой записи; показать unknown и возможность отдельно
   скачать сохранённую версию. Автоматического восстановления файла MA2 нет.
7. Этапы различают передачу файла, проверку, ожидание согласия, запись/загрузку
   MA2, подтверждение и готовность скачивания. При тайм-ауте/обрыве после отправки
   команды — unknown; команду не повторять. Повтор запроса с тем же ID не запускает
   запись/загрузку заново. Чтение статуса и повтор скачивания готового снимка
   допустимы. После перезапуска моста незавершённая операция не возобновляется.
8. Смена шоу другим клиентом панели, остановка, потеря связи и два параллельных
   запроса не должны смешивать файл, подтверждение и имя. Загрузка/сохранение
   сериализованы для клиентов этого моста;
   GET ничего в MA2 не записывает. Сохраняются проверки Origin/Host, запрет
   произвольных путей и существующие разрешения. Разрешённая панель в LAN может
   передавать/скачивать шоу; локальные настройки/секреты ей не выдаются.
   Мост не блокирует действия на самом MA2 или из другой Telnet-сессии. Между
   ListVar и SaveShow внешний оператор может переключить шоу: атомарного
   «сохранить только если имя прежнее» в изученной документации нет. В подтверждении
   сохранения требуется предупреждение не переключать шоу и не выполнять запись
   извне до окончания операции. Проверка имени до/после выявляет часть гонок,
   но не предотвращает сохранение другого шоу при внешнем вмешательстве.
9. Передача браузеру подтверждает готовность файла и начало скачивания, но не
   запись на устройство: место сохранения и итог контролирует браузер.
   config/settings/secret и существующие планы не подменяются загруженным архивом.

## Проверки будущей реализации

Сначала RED на реальном API/файловой системе: обрыв upload, неверный gzip/CRC,
пустой файл, превышение лимитов и gzip bomb, обход путей, коллизии/симлинки,
нет места/доступа, источник меняется при копировании, файл не появился/не обновился,
неверный каталог/версия, отсутствие имени в ListShows, смена шоу между prepare и
confirm, два клиента, halt/disconnect/timeout, повтор ID, перезапуск в середине.
Проверять неизменность исходных данных и отсутствие лишних команд MA2.
Затем реализация, полный pytest, Node, браузер в изолированном mock, независимый
review той же моделью, code-index и передача. AGENTS.md не включать в коммит.

Независимая проверка предложения: внутренний show_files_design_check, та же модель.
Два замечания подтверждены: не обещать проверку формата MA2 по gzip; не обещать
блокировку внешней смены шоу средствами action_lock. Оба отражены выше.

Остаётся проверить на MA2 по отдельному запросу владельца: видимость скопированного
файла в ListShows, поведение выбранного диска/диалогов, обновление файла SaveShow,
вход panel после чужого шоу и совместимость версии. Дома можно доказать обработку
сбоев, но нельзя объявлять проверенной работу onPC на основании mock.
