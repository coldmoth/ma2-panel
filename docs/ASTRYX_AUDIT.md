# Astryx в LUMA

19 ноября 2026, ветка `codex/luma-v2-design`, база U2.05 `56ffea7ee7aacb18303d8f9aa522ad3e5c008748`. Выводы об интерфейсе основаны на статическом чтении JSX и CSS. Размеры касания, контраст и объявления скринридера требуют проверки в браузере.

## Интеграция на этапе Foundation

- `luma-lab/package.json`, lockfile и `npm ls --depth=0` подтверждают Core и Neutral Theme `0.7.16`. React и React DOM объявлены как `^19.2.0`, зафиксированы и установлены как `19.3.1`. StyleX объявлен как `^0.19.1`, зафиксирован и установлен как `0.19.2`. Это соответствует peer dependencies Core `0.7.16` (React и React DOM ≥19, StyleX ^0.19.0).
- [main.jsx](../luma-lab/src/main.jsx) импортирует официальные `core/reset.css`, `core/astryx.css` и `theme-neutral/theme.css`, затем локальный `styles.css`. `Theme` с `neutralTheme` из `theme-neutral/built` и `mode="dark"` оборачивает App и лениво загружаемый DesignLab. Vite использует готовый CSS Astryx и не настраивает компиляцию локального StyleX.
- Рабочие компоненты Astryx — `Button` через общий `Action`, `Card` в `SceneCards` на полке Hall и на странице Scenes, `Switch` в Settings. `Action` задаёт `size="sm"` и передаёт `isDisabled`. `.ax-btn` и `.scene-card` частично задают оформление поверх Astryx.
- Собственные стили используют `--bg`, `--side`, `--panel`, `--elev`, `--line`, `--muted`, `--sub`, `--accent`, `--accent-dim`, `--danger`, `--green`, `--radius` и локальную типографику Inter/системный шрифт. Стили Astryx используют семантические шкалы цвета, отступов, высот контролов, рамок, фокуса, радиусов, теней, движения и типографики. У LUMA пока нет собственной темы Astryx, связывающей обе группы значений.
- Своё оформление есть у нативных кнопок шапки и Hall, навигации, сегментов, меню `details/summary`, каталоговых карточек-кнопок, полей и форм, `Range`, `Modal`, `Empty` и баннеров. Повторяются фон поля и навигации `#191a26` (2), граница Inspector `#2f2939` (4) и граница панелей Layout `#43384e` (3). Первые два употребления `#191a26` имеют разные роли. Сводить значения стоит по назначению. Фокус рисуется разными оттенками и с разным отступом в общих контролах, Hall, Layout и InspectorDock. Большинство отступов, радиусов и размеров контролов заданы локально.

## Документация и инструменты

Wiki задаёт общие принципы. Разметку и поведение определяет Core, оформление задаёт тема. При настройке порядок такой — props, семантические токены, прицельная настройка компонента через тему и затем собственная реализация при конкретном ограничении. У состояний нужен различимый фокус, а значимый статус дополняется текстом или семантикой. Репозиторный `AGENTS.md` Meta содержит также правила работы над самим Core. В LUMA действуют отдельные [правила интерфейса](../luma-lab/AGENTS.md). [Design Conventions](https://github.com/meta/astryx/wiki/Design-Conventions) · [System Architecture](https://github.com/meta/astryx/wiki/System-Architecture) · [AGENTS.md Meta](https://github.com/meta/astryx/blob/main/AGENTS.md)

В manifest, lockfile и `node_modules/.bin` LUMA CLI отсутствует. Официальный `@astryxdesign/cli@0.7.16` требует Node ≥22.13.0. Временная установка с отключёнными lifecycle scripts и чтение документации компонентов прошли на Node `26.9.0`. Из каталога `luma-lab` команду можно запускать через `npx @astryxdesign/cli@0.7.16 <команда>`, без записи в зависимости проекта. Опубликованный [релиз Core 0.7.16](https://github.com/meta/astryx/tree/v0.7.16) служит ссылкой на версионную документацию ниже.

## Состояния и тема

| Состояние | Как работает сейчас | Направление для темы LUMA |
| --- | --- | --- |
| Hover и active | Глобальный hover повышает яркость enabled-кнопок. Есть локальные правила для списков Hall и захвата в Layout. У Astryx есть свои стили. Класс `.active` в LUMA часто означает устойчивый выбор или состояние света. | Общий hover и краткое нажатие для стандартных контролов через их API и токены. Устойчивый выбор, состояние сцены и нажатие получают разные роли. |
| Focus | Общее `:focus-visible`, отдельные кольца для InspectorDock, Hall и Layout, SVG-обводка приборов. | Единые токены фокуса для HTML-контролов, проверка без обрезания у края dock и в меню. SVG сохраняет контрастную предметную обводку. |
| Selected / active scene | CSS-классы и `aria-pressed` для выбора, обводка SVG, цветовой маркер и текст сценария для readback сцены. | Развести фокус, выделение прибора, черновой выбор и состояние сцены. Сохранить подписи и доступные сведения об активности. |
| Disabled | Native `disabled`, `Action.isDisabled`, `aria-disabled` на SVG плюс защита обработчиков, `inert` для закрытых контекстов. Прозрачность различается в общих стилях и Hall/Layout. | Взять токены disabled для стандартных контролов. Оставить блокировки по готовности моста, выбору и readback, с доступным объяснением там, где это важно. |
| Pending и error | В сценах pending блокирует кнопки, в групповом редакторе показано сохранение и есть guard повтора, в Inspector показано качество данных. App и Layout выводят alert на ошибки. | Сохранить различие между ожиданием, подтверждением, staleness, потерей связи и ошибкой. Применять loading/status API только после сверки поведения при потере фокуса и повторном вводе. |

Предлагаемая структура для будущей отдельной задачи.

1. Оставить один верхнеуровневый `Theme` в `main.jsx`. Определить тему LUMA как расширение Neutral через `defineTheme` по версионному `docs author-a-theme`. Для текущего Vite сначала проверить вариант со скомпилированным CSS, сохранив текущую тёмную основу. Использовать общие семантические токены поверхностей, текста, типографики, отступов, плотности, радиусов, фокуса и движения для Astryx и заменяемых локальных стилей.
2. Держать роли предметных состояний рядом с темой LUMA как CSS-переменные проекта. Нейтральные рабочие поверхности, лавандовый акцент управления, видимое выделение приборов, активная сцена, ожидание, потеря связи и ошибки должны читаться в одном кадре. Для размеров использовать компактный desktop и адаптацию под coarse pointer. Сверить EN/RU, hit areas и контраст при наведении, нажатии и фокусе.
3. Оставить метры, углы, масштаб SVG, контуры/лучи, зоны точного выбора, fade и ограничения размера Inspector у соответствующих компонентов. Убирать повторяющиеся литералы CSS партиями по одной визуальной роли, с проверкой экранов, которые эту роль разделяют.

Для переноса диалога сохранения открыть отдельную задачу с pending, блокировкой повторов, ACK/отказом и поведением при смене ревизии.
- **B3. Список групп Hall.** Оценить [Popover][popover] только как оболочку. Готово, когда `hall-groups.mjs`, `hall-multiselect.mjs` и `hotkey-context.mjs` подтверждают пустые/частичные группы, точные ID, отмену, задержанный ACK и отказ, блокировки слоя и восстановление фокуса. Выбор проекции через [SegmentedControl][segmentedcontrol] проверять отдельным изменением в обеих проекциях.
- **B4. Один контрол Inspector.** Если [Slider][slider] подходит по модели событий, начать с отдельного диапазона, сохранив draft → commit, неизвестное и смешанное значения и отмену ввода. Готово после проверок одного действия на commit, нуля действий при отмене, смене цели и недоступности, неизменной адресации и `dimmer-browser.mjs`, `inspector-adaptive.mjs`, `blackout-header.mjs`. Критичный диммер/Grandmaster требуют отдельных проверок и review.
- **B5. Одна команда Scenes.** Оценить [Button][button] для Stop отдельно от Go и Card. Готово, когда подпись, pending, disabled, readback и фокус корректны в EN/RU, а mock подтверждает единственный Stop с тем же ID, отсутствие Go и корректное восстановление после ошибки.

### C — специализированные компоненты

- **C1. Stage и визуализация света.** Сохранить SVG, геометрию, проекции, лучи, hit-testing и различимые кандидаты. Отдельная работа над фокусом или hit areas готова после проверки mouse/touch/keyboard в обеих проекциях, перекрытий, плотного плана и отсутствия ложных адресатов.
- **C2. Pan/Tilt и адаптивный dock.** Оставить джойстик, ограничители, качество readback и separator. Отдельно спроектировать доступный путь для Pan/Tilt и проверить остановку при release, cancel, потере захвата, смене цели и отказе, отсутствие повторных действий сверх текущего контракта и работу в компактном Inspector.
- **C3. Локальная геометрия Layout.** Оставить собственные drag/rotate, числовую точность, предпросмотр и Undo/Redo. При изменениях формы проверять обе проекции, клавиатурную и числовую альтернативы, одно сохранение, отмену и отсутствие команд света.

Из проверенных компонентов для форм также доступны [CheckboxInput][checkboxinput] и [Selector][selector]. Текущие [Card][card] и [Switch][switch] можно переиспользовать. Для изменений B запускать затронутые существующие сценарии на изолированном mock, проверять протокол по кадрам, поддерживаемые размеры и реальный zoom. Приёмка на MA2 остаётся отдельной по [плану зала](hall-test-plan.md), §§12–13.
