# Шаг 3: Error #9 и полнота чтения Executor

Дата: 2026-11-02. Статус: **нужен зал**. Исследование выполнено локально;
предел адресов и реальный формат строк ещё не подтверждены. Продуктовый код и
`spec.md` не менялись. Команды ниже подготовлены, но пульту не отправлялись.

## Установлено по сохранённым данным и коду

- `field-data/2026-10-18/probe.txt:22` — версия **3.9.60.68** в том снимке,
  не доказательство текущей версии установки.
- `probe.txt:143–148` — `List Executor 1.1 Thru 1.250` вернул
  `Error #9: NUMBER TOO LARGE`, без строк объектов. `bridge.log` содержит ещё
  повторения этого отказа, но не успешные ответы меньших диапазонов.
- `probe.txt:149–169` — `List Page` показывает `(13)` на странице 1 и `(7)`
  на странице 2. Это свидетельство объектов на страницах, а не их адресов,
  типов или точного числа сцен панели. Экспорт приборов этих сведений не даёт.
- В сохранённом комплекте нет успешных строк `List Executor`. Текущие
  `commands.parse_executors` и `parse_running` по-прежнему основаны на предположениях.
- `bridge.list_execs` меняет **конечный адрес**, не размер ответа:
  250 → 200 → 128 → 100 → 90 → 60 → 30 → 15. После успеха остаток не читается.
  Один `exec_top` используется для всех страниц и сохраняется до перезапуска.
- `mock.py` задаёт `exec_ceiling=200` и придуманные строки Executor.
  `tests/test_real_ma2.py::test_executor_list_steps_down_after_number_too_large`
  доказывает поведение моста на этой модели, а не предел 200 настоящего MA2.
- Если пользовательский `ma2.list_cmd` содержит фиксированное `.250`, а не
  `{top}`, уменьшение `exec_top` не меняет команду. Мост отправляет один и тот
  же отказавший диапазон восемь раз. Документированный в spec пример имеет
  именно такую форму; локальные настройки и секреты в отчёт не копировались.

## Что говорит первоисточник MA

Проверено 2026-11-02 по руководству версии 3.9:

- [Error Messages](https://help2.malighting.com/Media/TopicPdf/55136/31):
  `Number too large` относится к введённому числу. Это не описание лимита
  количества объектов или байтов ответа. Номер ошибки сам по себе не сообщает
  допустимую верхнюю границу Executor.
- [Executors on the screens](https://help2.malighting.com/grandMA2/en/help/key_exec_on_screen.html):
  Action Buttons перечислены как 101–190.
- [Release Notes 3.9](https://help2.malighting.com/grandMA2/en/help/release_notes/key_releasenotes.html):
  раздел 3.9.60.63 описывает конвертацию фейдеров 1–90 и кнопок 101–190;
  более раннее описание синтаксиса содержит `Off Executor 101 Thru 240`.
  Последнее не доказывает, что `List` принимает каждый адрес до 240.
- [What are executors](https://help2.malighting.com/grandMA2/en/help/key_exec_what_are.html):
  есть также X-Keys; на Executor могут назначаться не только Sequence, но и
  другие объекты. Число физических кнопок не задаёт адресное пространство.
- [Executor Keyword](https://help2.malighting.com/grandMA2/en/help/key_keyword_executor.html):
  поддержаны формы `[Page].[ID]` и `[Pagepool].[Page].[ID]`. Текущий парсер
  ожидает только две числовые части; реальный ответ может потребовать уточнения.

**Гипотеза:** `.250` отвергается как недопустимый номер, а не из-за длины
выборки. Руководство и сохранённый отказ согласуются с этим объяснением,
но без одиночных запросов и успешных диапазонов оно ещё не проверено.
Ни 190, ни 200, ни 240 пока не объявляются универсальным пределом `List`.

## Локальное воспроизведение

Два эксперимента через существующую `bridge_cfg` во временной папке, только mock,
`MA2_MOCK_REAL=1`, `exec_ceiling=128`, строки `1.101 Low` и `1.150 Tail`:

| Шаблон | Отправленные диапазоны | Результат |
|---|---|---|
| По умолчанию | `1.1–1.250`, `1.1–1.200`, `1.1–1.128` | Импорт сообщает успех, `1.150` отсутствует |
| Фиксированное `.250` | Восемь одинаковых `1.1–1.250` | Импорт отказывает; уменьшение не действует |

Это воспроизведение дефектов алгоритма на искусственном ограничении.
Оно не доказывает существование `1.150` при таком ограничении на реальном MA2
и не подтверждает модель «пульт ограничивает размер пакета» из исходного аудита.

## Точный запрос для зала

Проводить отдельной проверкой по явному запросу владельца. Зафиксировать версию
и открытое шоу. Использовать только чтение, сохранить полные ответы с командой,
заголовками и приглашением, длительность и признак ошибки. Пароль не записывать.
Для воспроизводимости не менять шоу и назначения между сравниваемыми запросами.

1. Снять `ListVar` и `List Page`. Записать на экране адреса нескольких **уже
   назначенных Sequence**: фейдер, кнопка с большим номером и объект страницы 2.
   Если X-Keys используются, отдельно записать их адреса/назначения с экрана.
   Ничего не создавать и не запускать ради этой проверки.
2. Для страницы 1 отправить одиночные `List Executor 1.N`, где
   `N = 1, 90, 91, 100, 101, 190, 191, 200, 201, 220, 240, 241, 250`.
   Это диагностические кандидаты, не список разрешённых адресов.
   Дополнительно запросить каждый известный занятый адрес из п. 1.
   Различать явную ошибку числа, пустой результат и строку объекта;
   `Object does not exist` сам по себе не подтверждает предел нумерации.
3. Сравнить полные ответы на следующие строки:

   ```text
   List Executor 1.1 Thru 1.90
   List Executor 1.101 Thru 1.190
   List Executor 1.1 Thru 1.190
   List Executor 1.1 Thru 1.200
   List Executor 1.1 Thru 1.240
   List Executor 1.1 Thru 1.250
   List Executor 1.201 Thru 1.240
   List Executor 2.1 Thru 2.90
   List Executor 2.101 Thru 2.190
   ```

   Для каждого диапазона сверить наличие известных занятых адресов из п. 1,
   попадающих в него. Если отказал широкий диапазон с допустимыми одиночными
   концами, разделить **тот же набор допустимых адресов** и сравнить объединение.
   Не считать успех короткого запроса доказательством полноты широкого.
4. Нужны хотя бы одна реальная строка Sequence Executor и полный ответ на
   заведомо пустой допустимый адрес. Если на Executor назначен другой тип,
   сохранить его строку отдельно: нельзя автоматически импортировать его как сцену.
   Статусы Running/Off проверять отдельно в шаге 4; ради шага 3 свет не переключать.
5. Сохранить обезличенные ответы как тестовые fixtures, исходные — локально в
   `field-data/`. Уже имеющийся `PROBE_COMMANDS` запрашивает 250, 100, 200 и
   101–130, но не покрывает весь протокол. Обычный запуск моста автоматически
   не выполняет дополнительные запросы этого документа.

## Предлагаемый способ чтения после проверки

Это предложение для согласования, не новый продуктовый контракт:

1. Зафиксировать подтверждённые адресные диапазоны и реальные строки ответа.
   Отдельно решить X-Keys/трёхчастные адреса и типы назначенных объектов;
   до решения не заявлять обнаружение всех сцен шоу.
2. Читать весь подтверждённый набор; если одна команда его возвращает полностью,
   пакетирование не нужно. Если необходимы части, объединять их без пропусков,
   не уменьшать молча конечный адрес. Размер части и допустимые адреса — разные вещи.
3. При ошибке, обрыве или нераспознанной строке не подтверждать полноту импорта;
   существующий план сохранять. Для мониторинга отсутствие строки не означает Off
   (политика неизвестности и устаревания — шаг 4).
4. До изменения кода согласовать с владельцем правку разделов spec «Сцены и
   страницы» и «Конфиг и настройки» о чтении сцен и `ma2.list_cmd`, затем записать историю. Проверить регрессиями
   известную сцену за границей первой части, несколько страниц, ошибку следующей
   части, неизвестную строку и пользовательский шаблон с фиксированным концом.

Следующий шаг по этой проблеме — получить перечисленные ответы MA2. Независимый
локальный шаг 4 можно обсуждать отдельно; неподтверждённый предел Executor в него
не переносить.
