# Блок В: данные и совместимость

Дата: 2026-11-02. Пункты аудита 13–15 завершены локально.
Владелец согласовал уточнения spec в этом чате; опубликованный релиз не менялся.

## Результат

- **Импорт:** при неоднозначности prepare не меняет план. Выбор нужен для каждого
  нового прибора: перенос от конкретного кандидата или явное «Оставить новый».
  Один старый прибор нельзя использовать дважды; случай два новых/один старый
  тоже неоднозначен. JSON-ключи обрабатываются как строки.
- **Подтверждение:** token и монотонная ревизия исходного плана/контекст шоу
  отклоняют старый запрос, повтор и запрос после изменения с последующим откатом.
  Один merge используется для обычного импорта и confirm; группы, расстановка,
  флаги и отчёт `no_id` сохраняются. Confirm ничего не отправляет в MA2.
  Ручной XML использует тот же механизм через loopback HTTP.
- **Планы:** полный SHA256 имени даёт короткое ASCII-имя, различающееся и при
  Windows case-insensitive lookup. Актуальный файл предпочтительнее legacy;
  встроенное поле show проверяется до чтения/записи. Чужой legacy не мешает
  создать собственный план. Legacy не переписывается. При открытии старого плана
  его настройки площадки не возвращаются в config; версия остаётся 5.
- **Миграции:** v1–4 переходят сразу в v5, без версии означает v3.
  `port`, `rate_hz`, `ma2`, `master` переносятся в settings; существующие значения
  settings имеют приоритет на уровне вложенных ключей. До записи проверяются
  данные и создаются резервные копии. Settings заменяется атомарно первым,
  config последним; прерывание допускает безопасный повтор. v5 не переписывается.
  Неподдерживаемые версии и legacy-пароль отклоняются до файловых изменений.
  Безымянный сырой архив v3 хранится в backups/unnamed-plan-v3.json,
  именованный — в shows. Исходные байты также остаются в датированных backups.
- **Запуск:** миграция выполняется до вычисления портов/MA2/throttle. Частичный
  runtime override не теряет перенесённые поля. Чистые шаблоны запускаются;
  master читается из настроек площадки. Слово password внутри пути не считается
  ключом пароля; реальные password-ключи по-прежнему запрещены.
