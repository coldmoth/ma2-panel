## Что сделано

- На `diag.html` есть отправка в отдельный закрытый [coldmoth/ma2-panel-diagnostics](https://github.com/coldmoth/ma2-panel-diagnostics). Репозиторий создан, Issues включены; исходная история проекта туда не переносилась.
- Одна Issue — один отчёт; UI показывает короткий номер. Исходный ZIP остаётся локальной альтернативой для глубокого разбора.
- Сборщик читает существующий снимок `/api/diag`, количества из конфига, последний стартовый capture и краткий результат уже сохранённого selfcheck. Сам selfcheck не запускается; команд MA2/RDM/свету нет.
- Передаются версия панели (если распознана), числовая версия MA2, mock-флаг, режим/состояние, количества, структура строк ответов и коды ошибок. У строк таблицы сохраняются числовой идентификатор и число полей, у переменных — только известное имя поля, значения исключаются. Исходные XML, настройки, журналы, строки имён/путей/адресов не отправляются. Нераспознанные строки обозначаются явно.
- Сохранённые capture/selfcheck отмечены как исторические. Отсутствие данных и неизвестная версия не заменяются предположением. Это не даёт полный XML типа и не доказывает семантику Executor, изоляцию профилей или физический свет.
- Сначала атомарно сохраняются UUID/неизменяемое тело, затем состояние `pending`, затем POST. При потерянном ответе/5xx/краше повтор делает только GET всех страниц Issues и ищет тот же маркер. В том числе когда сразу после создания GitHub ещё не показывает Issue. Новый отчёт блокируется, пока предыдущий неоднозначен. Одновременные процессы сериализуются OS-lock; браузер сохраняет UUID отдельно от световых действий.
- Сеть выполняется в рабочем потоке без блокировки управления светом. Получатель/HTTPS-хост фиксированы, перенаправления не выполняются, приватность репозитория проверяется перед запросами, ответы ошибок не выводят исключения/секреты. POST допускается только через localhost на ПК моста, с проверкой Origin и специальным заголовком.

## Однократная настройка на ПК зала

1. Войти в GitHub как `coldmoth` и открыть [Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens/new).
2. Выбрать **Only select repositories → ma2-panel-diagnostics**. Права: **Issues — Read and write**, **Metadata — Read**. Выбрать срок действия токена по правилам владельца; истёкший токен заменяется той же командой настройки.
3. В папке установленной панели выполнить:

   ```bat
   python\python.exe diagnostic_setup.py
   ```

   В разработке: `uv run python diagnostic_setup.py`. Для отдельного settings: `--settings ПУТЬ_К_settings.json`.
4. Ввести токен в скрытом приглашении. Не вводить его на странице, в аргументе командной строки или в чате. Скрипт сначала проверяет закрытый получатель, затем сохраняет `diagnostic-upload.json` рядом с settings. На Unix — mode 0600, на Windows — ACL текущего пользователя через SID. Старый токен не заменяется, если проверка не прошла.
5. На этом же ПК открыть `http://localhost:<порт>/diag.html`, нажать «Обновить состояние отправки», затем «Отправить диагностику». На планшете отправка недоступна. Перезапуск моста после настройки не нужен.

Токен не входит в Git, шаблоны, ZIP сборки или диагностический пакет. Текущий широкий токен `gh` в приложение не копировался. Для реального сетевого smoke использован существующий CLI-доступ только в памяти процесса и только синтетическое содержимое.

Права Issues read/write соответствуют [GitHub REST API](https://docs.github.com/en/rest/issues/issues?apiVersion=2022-11-28). На создание отдельного ограниченного PAT нужен вход владельца: CLI-доступ не превращается автоматически в новый ограниченный токен.

## Срок хранения и неоднозначная отправка

Автоматического удаления нет: Issues и локальный `diag/upload-state.json` хранятся до ручного удаления. Журнал нужен для защиты от дубликатов; удалять его ради сетевого повтора нельзя.

Если поиск долго не находит Issue после неоднозначного POST, остаётся статус «результат неизвестен». Повтор безопасно продолжает поиск. Новый POST не делается даже при пустом результате: доказать, что GitHub не принял первый запрос, этим нельзя. Разрешение такой ситуации требует отдельной сверки маркера/журнала владельцем; автоматического сброса нет.
